internal offline test boundary, not a production integration entry point.

## Drafts, action mapping and lifecycle

`lib/cost-synergy/estimate-form.ts` owns input conversion/request construction:

```text
EstimateDraft = {horizon: raw string, actions: ActionDraft[]}
ActionDraft = {line_id, included,
  annual_run_rate: {amount: raw string, note: raw string},
  migration_one_time_cost: {amount: raw string, note: raw string},
  transition_overlap_cost: {amount: raw string, note: raw string}}
```

All flags start false; all amounts, notes and horizon start blank. No application
cost, license spending, disposition or AI narrative populates financial values.
Each supplied amount, including zero, requires its own nonblank basis note <=400
characters. Preserve raw notes and React escaping. Invalid raw fields, even excluded
drafts, block submission; excluded valid lines cannot contribute or create conflicts.

Rows follow trusted `reviewed.effective_actions` order. Exact globally unique action
IDs become line IDs; existing strict schemas reject unsafe IDs. Attribution is
`ala/<action_id>`. Preserve exact finding/action/subject ID and Buyer/Target side.
Each line owns only its action subject's whole-app spend; no inferred destination
ownership or disposition-specific eligibility. Reuse the calculator's membership
and overlap checks. Original AI actions/rationales, effective visitor proposals/
destinations/reasons, original relationship/evidence/uncertainty/coverage/provenance
remain separate and read-only. Financial inclusion is not recommendation approval.

The editor key contains the entire trusted context: source session/fixture/version,
app/license revisions and ordered digest, reviewed request/input identity, review
digest and exact action/content representation. A synchronous shared-session key
also contains fixture/session identity, exact ordered applications/licenses,
revisions and currency. Changed keys hide/unmount the old editor before an async
digest resolves; old totals cannot flash during verification. In-flight checks
cannot publish into a later lifetime. SHA-256 uses the unchanged server source
representation `JSON.stringify({applications,license_positions})`.

App/license edit, publication, reset, reorder, silent source change or new/reviewed
result clears inputs, totals and comparison. TSA-only changes retain them. The
protected owner must also revoke currentness/refresh context when reviews change;
browser equality does not establish authenticity. Refresh/navigation/unmount/reset
clears financial memory. No new storage keys, session-schema/registry writes,
database, download or server persistence.

## Exact inputs and unchanged engine

CAD strings accept `0`, `0.00`, `1.23`, `1200.5`, `1200.50`; blank means unknown.
Syntax: `^(0|[1-9]\d*)(?:\.(\d{1,2}))?$`, bounded before BigInt conversion.
Reject negative/plus/whitespace/leading-zero/exponent/comma/currency-symbol entries,
NaN/Infinity, omitted integer/fraction and >2 decimals. Convert decimal portions
using BigInt to exact cents: no float multiplication, rounding, epsilon, truncation
or default zero. Existing inclusive MAX_MINOR = CAD10,000,000,000.00. Horizon is
blank/null or explicitly 1–30 whole years, never defaulted.

Build only strict `CSERequestSchema`: expected source, original ALA review identity
and review digest; known components carry visitor_assumption, exact CAD/annual/once
units and basis note; blank components are null. `calculateCSE` alone computes:

```text
A = sum included annual_run_rate; M = sum migration_one_time_cost
T = sum transition_overlap_cost; O = M + T; H = A × horizon_years; N = H − O
```

One-time costs deducted once. Existing bounds/overflow/null/source precision and
ownership policies are unchanged. Negative net is valid. Source cost is evidence,
never savings or a financial cap. Numeric license contributions remain withheld;
the advisory U05.04 handoff is not inserted into financial lines.

## Presentation, comparison and accessibility

Native collapsible action fieldsets/legends preserve a compact screen. Labeled
checkboxes/decimal text inputs/notes/horizon, aria-invalid/describedby, adjacent
errors, submission alert and visible focus support keyboard operation. A1 scoped
grids wrap at 320/390/1440; status uses words, not color alone. Results announce
politely; no charts or hover-only controls.

Calculate is explicit/local. Edits hide previous totals and announce recalculation
required. Recalculate may show one previous valid snapshot with its own assumptions
and horizon, within the same keyed source/review. No numeric difference formula,
saved baseline/scenario or persistence. Reset clears both snapshots.

- invalid: fixed safe message/code, no totals or previous success panel.
- not_computable: explicit unavailable status/reasons, no monetary KPI or invented zero.
- incomplete: only calculator-supplied known components; prominent incomplete warning;
  null = Unknown / Not computable, never a complete portfolio claim.
- computed: exact bounded illustrative/unapproved CAD totals and explicit horizon.

All returned assumptions, excluded/unknown/conflicting/unsupported lines and fixed
reason text remain inspectable. Conflicts identify keys/line IDs; no automatic
winner, splitting, cap, omitted material line or duplicate financial benefit.
