# U00.05 — Shared browser session contract

REQ-004, REQ-058, REQ-062; ADR-003/009 and A1 Coastal Navy / ADR-011.
Session schema **1.0.0** is independent of demo schema **1.0.0**.
Single key: **`aivra:r0:demo-session:v1`**, declared in `lib/session/session.ts`.

## Ownership and lifecycle

`DemoSessionProvider` mounts once above the workspace in `app/layout.tsx`.
It owns one controller, shared through React Context and `useSyncExternalStore`.
Snapshots are cached and deeply frozen. SSR and initial client hydration both
start with a stable not-ready/null snapshot; storage access happens after mount.
There are no module-local stores, browser globals for debugging, server writes,
URL-encoded deal state, localStorage, cookies, IndexedDB or database.

The controller initializes from strict, bounded `sessionStorage` JSON or a fresh
`loadSyntheticDealFixture()` result. Current source data always reuses the full
`SyntheticDealFixtureSchema`, including referential integrity. The source fixture
and U00.02 contracts are unchanged. Home uses context names and counts after
hydration, rather than retaining server-rendered fixture counts.

Same-tab navigation/refresh retains state. A normal separate tab has a separate
browser storage area; an opener/duplicated tab may copy an initial snapshot.
This is ordinary sessionStorage behavior, not a security boundary or durable
deal storage. Use synthetic data only; no model/provider receives session data.

## Envelope

| Field | Meaning |
| --- | --- |
| `session_schema_version` | Supported session contract literal; no automatic migration |
| `session_id` | Random UUID for this session lifetime; reset creates a new one |
| `fixture` | Bundled `fixture_id`, `schema_version`, `dataset_version`; must match the current bundle |
| `created_at`, `modified_at` | UTC ISO timestamps; modification time never moves backward within the session |
| `current_deal` | Validated synthetic fixture-shaped current data: names, CAD, disclosure, stable application/license/TSA IDs and records |
| `input_revisions` | Independent nonnegative safe-integer counters: `applications`, `licenses`, `tsa` |
| `session_revision` | General revision, incremented for source changes or metadata registration |
| `derived_results` | Initially empty, strict optional registry of known result kinds; only provenance metadata, never arbitrary output payloads |

Persisted JSON is limited to **512,000 UTF-16 characters**, 50 applications per
side / 100 total, 200 license positions, 100 TSA services and seven registry keys.
The underlying schemas retain null versus zero, valid dates/numerics and source
references. Unknown fields, incompatible versions/identity/currency, negative or
future revisions, bad references, impossible timestamps and invalid metadata
are rejected. Parsing is not a tamper-proof audit trail or approval mechanism.

## Public API

Client module components import `useDemoSession` from
`components/demo-session-provider.tsx`. Pure contracts/functions are in
`lib/session/session.ts`; the reusable controller is in `lib/session/controller.ts`.

```tsx
const {
  session, ready, storageAvailable, recovered,
  updateApplication, updateLicense, updateTSA,
  captureInputVersions, recordDerivedResultMetadata,
  getResultFreshness, resetDemoSession,
} = useDemoSession();

// Check ready before reading source records or capturing a snapshot.
const outcome = updateApplication(appId, { owner: "Fictional finance team" });
if (!outcome.ok) { /* Show an appropriate validation message in the future editor. */ }

// Only register after the future module has independently validated a real output.
// Capture BEFORE the calculation/request, not when an old response returns.
const captured = captureInputVersions(["applications"]);
// ...future module obtains and validates its actual result...
recordDerivedResultMetadata("ala", ["applications"], captured);
const freshness = getResultFreshness("ala"); // missing | current | stale
```

Updates take a stable record ID and typed partial patch. `ApplicationPatch`
excludes `app_id` and `company_side`; `LicensePatch` excludes `license_id`;
`TSAPatch` excludes `tsa_id`. Runtime strict validation also rejects identity
changes. A missing record ID or invalid complete-fixture candidate returns
`{ok:false,error}` without mutation, persistence or revision increment. Successful
updates return `{ok:true}`. Normalized no-ops retain snapshot identity, timestamps,
revisions and storage. Only the changed record kind's source revision advances;
other source arrays retain their content and IDs. No add/remove/import workflow
or user-facing editor is implemented in this unit.

`captureInputVersions(dependencies)` returns:

```ts
{ session_id: "<current lifetime UUID>", revisions: { applications: 2 } }
```

Metadata contains unique dependency tags, that exact captured key set, a session
lifetime ID and `recorded_at`. A capture from a previous/reset session or future
revision is rejected. An older revision in the same lifetime is accepted as
**stale**, allowing honest handling of a delayed response. No result payload is
stored here. Missing metadata means **missing**, never a completed/current result.
Changing any declared source marks freshness stale mechanically; metadata is
retained. No model request, recomputation, business decision or approval occurs.

## Minimum dependency map

| Result kind | Required source tags |
| --- | --- |
| `ala` | applications |
| `licenses` | applications, licenses |
| `cost` | applications, licenses |
| `scenario` | applications, licenses |
| `playbook` | applications, licenses, tsa |
| `assistant` | applications, licenses, tsa |
| `health` | applications, licenses, tsa |

`RESULT_DEPENDENCIES` documents conservative minimums; additional declared tags
are allowed. Missing required tags are rejected. This is source provenance only;
later units must extend their own real contracts for reviewed-output versions,
financial assumptions and downstream output-to-output dependencies. No local
rationalization/retain/retire/migrate recommendation rules are present.

## Reset and storage failures

`resetDemoSession()` creates a fresh fixture/session ID/timestamps, resets all
revisions to zero, removes derived metadata and immediately replaces the single
stored value. UI confirmation is outside the controller: Reset → Confirm reset
or Cancel. Confirm receives focus when opened; both choices return focus to Reset.

Malformed/incompatible/incoherent saved data is removed and replaced with the
known fixture. The UI announces recovery without displaying/logging raw stored
data. Access/read/write/quota failures retain a usable in-memory session and
show a refresh-loss notice. Failed replacements attempt to remove the old key,
so a quota error cannot normally resurrect an older edit after reset.
If browser policy denies both writing and removing an existing value, no code
can clear that inaccessible storage; the in-memory-only notice remains accurate
and persistence cannot be guaranteed. No alternate persistence is introduced.
