# U05.02 — License LLM findings contract

Version: **licenses/v1**, in review. This is a server-only, offline-testable
request/orchestration/validation boundary. It does not enable public analysis.

G2 v0.1 U05.02: **Request and validate LLM-based license opportunity findings**;
dependencies U05.01/U00.07; REQ-071. Approved acceptance: “AI supports missing
evidence, references known app/license IDs; no legal certainty claims.” REQ-071
asks the LLM to identify possible consolidation, duplication, under-utilization
and optimization opportunities, explain data used and highlight missing
contract/entitlement evidence. Existing U00.02/05/06/07 supply source contracts,
session lifecycle, adapter and controls. U05.01 supplies the read-only inventory.

G2 does not prescribe a closed business taxonomy or numerical impact contract.
`category` and `suggested_action` are bounded **LLM-authored text**, not a new enum
or classification rule. Quantitative opportunities, savings, utilization ratios,
legal rights, selection and cost impacts have no fields here. The G1 conceptual
`estimated_savings_if_supported` is not implemented in this unit: quantitative
implications and user selection belong to REQ-072/073, U05.03/04.
“Request and validate” requires the guarded server composition; it does not require
adding a public trigger in this unit. The current UI stays unchanged.

## Request and source identity

`buildLicenseRequest(currentSession)` validates the actual complete DemoSession,
fixture/version identity, currency, globally unique source IDs, app foreign keys,
Buyer/Target presence and existing record/session limits. Validation must preserve
the input exactly; no trimming, coercion, stripping, repair or seed substitution.
The request is a detached recursively frozen snapshot. It has the existing
Invocation shape: `module: licenses`, `prompt_version: licenses/v1`, immutable
`system`, `context: {deal: current_deal}`, `allowed_source_ids`.

The allowlist contains source-order license IDs then current application IDs
linked by those licenses, without fabricated names/indices or unrelated TSA IDs.
IDs use the existing SourceId contract (nonblank/no whitespace, max 128). Source
bounds are 1–200 licenses, 2–100 applications, max 50 per side; zero licenses
returns safe `invalid_input` **unsupported inference**, never zero opportunities.
There is no special runtime bound of ten. No source rows are silently excluded.

All license attributes remain exact: `license_id`, `app_id`, nullable `vendor`,
`product`, nullable integer `seats_entitled`/`seats_used`, nullable nonnegative
`annual_spend`, optional/nullable ISO `renewal_date`, nullable `notes`. Linked app
ID, current Buyer/Target `company_side`, name and all current context remain
available. Explicit null/omission is unknown; zero is known zero. Source notes
and other text are untrusted data, never instructions. The immutable prompt
requires evidence and missing entitlement/contract caveats, prohibits tool use,
legal certainty and numerical savings claims, and ignores all TSA/unrelated apps.
License spend is already included in app annual cost; they are never additive.

**Existing compatibility limit:** Invocation requires the whole synthetic deal,
including TSA and unlinked applications. The prompt ignores these; output cannot
cite them. No new transport or privacy guarantee is introduced. Before any live
activation, review data minimization/provider retention and this inherited whole
context requirement. No confidential data or user-entered keys/prompts are used.

Both the actual request and `{input, schema: z.toJSONSchema(LicenseResultSchema)}`
must fit **128,000 UTF-8 bytes**. Oversize returns `request_too_large` before
reservation/dispatch. The router may enforce a smaller approved policy limit.
Session serialization retains its existing 512,000-character limit. No chunking,
automatic prompts, truncation or limit increases.

## Structured model output dictionary

All objects are strict. Strings retain exact model text; nonblank validation does
not transform it. Array/text limits bound response size independently of coverage.

| Field | Meaning and bound |
| --- | --- |
| `findings` | 0–100 provisional model-authored findings |
| `finding_id` | Unique output identity, 1–64 letters/digits/underscore/hyphen; no source-ID derivation requirement |
| `category` | Model-authored description, nonblank, max 120 characters; no closed business taxonomy |
| `license_ids` | 1–200 unique exact source license IDs within a finding |
| `app_ids` | 1–100 unique exact current linked app IDs; must equal the set of apps linked by that finding's licenses |
| `suggested_action` | Model-authored advisory proposal, nonblank, max 400 characters |
| `rationale` | Model-authored explanation/data used, nonblank, max 800 characters |
| `evidence` | 1–200 strict `{license_id, attribute}` pointers; each finding license needs at least one |
| `attribute` | Exact LicensePosition key: license_id, app_id, vendor, product, seats_entitled, seats_used, annual_spend, renewal_date or notes |
| `unknowns`, `assumptions` | Separate explicit model-authored arrays, each 0–10 nonblank strings, max 200 characters each |
| `uncertainty` | `{level: low | medium | high | unknown, reason}`; reason nonblank max 400; qualitative, not calibrated probability |
| `review_required` | Literal true for every finding; no acceptance/selection state |
| `not_evaluated` | 0–200 unique `{license_id, reason}`; reason nonblank max 400; source ID cannot also occur in findings |

Within a finding duplicate license/app IDs and duplicate evidence pairs are
invalid. Evidence must reference that finding's license and an actually present
source attribute: explicit null may be cited as unknown; absent/undefined renewal
cannot be cited as a supplied value. App joins cannot be inferred/repaired from
names, vendors or array order. Total license memberships, app memberships and
evidence pointers are each capped at 400 across all findings. Extra properties
including savings, percentages, confidence, destination, selected and provider
identity are invalid; no zero/null default amounts are created.

Multiple distinct findings may refer to one license. Raw references are preserved;
the module reports overlap structurally, without prioritization, selection,
arithmetic or financial aggregation. Source existence/joins and pointers are
checked independently after the shared adapter validates JSON/schema/allowlist.
References are extracted as a unique union only after within-finding duplicate
validation, allowing legitimate cross-finding overlap under the existing adapter.

## Coverage, provenance and outcomes

`inspectLicenseResult` returns exact original validated data plus server-computed
coverage, or fixed `invalid_model_output`. It never invents/reclassifies findings.
Coverage includes:

- `status: complete | incomplete` and ordered reasons `missing_licenses`, then
  `not_evaluated_licenses`, where applicable.
- `source_count` (1–200), `accounted_count` (0–200, findings union plus not-evaluated).
- Source-order `missing_license_ids`, `not_evaluated_license_ids`,
  `overlapping_license_ids`. Each is bounded to 200.

Complete requires every source license in findings, with no missing or explicitly
not-evaluated licenses. Not-evaluated counts as accounted **but still incomplete**.
Empty output is valid incomplete, never proof that no opportunities exist.
“Complete” describes structural coverage, not evidence quality or legal certainty.

`createLicenseAnalyzer(options)` invokes only the existing `createAIRouter` with
`LICENSE_OUTPUT_CONTRACT` and the existing trusted-server caller/store interface.
Default policy returns `ai_disabled`; enabled options still require explicit
offline-test execution and store/caller. Production composition never imports
fake stores/transports. Tests alone create invented policies/provider identities;
they are not model or spend approvals. Existing independent paid/fallback budgets,
rate/concurrency reservations, settlement and fail-closed behavior are unchanged.
No retries, provider-error fallback or repair prompts are added.

Outcomes are strict `{status: error, error: {code, request_id, message}}`, or
`{status: success | incomplete, envelope, coverage, source_token}`. Errors reuse
existing codes and server-owned fixed messages; no raw provider/model/source text
is returned or logged. The existing ResultEnvelope retains module, request UUID,
input digest, actual model provider/ID, paid/fallback mode, required fallback reason,
prompt version, server timestamp, bounded nullable usage and fixed draft/reference
warnings. `cost_usd` remains null. Model output cannot supply this metadata.
Analyzer checks module/version, metadata schema, exact input digest, output byte
cap and module source/coverage integrity before returning an outcome.

The input digest is SHA-256 of JSON `{input, references: {allow_empty: true,
duplicates: reject}}`, matching the shared adapter/router serialization.
Actual model output **and complete envelope** must each fit **64,000 UTF-8 bytes**.
No result is silently trimmed. Output remains at most **2,048 tokens** under the
unchanged router policy; mocked transports do not prove that limit is adequate.

## Freshness and future consumer boundary

Before the first await, source token captures session UUID, fixture ID/dataset
version, application revision, license revision and SHA-256 of JSON
`{applications, license_positions}` in validated schema-key/source-array order.
It conservatively includes every application, so any application edit/publication
stales the outcome. License edits, source reordering and reset stale it even if
someone reuses revision numbers. TSA-only edits do not change this source token.
The envelope input digest still records the whole captured Invocation context.

`matchesLicenseSource(token, currentSession)` must be checked at consumption time,
including after a pending request finishes. Analyzer can only know its captured
snapshot; it cannot observe later browser edits. `inspectLicenseOutcome(outcome,
capturedSession, currentSession)` is the stronger future server consumer gate:
rebuild the captured request, revalidate exact outcome/schema/module/version/
digest/source token/coverage/references/bytes, then return `current`, `outdated`
(no outcome) or `invalid` (no outcome). Current incomplete outcomes retain their
incomplete status. TSA-only changes are compared using the **original captured**
snapshot, not a reconstructed post-edit request with a different input digest.

This gate validates structure/freshness, **not authenticity**. Never trust an
arbitrary browser-submitted envelope as genuine AI output, even if all hashes
match; hashes are not signatures. Future trusted delivery remains a separate
approval/integration gate. No current-deal/revision/derived-results writes,
sessionStorage, persistence, client import or downstream publication occurs here.

## Fabricated offline test example — no inference occurred

This incomplete specimen is constructed only in offline tests, using exact source
IDs supplied by the test. It is not displayed to visitors and makes no claim that
an actual model analyzed the data:

```json
{"findings":[],"not_evaluated":[{"license_id":"lic-TEST-ONLY","reason":"Fabricated offline example; contract evidence was not evaluated."}]}
```

`lic-TEST-ONLY` is a placeholder: the inspector rejects it unless it exists in the
explicit test source. The test script also builds fabricated findings with fixed
non-recommendation text to verify joins/coverage, never derives suggestions from
seat ratios, names, dates, spend or vendor strings.

## Security, limitations and remaining gates

Public `/license-optimizer` keeps its read-only source table, one AI-not-enabled
notice and “No AI license analysis has run.” No public license API, readiness
button, fake results or review/selection controls are created. ALA POST remains
unconditional 503/no-store without reading its body; GET stays unsupported.
No ALA/session/fixture/security/theme/dependency changes are needed.

Structural validation cannot prove narrative grounding or prevent all false
free-text legal/savings claims. Prompt constraints and exclusion of quantitative
fields reduce that surface; semantic model quality and entitlement caution still
require separately approved live evaluation and human review. No legal certainty
or savings verification is promised by passing these checks.

Remaining live gates: ADR-012 exact primary/fallback model approvals, verified
JSON/semantic/latency/retention/license/cost quality, approved independent budgets,
real durable atomic usage store, trusted ingress identity/anti-abuse, provider
billing backstops, deliberate replacement of existing live hard stops, trusted
result delivery and G5 release approval. **200-license narrative output adequacy
at 2,048 tokens remains unverified**. The boundary test accepts a 200-source input
and fabricated output under byte caps; it does not demonstrate model capacity.
Oversize/truncation must fail/incomplete, never silently reduce the source set.
U05.03 owns review/selection; U05.04 owns cost impacts and is gated by U03.01.

Run `npm run check:license-findings`, then the final `npm run check:ci`. No browser
UAT is added because this unit changes no public UI. Rollback: revert this scoped
code/test/docs/scripts change; no migrations, storage keys or external resources.
