# U01.03 — Manual column mapping and confirmed local drafts

Status: **in review**. REQ-012/013/014; approved G2 U01.03. This is mapping and
row validation only. It does not publish records, replace inventories or enable AI.

## Authority and manual field mapping

The approved G0 requirements describe key columns, visible validation and confirmation;
G2 separates U01.03 mapping from U01.04 shared publication. The authoritative types
are the unchanged `ApplicationSchema` in `lib/contracts/demo.ts` and
[U00.02 data contract](U00.02_Shared_Demo_Data_Contract.md). IDs are source-owned,
opaque, nonempty and whitespace-free. No approved alternate/generated-ID policy or
auto-mapping convention was found. Required source mappings are therefore `app_id`,
`app_name`, `function`; every select starts explicitly **Not mapped**.

`ColumnSelections` maps the ten established fields to a zero-based source-column
integer or null. The UI shows **Column N: original header**, including duplicate
header names, so selection never depends on header text. Optional fields may stay
unmapped. A source index cannot be reused: choices used by another target are
disabled, and the pure validator independently rejects reuse, invalid indexes and
unknown target fields. Extra raw columns remain excluded. `company_side` is never
selectable: the CSV owner supplies Buyer or Target. Raw source headers, values,
order, side and generation remain intact. No automatic guesses or recommendations.

## Narrow normalization and validation policy

| Field | Current rule |
| --- | --- |
| `app_id` | Required mapped source value, unchanged; no trim, generation or ID rewrite; exact case-sensitive duplicate detection within that side |
| `app_name`, `function` | Required mapped nonblank text; schema trimming |
| `vendor`, `owner` | Optional; trim text, blank/unmapped becomes null |
| `notes` | Optional; trim, blank/unmapped null; schema maximum 500 characters |
| `annual_cost` | Optional; blank/unmapped null; strict plain nonnegative decimal, zero retained |
| `criticality` | Optional; trim/lowercase, then low / medium / high / critical, or null |
| `deployment` | Optional; trim/lowercase, then cloud / on_premise / hybrid, or null |
| `lifecycle` | Optional; trim/lowercase, then active / legacy / retiring, or null |

Cost input permits digits with an optional decimal point followed by digits,
after outer whitespace removal. Leading zeros/trailing fractional zeros are
unambiguous and accepted. Signs, exponent input, commas, currency symbols,
percentages, `.5`, `1.`, nonfinite values and values losing decimal digits on
conversion to the existing JavaScript number contract are rejected. Comparison
uses canonical decimal text against the expanded Number round-trip representation;
it performs no currency conversion or decimal rounding. Examples: `0`, `01.2500`
and `0.0000001` accepted; `1,000`, `1e3`, `9007199254740993` rejected. Normalized
candidate values are not changed by the inherited currency display formatter.
The existing session currency is passed down for display only; no new session
consumer or organization/currency editing is added.

Every row is checked with `ApplicationSchema.safeParse`. At least one and at most
50 data rows from an existing ready CSV are required for confirmation. Duplicate
IDs within the candidate are rejected even if another field in that row is bad.
No valid-row subset can be confirmed: any issue yields no normalized candidate
rows. A header-only U01.02 source still previews normally but cannot confirm.

`MappingValidation = {valid, rows: Application[], issues, total_issues}`. Each issue
is `{row: number|null, field: MappingField|'mapping', code}`. Null row means a
mapping/source-level problem; numeric rows are 1-based data records. There is one
schema issue per field per row (duplicate low-level diagnostics are collapsed),
plus candidate-ID uniqueness errors. Only the first **40** issues are retained;
the full bounded count is reported. Fixed `MAPPING_MESSAGES` cover missing mapping,
invalid/reused column, unknown target, empty/invalid source, missing value, bad or
duplicate ID, cost, enum, notes length and generic contract failure. No cell value,
Zod/raw exception, path or stack trace enters these notices/logs.

## Ownership, lifecycle and exact U01.04 handoff

`CSVPreview` remains the sole owner of both sides' React memory. The existing
U01.02 parser/reducer is **unchanged**. `columnMappingReducer` composes its CSV
transitions and owns `MappingState = {csv: CSVDrafts, mapping: Record<side,MappingDraft|null>}`.
Each mapping draft is `{source_generation, revision, mappings, confirmed}`. Validation
is derived live by the UI; Confirm Mapping revalidates synchronously in the owner
reducer, against the exact current source generation and mapping revision.

A successful local handoff has this exact type (not serialized/published):

```ts
type ConfirmedMapping = {
  status: 'confirmed_draft'; validation_version: 'u01.03/v1';
  side: 'buyer' | 'target'; source_generation: number; mapping_revision: number;
  file_name: string; file_size_bytes: number;
  mappings: ColumnSelections; rows: Application[];
};
```

This is reachable only inside the current module's `state.mapping[side].confirmed`.
Its matching raw source is `state.csv[side]` with the same generation. Filename is
bounded display metadata, **not** durable identity, authorization or proof of
publication eligibility. Generation/revision are module-local, not dataset versions.
No persisted DTO, new global store or public API exists.

Beginning/replacing/clearing a file or a read error clears same-side mapping and
confirmation immediately. A new ready file starts all targets unmapped. Stale CSV
completion remains rejected by the original reducer. Mapping changes increment
revision and clear confirmation. Obsolete generation/revision actions cannot
confirm a different source/map. The other side stays intact. Tabs preserve drafts;
leaving/remounting/refresh discards them. Unmount read suppression remains U01.02's
guard. Global Reset retains its unchanged shared-session behavior: it neither
publishes nor implicitly confirms these independent temporary drafts.

**Proposed U01.04 handoff/approval items, not new approved ADRs:** mandatory source
IDs vs any future generated-ID policy; accepted numeric lexical/precision and enum
alias policies for publication; cross-side/global ID uniqueness and collisions;
linked license/TSA references and replacement semantics; source freshness, dataset
version/revision changes and downstream invalidation. This unit uses strict schema-
supported local rules and validates duplicate IDs only **within each side**. Two
confirmed sides may still conflict, and confirmation never guarantees publication.
No ambiguity blocks this bounded local behavior; publication policy stays deferred.

## UI, accessibility and exclusions

Below each ready raw CSV, native selects have field names, Required/Optional labels,
canonical enum help and issue associations. Live validation announces a concise
count and lists row/field issues. The normalized caption says **Proposed normalized
data — not imported**. Confirm Mapping is disabled with guidance until valid;
clicking produces **Mapping confirmed (draft only)** and **Not imported/published**.
No focus is stolen on edits. A1 tokens, native focus, labeled scroll regions and
row/column scopes are reused; narrow tables scroll internally.

No edits to shared source, IDs, revisions, AI metadata, fixture/dataset versions,
sessionStorage, parser policy, routes, backend, providers or budget controls. No
upload/import, export/template, AI call or recommendation. See focused checks and
limitations in [U01.03 validation](../../U01.03_VALIDATION.md). Rollback is reverting
this isolated mapping/test/docs diff; no migration, server data or external resource.
