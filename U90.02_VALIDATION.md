## Implementation and bounded design

Added `scripts/check-provider-acceptance.mts` and registered `check:provider-acceptance` in existing `check:ci`. It imports existing guarded license fixture policy, reference fake store, Playbook/ALA specimen helpers, actual module owners and U00.08's safe presentation function. It does not run imported complete suites or introduce another test framework.

The new matrix contains **84 rows**:

- **12 successful route rows**: four modules times paid-first, insufficient paid budget, and explicitly disabled paid routing. For each module, the exact same source/specimen is used on both transports and validated result data is deep-equal across all three routes. Server-owned provider/model, mode, permitted routing reason and one selected dispatch are asserted.
- **64 failure rows**: four modules times paid/fallback times eight cases (provider exception, typed unavailable, timeout, malformed output, invented reference, negative usage, reservation failure, settlement failure).
- **8 missing-usage rows**: four modules times paid/fallback, verifying valid structured output with unknown token counts retains the full reservation rather than inventing cost or refunding exposure.

The selected existing control groups retain detailed atomic store, quota and failure tests. They are reused rather than copied into a second implementation. Full CI also executes their unchanged complete suites once.

The source is the existing synthetic session/fixture, not another deal. Actual saved ALA overrides, license selections and Playbook visitor edits are created against accepted owner results. Failure requests use the same owner after acceptance and assert that originals, saved review objects, session/upstream assumptions and (for Assistant) accepted history remain unchanged and current. Playbook's isolated source is immutable and provides its required subscription interface; no public owner is fabricated. No Assistant conversation handle is serialized.
