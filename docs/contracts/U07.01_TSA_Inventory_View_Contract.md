# U07.01 — Read-only linked TSA service inventory

In review. Exact approved G2: **Display linked synthetic TSA services with dates
and statuses**, dependencies **U00.02 U00.05**, **REQ-080**. Exact unit-register
acceptance: **List shows required TSA fields; empty/invalid fields handled**.
G0's editable TSA capability is split by G2: U07.02 owns editing/status/filter/date
attention; U07.03 owns exports/dashboard publication. Neither is implemented here.

## Source and identity

The existing `/tsa-tracker` route renders TSAInventory. It reads useDemoSession,
then session.current_deal.tsa_services and applications from the same snapshot.
There is no new fixture, source owner, storage key, local editor or API. All existing
schemas, fixture/version and session controller remain unchanged. Provider hydration,
subscription, navigation/refresh/storage recovery and Reset retain existing semantics.
TSA updates through the existing controller increment the independent TSA revision;
application changes update displayed names without changing exact relationship IDs.
The UI never invokes updateTSA/updateApplication or registers a derived result.

The five bundled services are fictional source data, not model findings, approved
milestones, contractual obligations or verified risks. Five is not a view invariant;
empty through existing maximum 100-service sessions are supported. Dataset, TSA and
application revisions describe the current source. No global/dashboard metric is
published; the displayed row count describes this inventory only.

## Display dictionary

| Column | Exact source and unknown treatment |
| --- | --- |
| TSA ID | tsa_id, unchanged opaque identity and React row key |
| Service title | title, source text |
| Provider / Recipient | provider / recipient, source text (not inferred Buyer/Target direction) |
| Owner / role | owner; null → Unknown |
| Start / End date | start_date / end_date as exact YYYY-MM-DD; null → Unknown |
| Source status | planned → Planned; active → Active; at_risk → At risk; completed → Completed |
| Exit milestone | exit_milestone; null → Unknown / not supplied |
| Risk / dependency notes | risk_notes; null → Unknown / not supplied |
| Linked applications | related_app_ids in exact source order, each raw ID plus current exact-join name and Buyer/Target side |

No Date/time-zone parsing, UTC offset, overdue/approaching milestone logic, sorting,
status inference or risk score. at_risk is a provided status, not a computed finding.
Source strings remain ordinary escaped React text, including quotes/newlines/Unicode
or markup-like notes; no HTML, URL activation or markdown evaluation.

Omitted related_app_ids displays **Relationship information not supplied**. An empty
array displays **No application links recorded**. Neither invents dependencies.
Provider/recipient labels are independent of linked app sides and retain exact text.

## Defensive pure projection

Client-safe tsaInventoryRows accepts isolated unknown inputs and uses original
TSAServiceSchema/ApplicationSchema. It does not replace full session validation.
The production provider has already validated the complete shared dataset and
referential integrity; malformed candidates exist only in tests.

The helper enforces existing 100-service/100-application and MAX_SESSION_CHARACTERS
bounds; non-arrays, overflow and cyclic/unserializable source fail with one fixed
inventory issue. Invalid or duplicated TSA identities are omitted with fixed bounded
row-number issues, never generated replacement IDs or guessed field values. Source
text that the shared trimming schema would alter is rejected rather than silently
normalized. Valid services preserve source order and exact values; original inputs
are never mutated. Parsed records are temporary projections, not authoritative state.

Missing, malformed or duplicate application IDs cannot resolve to an arbitrary app.
The row retains its exact related_app_id and displays **Unresolved application
reference**, without inventing a name/side. Issues are fixed text plus bounded row
numbers; raw invalid data or exception text is never dumped. At most one application
issue per input app and one service/link issue per service, within existing row caps.
Full shared-session schema remains the source authority and still rejects dangling
references; the new view adds no repair/import path.

## States, layout and accessibility

- Not ready: accessible Preparing the shared TSA inventory status.
- Missing session: explanatory unavailable status; no guessed rows.
- Empty valid list: No TSA services are present; no table or fabricated services.
- Invalid/unresolved projection: visible issue notice; no invalid service row or
  phantom linked application. A wholly invalid inventory has no validated rows.

Existing A1 Coastal Navy typography/tokens and inventory table styles are reused.
The table has a caption, eleven column headers, stable-ID row headers and a labeled,
focusable horizontal scroll region with instructions. Scoped widths preserve dates
and long notes/links; the page itself does not overflow at 1440/390/320. Status is
explicit text; color is not required to understand it. No Add/Edit/Change Status/
Filter/Export controls or inactive controls pretending to implement future actions.
