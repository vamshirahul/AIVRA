## Policy, limitations and deferred publication

The unchanged ApplicationSchema/U00.02 contract support required source IDs/names/
functions, schema text trimming and nullable optional fields. No approved default
mapping or ID-generation policy exists. The narrow policy is manual/unmapped,
exact IDs, optional blanks null, trimmed lowercase canonical enum tokens only,
and lossless plain decimal conversion; no aliases, currency guessing or rounding.
See the new contract for all accepted/rejected formats and exact handoff type.

Mandatory IDs, future numeric formats/enum aliases, cross-side/global ID collision
handling and linked license/TSA integrity are **proposed U01.04 handoff/approval
items**, not new approved decisions. This unit checks duplicate IDs within each
side only; confirming both does not prove publication eligibility. U01.04 alone
owns record replacement, cross-entity integrity, dataset/version/revision changes
and downstream invalidation. No blocker to this narrow local behavior remains.

Unit and browser tests made zero provider/model/external page requests (fetch
rejection in unit tests, external-page blocking/counting in CDP). No API charges,
cloud provisioning/deployment or U90/live-provider claim. Manual screen-reader/
full WCAG and all future publication paths are not tested. Large bounded CSVs
can have long option lists; no unauthorized extra intake limit was introduced.

Rollback is reverting these eleven mapping/view/test/docs files, with no migration,
server data or resources. PR/base/head are reported at submission. Do not merge,
