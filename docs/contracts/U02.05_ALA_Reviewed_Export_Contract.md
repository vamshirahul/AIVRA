# U02.05 — Reviewed ALA export and future consumption contract

Status: **in-review**, not accepted; M02 is not released or live end-to-end.
G2 U02.05: export/consumed-by-downstream ALA result contract; prerequisite U02.04;
REQ-026/064. Exact acceptance: `Download JSON/CSV with provenance; CSE/Playbook read
same reviewed IDs`. G2 also specifies CSV/JSON for tables. The founder explicitly
confirmed **implement JSON and CSV** after the packet's JSON-default discrepancy
was reported. Historical G0/G1/G2 records remain unchanged; no new ADR approval.

## Boundary and authority

`lib/ala/review-export.ts` is client-safe, bounded and side-effect free except its
explicit browser download function. It reuses U02.04 draft validation/effective
enumeration and existing ApplicationSchema. No server-only runtime import, provider
call, persistence, API, event topic, storage bus or downstream integration.

**The current public ALA endpoint still always returns 503; there are no real
validated AI results to export publicly.** The page still supplies literal absent
view to the review workspace, so neither download button appears. No sample-result
route, query/header switch, fixture import or public test hook enables it.

## Versioned canonical JSON dictionary

UTF-8 JSON, MIME `application/json;charset=utf-8`, filename
`aivra-ala-reviewed-draft.json`. Version is **ala/review-export/v1**, distinct from
the unchanged LLM **ala/v1**. No optional/unknown extension fields are accepted.

| Field | Required meaning |
| --- | --- |
| contract_version | Exact ala/review-export/v1; no version guessing or implicit migration |
| artifact_kind / status / source_module | ala_review_export / exported_unapproved / ala |
| disclaimers | Exact three strings below: AI draft, visitor-unapproved values, incomplete warning |
| analysis.metadata | Original bounded model_provider/model_id, paid or fallback; fallback requires budget_exhausted or paid_unavailable routing_reason, paid forbids it |
| analysis.provenance | Original ala/v1, generated_at UTC, request UUID, 64-hex input_digest |
| analysis.source_revision / currency | Original nonnegative application revision and captured currency |
| analysis.coverage | Exact complete/incomplete, reasons; Buyer/Target source_count/accounted_count and ordered missing_app_ids/not_evaluated_app_ids |
| analysis.findings | Full original order and frozen fields: finding_id/domain/relationship, ordered Buyer/Target IDs, all original actions/rationales, evidence pointers, qualitative uncertainty, captured member names and source_evidence values |
| analysis.missing | Original source-ordered app_id/side records, no fabricated recommendation |
| analysis.not_evaluated | Original source-ordered app_id/side/reason; accounted but unassessed/incomplete |
| review | Exact U02.04 result_identity and current valid visitor overrides, separate from original analysis |
| effective_actions | One ordered entry per original action occurrence, defined below |
| counts | source_applications, findings, original_action_rows, visitor_overrides, missing, not_evaluated; independently recomputed |

Each effective_actions entry contains finding_id, action_id, original subject app_id/
side; original `{disposition,destination,rationale}`; effective `{disposition,destination}`;
origin ai_suggestion or visitor_override; visitor_reason null for unchanged AI actions,
nonblank <=400 characters only for real overrides. Original actions/rationales remain
inside analysis as well. No deduplication across findings or inferred review/approval.
An unchanged AI action is not a human-reviewed or approved decision.

Disposition literals are Retain, Retire, Migrate, Integrate, Needs Review. The first,
second and last require null destination; Migrate/Integrate require another member
of that finding with exact ID/side. Relationship literals remain functional_overlap,
potentially_related, unique, uncertain. Null evidence is unknown; numeric zero is
zero; null destination is not applicable. Names/text/case/reasons are never trimmed,
repaired or silently truncated. ApplicationSchema normalization would be rejected.

The projection does not expose session ID/application digest/source token, usage,
warnings or full provider envelope; the export does not invent them. No exported_at
or reviewer/approval timestamp is added: serialization is deterministic for identical
view/draft inputs and uses only the server-supplied generation timestamp.

## Validation and future consumers

`ReviewedALAExportSchema` is strict and bounded. `buildReviewedExport(view,draft)`
requires current/incomplete trusted projection, revalidates its full display shape,
checks view state against coverage, and validates the latest draft again. It fails
closed without partial data. `readReviewedExport(jsonOrObject)` performs bounded
version-aware parsing/structural validation only and returns an immutable artifact.
Unknown/superseded versions, extra fields, malformed identities, foreign/mismatched
subjects/targets/evidence, duplicate/conflicting actions, inconsistent member names/
captured values, false coverage/counts or inconsistent effective values are rejected.

Checks retain existing limits: <=100 findings, <=200 actions, <=400 evidence/member
references, <=100 distinct applications and <=50/side. Original generated data must
still fit 64,000 bytes. Coverage is independently reconciled from member, missing
and not-evaluated references; original inspected order is preserved. Repeated IDs
across findings remain distinct action occurrences with unchanged stable IDs.
Existing U02.04 same-subject checks validate both original and effective groups.

**Parsing a file or possessing an opaque TypeScript type is not cryptographic proof
of model execution, authentic source values, current browser freshness or authority.**
A fully schema-valid fabricated artifact can pass structural validation. This unit
does not import a downloaded file into a trusted AI view or session. Only the future
approved protected result source can establish runtime provenance/currentness.

`consumeReviewedExport(input)` returns read-only version/status, coverage, provenance,
metadata, actions and original_analysis. Future CSE/Playbook/License/Scenario consumers
must use `actions[].effective`, retain original/origin/visitor_reason, and propagate
incompleteness rather than claiming complete/approved results. No actual module is
wired, no session record is changed, and no artifact is published downstream here.

## CSV table view and encoding

UTF-8 CSV, MIME `text/csv;charset=utf-8`, filename `aivra-ala-reviewed-draft.csv`.
Every cell quoted, internal quotes doubled, rows separated by CRLF. One `analysis`
metadata row always precedes ordered `action` rows, including zero-action/incomplete
analysis. Preserve the metadata row when moving the table; it carries provenance,
coverage/missing/not-evaluated reasons and explicit unapproved/incomplete disclaimers.

Ordered columns:

```text
record_type,contract_version,status,request_id,provenance_json,metadata_json,
source_revision,currency,coverage_json,counts_json,missing_json,not_evaluated_json,
disclaimers_json,finding_id,domain,relationship,buyer_json,target_json,
finding_rationale,evidence_json,source_evidence_json,uncertainty_json,action_id,
subject_app_id,subject_side,original_disposition,original_destination_json,
original_action_rationale,effective_disposition,effective_destination_json,
origin,visitor_reason
```

Action rows retain finding membership/names, full finding rationale/evidence/captured
values/uncertainty and per-action original/effective/origin/reason. Structured cells
contain JSON (including explicit null); unrelated metadata columns are blank on action
rows and action columns blank on the metadata row. This is a tabular companion, not
a second canonical reader/import format. JSON is the lossless consumption contract.

Formula-like text beginning with whitespace/invisible separators followed by =,+,-,@,
or leading tab/CR/LF, receives a leading apostrophe before CSV quoting. This safety
representation can change dangerous text/IDs in CSV; the exact value remains in JSON.
Unsupported C0 controls cause safe CSV rejection, never stripping/truncation. CSV
formatting is not a guarantee of every spreadsheet's behavior; import cells as text.
Never evaluate formulas, HTML or embedded instructions. The export may contain full
captured evidence/visitor commentary: use synthetic/test data only, not confidential
transaction data. No requests or telemetry transmit file contents.

## Download, file limits and errors

Each JSON/CSV file is limited to **1,000,000 UTF-8 bytes**, a separate conservative
derived-file cap near the combined two 500,000-byte intake limits. This is not a
raised AI output cap, tokenizer allowance or new source storage policy. JSON copies
and CSV repeated evidence may exceed the bound: return export_too_large with no file,
no truncation/chunking or dropped IDs. The LLM input/output/token caps are unchanged.

`prepareReviewedDownload(view,draft,format)` validates and serializes on demand.
`downloadReviewedResults` uses a Blob/object URL/temporary anchor only on deliberate
click. The existing ResultReview uses `latest.current` synchronously, with no second
review source. Unsaved form fields are excluded; saved overrides are reflected.
Absent/invalid/outdated view or mismatched review allocates no URL. Links are removed
in finally; failed creation/append/click/cleanup scheduling revokes any allocated URL.
On initiation, revocation is scheduled on the next task so the click can resolve.
The only scheduled work is resource cleanup, not polling, inference or autosaving.

Both buttons are native secondary actions, with existing A1 styling and polite
initiation status/safe alert errors. Status says **Download initiated**, explicitly
not that browser/disk saving succeeded. Invalid_export/export_too_large and browser
download_unavailable errors expose fixed bounded text, retain the local draft and
never leak exceptions. Navigation/invalidation retains the existing keyed lifecycle.
