# U10.03 Assistant Chat UI Contract

## Approved mapping and boundary

Approved G2 v0.1 and `docs/registers/unit-register.csv` define U10.03 as
**Create visitor chat UI with citations and reset**, parent **M10 — AI M&A
Assistant**, dependency **U10.02**, requirements **REQ-090 / REQ-093**.
The acceptance criterion is **“Chat asks questions; citation labels shown; no
backend side effects”**. The founder's U10.03 execution packet explicitly permits
a typed presentation seam when protected public delivery is unavailable.

This unit implements the composer, conversation display, structured citations,
disclosures, error states and Reset. It does not implement U10.04, a public Ask
transport, live providers, exports, transaction mutations or persistence.
Protected Ask is intentionally unavailable on the public page. UI tests with
mocked providers do not establish genuine LLM quality or public end-to-end Ask.

## Source authority and projection

`createAssistantChatSource` is an additive **server-only**, per-workspace factory
over the existing U10.02 owner, actual source reader, trusted caller and source
subscription. It invokes only `owner.createConversation`, `owner.ask`,
`owner.getHistory` and `owner.isCurrent`. Existing owner validation, router,
budgets, fallback eligibility, accounting and live hard stops remain unchanged.
There is no singleton, endpoint, serialized handle, client-selected provider,
hardcoded caller or direct adapter call.

The factory privately retains conversation handles and exact original owner-issued
successes. It validates their history and currentness before projecting questions,
answers, typed references and allowlisted provider/model/mode/routing reason,
generation time and prompt version. Display views omit session/conversation/request
identities, source digests, source context, system instructions and caller keys.
The exact issued view identity must remain current; imported or cloned JSON is
not authority. A strict supplemental display guard rejects unexpected keys and
invalid bounds, but structural validation alone proves neither ownership nor
citation membership. Those remain the server owner's responsibility.

`AssistantChatSource` is a function-bearing in-memory composition contract, not
an RPC protocol or security boundary against arbitrary trusted JavaScript. Its
server implementation cannot be passed across Next's client serialization
boundary. A future approved protected per-tab transport must supply genuine
authority and delivery without exporting these closures. Production currently
passes **no source**, creates no owner and makes no Ask request.

## Presentation limits and lifecycle

- Questions: nonblank, at most 2,000 JavaScript characters; backend-compatible
  control-character rejection. Oversized pasted text is retained with an error,
  never clipped; Ask is disabled. Enter adds a line; Ask is explicit.
- Answers: at most 4,000 characters; at most 20 strict typed references; at most
  seven known missing-context disclosures. Answered results require citations;
  insufficient-evidence results may have none.
- Conversation: four complete ordered exchanges; 32,000 UTF-8 bytes measured
  against the original full owner history, including metadata. No truncation.
  Existing complete invocation/output limits remain authoritative.
- No chat storage in localStorage, sessionStorage, cookies or databases. State is
  limited to a mounted workspace and its private in-memory owner. Existing deal
  session storage is unchanged.

The controller supports initial/ready, invalid question, submitting, answered,
insufficient evidence, AI disabled, safe provider/budget/fallback/rate/concurrency
errors, source changed, history limit and Reset completed. Safe error copy is
reused; private exception messages are never displayed. Duplicate submission is
blocked. Success must append exactly one matching question to the unchanged
ordered prefix; a successful flag cannot authorize an old or unsupported view.

Every read and action checks current source identity and the latest actual shared
session. Authoritative source subscriptions include saved review/assumption and
owner-issued Playbook changes. Source changes irreversibly invalidate captured
answers until Reset. Epoch checks suppress asynchronous completions after Reset,
source changes or unmount. Reset clears prepared text, transcript and current
conversation handle, then captures fresh source authority. The next Ask requires
a newly issued owner conversation. It does not reload or reset transaction data.
The controller refreshes explicitly after its own Ask/Reset; external changes
arrive through the protected subscription.

## References, disclosures and safe rendering

Namespaced references retain exact IDs and parent/side relationships: Buyer/Target
applications; application-linked licenses; TSA; original ALA findings/actions;
original license findings; financial assumption lines; Playbook phases,
activities, milestones and risks; and section references separating original AI
content from visitor reviews. Missing descriptions remain missing; no names,
URLs, links or citations are inferred from narrative text.

Verified envelope metadata is displayed as paid or open-weight fallback with the
existing reason. Every response is an unapproved illustrative AI draft, not advice
or a verified transaction fact. Missing/incomplete sections remain explicit.
Citation membership does not verify narrative truth or confidence. There are no
confidence scores, invented savings or deterministic recommendation rules.

All text uses React escaping. No HTML/Markdown execution, generated links,
`dangerouslySetInnerHTML`, body logging, analytics, credentials or tools.

## Accessibility and verification

Semantic headings, a labelled multiline composer, linked character/error guidance,
native buttons, ordered question/response articles and polite status/error
announcements support keyboard and reading order. Submit and Reset return focus
to the composer. Existing focus styles and scoped wrapping handle 1440/390/320px
without global horizontal overflow. Ask is visibly disabled when unavailable;
Reset and question preparation remain functional.

`check:assistant-chat` exercises the actual owner and guarded mocked routing,
projection, limits, errors, privacy, invalidation and Reset. The separate Chromium
loopback harness mounts the actual component with isolated prevalidated fixtures;
no fixtures enter the production route. Production browser checks verify disabled
Ask, zero chat requests and unchanged deal data. Browser accessibility-tree and
keyboard checks are evidence, not a full assistive-technology audit.
