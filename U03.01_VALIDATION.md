## Formulas, precision and double-counting rationale

Contract **cse/calculation/v1**. Explicit included line assumptions in **integer CAD cents**: A=sum annual_run_rate, M=sum migration_one_time_cost, T=sum transition_overlap_cost. One-time O=M+T, horizon H=A*horizon_years, illustrative N=H-O. O deducted once. Whole horizon1–30 years; full annual run rate solely for illustration. No discount/ramp/tax/FX or inferred savings; no action-label-specific math. Costs/savings nonnegative; N can be negative.

Example fabricated assumption A=10,000, M=2,000, T=3,000 cents: one-year N=5,000; three-year N=25,000 with O still5,000. Zero inputs can compute zero. Missing components stay null/unknown and block the affected aggregate/net. Known annual or one-time components remain visible independently. No inclusion means no supported estimate, not a $0 KPI.

Each amount and aggregate is bounded to1,000,000,000,000 cents (absolute bound for N); BigInt exact arithmetic, JSON integer outputs, no intermediate rounding/capping. Source annual_cost is kept in original major units and converted only as exact cost evidence if at most two decimal places and bounded; unsupported precision is reported, never rounded. Annual amount requires known source cost evidence but is never inferred or capped to that source cost.

Ownership is conservative **whole-application spend**: every included line carries a unique line ID, explicit attribution key and exact spend_app_ids containing its validated ALA subject. Duplicate attribution or shared owners create explicit conflicts; no winner/merge/repair. A withheld included component makes its aggregate unknown rather than silently dropping the line. Application cost and contained license spend are never additive. Generic inspectCostClaims can detect future app/license ownership collisions; license-kind financial amounts always withheld today.

Original ALA findings/destinations/rationales/coverage/provenance and effective visitor overrides remain separately preserved via the existing reviewed representation. Financial inclusion is an independent visitor assumption, never an AI decision or approval. Source binds session, fixture/version, application+license revisions and ordered records digest; review_digest also captures current overrides/effective actions so old financial requests cannot replay after review changes. Owner must supply fresh server-validated context; hashes/types/schema are not inference authentication.
