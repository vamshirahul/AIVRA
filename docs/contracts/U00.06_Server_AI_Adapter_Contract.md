# U00.06 — Server AI adapter contract

REQ-020/050/056/057; ADR-002/004/005/006/009. Exact live-model selection remains
ADR-012 work. This foundation introduces no public endpoint, live invocation,
fallback dispatch, budget/rate store, UI action or business recommendation rule.

## Server boundary and composition

All four modules in `lib/server/ai/` import `server-only`. Next.js prevents their
use from a client component. They use Node crypto/validation only on the server.
Application components/routes import none of them. Provider credentials/model
configuration are read only by the explicit server factory, never on import.

Public composition for a future protected server caller:

```ts
import { createAIAdapter } from "lib/server/ai/adapter";
import { createOpenAITransport } from "lib/server/ai/openai-transport";

// Relative imports should be adjusted to the caller; no path alias is configured.
const invoke = createAIAdapter(createOpenAITransport());
// invoke(request, outputContract) returns a typed failure in U00.06, not a live call.
```

`createAIAdapter(transport, {timeoutMs?})` is the trusted internal injection seam
used by offline tests and future protected provider composition. Transport is
server code, never client-supplied instructions, functions or credentials.
`sdk-transport.ts` is internal SDK plumbing, not authorization: do not bind a
chargeable external model to it outside the guarded provider factory. Tests use
the SDK's offline `MockLanguageModelV4`. An arbitrary injected function is not
a security boundary and must never be selected/deserialized by a public caller.

## Validated invocation input

```ts
type InvocationInput = {
  module: "ala" | "licenses" | "playbook" | "assistant";
  prompt_version: string; // e.g. contract-check/v1; server-owned version
  system: string;        // trusted server-owned instructions
  context: {
    deal: SyntheticDealFixture; // existing normalized U00.02 contract/current deal
    user_text?: string;         // untrusted user context, not system instructions
  };
  allowed_source_ids: string[];
};
```

The strict input rejects extra fields (including credentials). The module list is
server-owned. Prompt versions match `name/vN`, with a lowercase name of at most
32 characters, positive integer version of at most four digits, and 64-character
overall bound. System instructions are nonempty and at most 4,000 characters;
user context text is at most 2,000 characters. Total serialized request is capped
at **128,000 UTF-8 bytes** before dispatch. Context reuses the complete existing
`SyntheticDealFixtureSchema`, not a second importer or duplicate domain schema.
Record limits are 50 apps per side / 100 total, 200 licenses and 100 TSA services.

Allowed IDs: 1–400 unique opaque, nonempty, whitespace-free strings, at most
128 characters each. Each must occur in the actual supplied application,
license-position or TSA ID fields. No IDs are inferred from names/vendors.
The caller supplies the relevant subset; merely existing elsewhere in the deal
does not make an ID an allowed citation. Full fixture cross-references validate
before dispatch. This is source consistency, not confidential-data approval.

## Caller-owned output and reference contract

```ts
type OutputContract<T> = {
  schema: z.ZodType<T>;
  references: {
    extract: (validated: T) => unknown; // return flat structured cited ID list
    allow_empty: boolean;
    duplicates: "reject" | "allow";
  };
};

// Generic shape illustration only; not a business result or ALA schema:
type ModuleOwnedShape = { source_ids: string[]; /* module-specific fields later */ };
```

The module owns its strict, JSON-compatible Zod output schema and extraction of
structured citation fields. U02.01 owns detailed ALA schemas/prompts; no such
business schema is defined here. Use strict objects without coercion, stripping,
defaults or data transformations. The adapter independently validates output
and rejects any change between generated and parsed data rather than silently
dropping fields, fixing IDs or replacing recommendations. Output is capped at
64,000 UTF-8 bytes. Empty/null/non-JSON/invalid output is rejected.

After shape validation, the extractor's result must be at most 400 well-formed
IDs, all in the original allowlist. No citations are accepted only with explicit
`allow_empty: true`. Duplicate rejection/allowance is explicit, allowing future
modules to distinguish global duplicate restrictions from legitimate repeated
citations across findings. The caller must correctly extract all relevant
structured references; narrative text is not searched or interpreted as IDs.

Validation verifies shape and source-ID membership, **not narrative truth,
coverage, recommendation quality, calibrated confidence, legal correctness or
SME approval**. Detailed module-level coverage/contradiction rules belong later.

## SDK transport and hard stop

Pinned runtime additions: **ai 7.0.159**, **@ai-sdk/openai 4.0.106**,
**server-only 0.0.1**, compatible with existing Node 24 and Zod 4.6.7.

The installed SDK path uses `generateText` with `Output.object({schema})`, an
explicit model object (no implicit gateway model string), `maxRetries: 0`,
`maxOutputTokens: 2048` and an abort signal. OpenAI provider options use
`store: false`. Trusted instructions are kept in the system message; normalized
context and allowed IDs are serialized as JSON in the user prompt and identified
as untrusted data. This is prompt hygiene, not a guarantee against prompt injection.
No payload/response/error logging or telemetry integration is added.

The OpenAI Responses factory reads only `OPENAI_API_KEY`, `AIVRA_PAID_MODEL_ID`
and `AIVRA_AI_ENABLED` from server environment when explicitly called. No model
ID is hardcoded or considered approved. Blank/default flag produces
`ai_not_enabled`. Enabled-but-missing configuration produces `invalid_input`.
Even enabled with valid-shaped configuration produces **`ai_controls_not_ready`**.
The returned transport refuses direct dispatch too. Its underlying provider has
an unconditional blocking fetch implementation as an independent hard stop.
Factory construction performs no network I/O. An environment flag alone cannot
enable the configured live path. `.env.example` contains blank variable names
and comments only; no credentials are needed for build/tests.

## Result and error envelopes

Success is `{ok:true,result:ResultEnvelope<T>}`. The full envelope is strictly
runtime-validated and includes:

| Field | Source/meaning |
| --- | --- |
| `module`, `prompt_version` | Validated server request identity |
| `request_id` | New server UUID per invocation, including failures |
| `input_digest` | SHA-256 of normalized request and reference policy; no raw payload |
| `model_provider`, `model_id` | Validated server transport identity, not model-generated claims |
| `mode` | `paid` metadata only in U00.06; fallback mode is not implemented |
| `generated_at` | Server UTC timestamp |
| `usage_estimate` | Nonnegative integer `input_tokens`, `output_tokens`, `total_tokens` when supplied by the transport/SDK; otherwise null. `cost_usd` is always null pending U00.07 |
| `warnings` | Only bounded safe codes: `ai_generated_draft`, `references_not_narrative_verification` |
| `data` | Caller-schema-validated output, with independently checked structured references |

The normalized input is copied before transport dispatch so an injected driver
cannot mutate the authoritative allowlist used for reference validation.
Hashing is provenance, not encryption or tamper-proof evidence. No generated
result is an approved decision. The adapter does not persist results into the
session or log source/prompt/completion data.

Failures are strictly `{ok:false,error:{code,request_id,message}}`; messages are
fixed server-owned text, never raw provider errors, headers, keys or source IDs.
Codes: `invalid_input`, `invalid_model_output`, `provider_unavailable`,
`request_too_large`, `unexpected_error`, `ai_not_enabled`, `ai_controls_not_ready`.
Timeout is `provider_unavailable`; the default is 10 seconds, with a bounded
server-only override of 1–15,000ms. The adapter returns even if an injected
transport ignores abort, and real transports must honor the signal. SDK invalid
structured-output errors map to `invalid_model_output`. No retries, repair calls
or business fallback results are generated.

## Handoffs before any live public use

U00.07 must implement atomic budget reservation/settlement, anonymous rate and
concurrency authorization, payload/token bounds and fail-closed controls before
deliberately replacing the OpenAI factory's pre-dispatch **and** fetch hard stops.
It must validate ADR-012 model eligibility, independent fallback credential/quota
paths, operator controls and cost semantics. These protections are not implemented
by this unit, and `.env` settings cannot substitute for them. There is no public
API endpoint or server action to enable accidentally.

U02.01 and other module units must supply real schemas/prompts, structured ID
extractors, coverage checks and appropriate dependency snapshots. Use U00.05 to
capture source versions before asynchronous work; record metadata only after a
valid output, preserving stale status if inputs changed. This adapter does not
decide recommendations, write session results or implement user approval.

Validation: `npm run check:ai-adapter` uses `node --conditions=react-server` for
the marker's legitimate server condition and injects offline transports/models.
Normal imports without the server condition fail. No fixture/session/browser
regression suites or live calls are needed for this isolated server foundation.

SDK references: [structured output](https://ai-sdk.dev/docs/ai-sdk-core/generating-structured-data),
[OpenAI provider](https://ai-sdk.dev/providers/ai-sdk-providers/openai), confirmed
against the installed package declarations/source during implementation.
