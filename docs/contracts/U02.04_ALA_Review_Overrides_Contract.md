## Identity and ephemeral lifecycle

Client-safe `lib/ala/review-overrides.ts` defines an immutable bounded overlay:

```ts
type ReviewDraft = {
  result_identity: { request_id: string; input_digest: string;
    prompt_version: 'ala/v1'; source_revision: number };
  overrides: readonly {
    finding_id: string; action_id: string;
    subject: { app_id: string; side: 'buyer' | 'target' };
    proposed_disposition: 'Retain' | 'Retire' | 'Migrate' | 'Integrate' | 'Needs Review';
    proposed_destination: { app_id: string; side: 'buyer' | 'target' } | null;
    visitor_reason: string;
    origin: 'visitor_override';
  }[]; // <=200, unique (finding_id, action_id)
};
```

Identity is selected exactly from trusted projection provenance/source revision;
there is no reviewer identity, timestamp, approval record or copied LLM answer in
the overlay. The original action is resolved from the immutable result on every read.
Application/finding/action IDs and original subject cannot be edited.

The projection does not expose the source session token. Its existing server-only
boundary checks session/digest freshness and yields outdated/invalid on source
change/reset; this unit does not alter that frozen contract or invent a client token.
Future protected delivery must continue to supply freshly validated view states.

A result-identity React key owns saved overlays and each row's unsaved editor state.
Identity changes synchronously remount the owner; absent/invalid/outdated unmount it.
Unmount/navigation/refresh discard all drafts. Same-identity rerenders, including a
license-only change projected against the same captured result, retain the draft.
Independent keyed row editors preserve unsaved fields when another row saves or
restores. A synchronous latest-draft ref prevents rapid independent saves losing
updates. Nothing is written to shared session/schema/metadata, browser storage,
backend, files or database. No promise of durable saving.

## Validation and operations

All overlay/edit/reference objects are strict existing-Zod schemas, with no coercion,
trimming, extra fields or guessed IDs. Finding/action IDs use the existing <=64
identity syntax; app references use <=128 no-whitespace IDs and exact side. Request
UUID, 64-hex input digest, ala/v1 and nonnegative revision must match the result.
Every existing override is revalidated before save, restore or effective enumeration.
Malformed/stale/duplicate/foreign payloads fail with bounded fixed messages, never
raw exception text. Overlay origin can only be visitor_override, never AI content.

- Retain, Retire, Needs Review require null destination.
- Migrate/Integrate require another exact member of the same finding on its real
  side. No self-target, foreign/unevaluated/missing record or inferred candidate.
- Changed action/destination requires a nonblank reason, <=400 characters. Whitespace
  is tested for nonblankness but original visitor text is retained and escaped.
- Same-subject effective groups retain frozen ala/v1 structural rules: no duplicate
  subject/disposition/destination; Retire/Migrate/Needs Review cannot coexist with
  another action; Retain + Integrate and distinct Integrate targets are allowed.
  This validates visitor input; it never selects recommendations or rewrites peers.
- Restoring an original action also checks the whole effective group. If restoration
  would duplicate/conflict with another visitor override, it is rejected until the
  visitor explicitly changes/restores that peer. No silent deletion or rewriting.

`createReviewDraft`, `reviewIdentity` and `reviewResultKey` construct local identity.
`saveReviewOverride` returns validated new draft/changed flag or safe field errors.
Re-saving identical values **including reason** is a value no-op; changing only the
justification of an existing override updates that commentary. An action identical
to original removes its overlay, even if a nonblank comment was supplied: reason-only
annotations are not stored or mislabeled as a change. Bounds still apply to input.
`restoreAIRecommendation` removes only the named override after identity/conflict
validation; restoring an already original action is a no-op. `reviewDraftForView`
explicitly resets stale/mismatched drafts, returning null for non-displayable states.

`effectiveReviewActions` returns only a derived, read-only original/effective display
comparison, with explicit ai_suggestion/visitor_override origin and visitor reason.
It is not a trusted AI envelope, approval, exported artifact or downstream publication.
Invalid overlay yields no effective rows. Coverage stays unchanged/incomplete.

## UI and accessibility

Original AI suggestion, rationale and destination remain beside Visitor override —
not approved / Visitor-changed draft and visitor justification. Unchanged actions say
AI suggestion — not changed. Counts distinguish original actions and visitor overlays,
not approvals. Only action rows are editable; unassessed records retain coverage alerts.
No relationship/domain/rationale/evidence/provenance/source/identity editing.

Native labeled Edit suggestion, disposition select, explicit destination select,
justification textarea, Save override, Cancel and Restore AI suggestion are keyboard
operable. Labels/fieldset legend identify finding/action; generated DOM IDs associate
fields, hints and safe errors. Successful edits use a polite live region. Save/Cancel
return focus to that row's Edit button; Restore also returns focus there. Cancel
closes only the unsaved editor and leaves saved overlays unchanged. Other row forms
remain mounted. No review operation calls an API.

Editor starts with the exact effective values; changing disposition clears destination
so a newly required target is explicitly selected. No first-candidate auto-selection,
matching, scoring, cost rule or model hint picks a target. All text uses React escaping.
Scoped A1 CSS provides wrapping, stacked comparisons, native focus rings and contained
controls while retaining the existing read-only table's local horizontal scroll.
The public page retains one primary Analyze action; review buttons are secondary.
