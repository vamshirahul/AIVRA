# U11.01 — Immutable baseline and one alternative

Status: in review. Approved G2 **Clone baseline and create one editable alternative
scenario**; dependencies **U03.02 U02.04**; **REQ-100/101**; acceptance **Baseline
unchanged while alternate modifies selected assumptions and dispositions**.
U11.01 implements cloning/editing only. U11.02 owns calculated metrics/differences,
and U11.03 owns rich provenance/stale presentation and scenario exports. REQ-101's
full comparative-calculation requirement is not completed here.

## Protected source and public truth

The real `/scenario-modeling` mounts `ScenarioWorkspace` without source/currentness.
It shows No validated reviewed ALA/CSE baseline available, two prerequisite links,
and the bounded future-comparison note. No fake Clone, populated scenario, model
result, comparative KPI or download. Public ALA remains 503/no-store and live models
remain disabled. No new endpoint, data importer or JSON-to-trust operation.

The narrow in-memory **ScenarioSource** requires:

- `context`: original trusted CSEContext from existing server composition;
- `view`: matching original trusted ALAResultsView from existing projection;
- `financial_draft`: the actual current, validated U03.02 raw EstimateDraft.

Requiring the original projection lets existing ALA review validators run without
casting an imported/exported analysis into a trusted view. `buildReviewedExport`
must reproduce context.reviewed exactly. That representation is internal validation,
not a download or inference authentication. The existing `buildEstimateRequest`
validates the whole CSE draft, identities, notes, amounts and horizon. Missing
components remain explicit null; no previously calculated result is required and
no source cost or label supplies an amount.

A future protected result owner must provide these actual current inputs and
`current=true`, revoking/updating on source/review/financial changes. There is no
approved live result owner or cross-route CSE draft transfer today. This unit does
not add storage or a public fixture to fill that gap. Schemas, types, digest equality
and a current flag do not prove a model was invoked.

## Versioned dictionary and immutability

Client-safe `lib/scenario-modeling/scenario-draft.ts` defines strict bounded
**scenario/draft/v1**; unknown fields/versions and additional alternatives fail.

| Field | Meaning |
| --- | --- |
| contract_version | scenario/draft/v1 |
| status | provisional_unapproved |
| source_binding.source | Exact CSE session/fixture/dataset/currency, app/license revisions and ordered source digest |
| source_binding.fixture_schema_version | Existing DEMO_SCHEMA_VERSION (1.0.0), no new schema/version |
| source_binding.review_identity / review_digest | Exact original ALA request/input/prompt/source identity and existing CSE review digest |
| baseline.actions | Detached original/effective reviewed actions, origins and existing visitor reasons |
| baseline.financial_draft | Detached exact U03.02 raw strings/notes/inclusion/horizon |
| baseline.financial_request | Existing strict cse/calculation/v1 canonical request, exact cents/units/source roots/attribution |
| alternative.action_edits | At most 200 scenario-only changed action hypotheses; empty initially means baseline effective values |
| alternative.financial_draft / financial_request | One separate raw/canonical financial copy, initially equal to baseline |

Each action edit has exact finding_id/action_id/subject app_id and side,
disposition, nullable destination, and scenario_reason <=400 characters. It is a
scenario hypothesis, never an AI recommendation or published ALA visitor override.
Baseline visitor reasons and original model rationale remain separate. Full original
findings/evidence/uncertainty/provenance/coverage remain available in the protected
source context; they are not rewritten or redundantly copied into a new AI result.

Cloning is explicit. All nested collections are detached from source and from the
other scenario layer, including references preserved by structuredClone within one
object graph. Returned snapshots are recursively frozen. Pure updates return new
validated frozen objects; rejected edits leave every existing valid object untouched.
Clone with an existing valid scenario returns the same values, never a second
alternative. There is no scenarios array, named saved scenario list or CRUD store.

Existing derived cap **1,500,000 UTF-8 bytes**, <=200 financial/action rows and source
caps apply through parseCSE/current contracts. No truncation or raised model limit.
Financial raw strings are <=32 characters, notes <=400 and horizon <=3 characters.

## Pure operations and validation

- `cloneBaseline(source,existing?)`: validate source/review/raw request, detach and
  freeze baseline plus one initial alternative; fail safely on invalid source.
- `validateCurrentScenario(source,value)`: strict shape plus exact source-binding
  and rebuilt baseline equality, canonical alternative financial equality and all
  scenario action/reference/structural validation. Shape parsing alone is insufficient.
- `editAlternativeAction`: only exact current action references; all five existing
  dispositions, explicit valid same-finding destination for Migrate/Integrate, null
  for other actions; nonblank reason for a change from the reviewed baseline.
- `restoreAlternativeAction`: remove that hypothesis and recover exact baseline
  disposition/destination/reason; validate the whole resulting action set first.
- `editAlternativeFinancialInput` / `restoreAlternativeFinancialInput`: atomically
  validate/save/restore one complete raw line; retain exact original ownership and
  action/attribution IDs and baseline review binding.
- `editAlternativeHorizon`: save whole years 1..30 or explicit blank/unknown.
- `resetAlternative`: restore all alternative values to baseline, not a new source.
- `scenarioChanges`: derive changed action/financial identities and horizon flag;
  no redundant editable change register or monetary delta.

Action validation composes a disposable review overlay against the original trusted
projection, starting with the original visitor overrides. Existing validateReviewDraft
and saveReviewOverride enforce membership, required/forbidden destination, reasons,
duplicate signatures and same-subject coexistence. No ALA rule is reimplemented,
weakened or used to pick advice. A hypothesis returning to original AI advice may
remove a baseline visitor override only in that disposable validation representation;
the original review and scenario justification remain intact and separate.
Conflicting restore fails; no peer deletion, winner, splitting or repair.

Money validation reuses buildEstimateRequest/parseCADInput unchanged: decimal strings
to exact CAD cents via BigInt, no floating multiplication/rounding/default zero.
Known zero needs a nonblank basis, blank stays unknown, precision/sign/exponent/
comma/overflow and missing notes reject. Excluded row edits stay excluded unless
explicitly changed. Exact currencies/units, attribution, subject ownership and
reference fields are rebuilt from source, never visitor-editable. Overlapping spend
is preserved; no financial conflict resolution or calculation occurs in this unit.

## UI, lifecycle and freshness

`ScenarioWorkspace` subscribes to the existing shared provider. It uses the exact
existing CSE session/dependency stamp and source digest verification. Its source
key includes the full trusted context and current raw CSE assumptions. App/license
edit, publication, source reordering, fixture/session reset, review/new result or
financial baseline change synchronously unmounts the scenario before asynchronous
verification can admit a new source. Pending callbacks cannot resurrect old state;
digest failure fails closed. TSA-only changes retain the key and draft.

The protected `ScenarioEditor` offers one Clone baseline primary action, an immutable
read-only baseline disclosure and exactly one alternative with native per-action
disclosures, action and financial forms, explicit Save/Restore and horizon/reset.
Original AI, existing reviewed visitor override and scenario hypothesis are labeled
separately. Last valid state is unchanged on failed Save. Unsaved forms are local;
unrelated row saves do not reset them. A synchronous latest-snapshot ref prevents
rapid independent updates losing each other. Focus returns to the stable row summary
or alternative heading after successful save/restore/reset. Native labels, fieldsets,
legends, error associations/alerts and A1 scoped responsive styles support keyboard
use and 320/390/1440 layouts. No automated AI call or hidden action.

Refresh, navigation and unmount discard everything. No storage key, session schema,
derived-result metadata, event publication, database or persistent estimate change.

## U11.02 consumption boundary and remaining work

After validateCurrentScenario, a future consumer can read baseline financial_request,
alternative financial_request, exact source/review identity and separate action_edits.
Both requests intentionally retain the **original baseline CSE review identity/digest**:
this unit never invents an alternative digest or claims hypotheses are the original
reviewed ALA result. Financial assumptions are valid v1 shapes, not calculated metrics.

Today's calculateCSE validates action references against a trusted reviewed context;
it does not consume a separate scenario hypothesis/review identity. U11.02 must
explicitly compose/validate a distinct alternative interpretation within its approved
boundary, keeping the original baseline/review intact, before claiming comparison
semantics. It must not forge a current context/digest or import a CSE export as
trusted source. No core contract modification or comparative engine is preapproved
or implemented here. U11.03 presentation/export remains deferred.
