# U05.04 — Selected provisional license-to-CSE handoff

Version **licenses/cse-handoff/v1**, in review. Executes Revision 2, superseding
the gated Revision 1. Exact G2 objective: expose selected license cost impacts to
CSE without double counting; prerequisites U05.03/U03.01; REQ-073/032, with REQ-072
selection semantics. Acceptance: **Missing monetary data not invented; overlapping
savings not added twice.** This is separate advisory evidence for a future CSE
workflow, not enabled license aggregation or public integration.

## Trust flow and public reality

`buildLicenseCSEHandoff(outcome,captured,current,review,comparison?)` is server-only.
The outcome must come from trusted composition. It calls unchanged
`projectLicenseResults`/U05.02 inspection, validates the entire current
licenses/review/v1 overlay with `validateLicenseSelectionDraft`, and resolves
source evidence only from the exact captured DemoSession. It never calls a model.
Absent/invalid/outdated results or invalid selection/comparison yield fixed errors
with no partial candidate list. Only original finding IDs explicitly selected
become candidates, in original model order. Not-selected and unreviewed findings
have no candidate. Clear/remount lifecycle stays owned by the existing review UI.

`readLicenseCSEHandoff` is a client-safe **structural reader only**. It validates
shape, selected membership, represented joins/evidence/coverage consistency,
precision, ownership assessment and withholding flags. Hashes, schema validity
and type assertions cannot authenticate a model execution or captured source side/
amount. No HTTP/file/browser-state import path is provided.

`validateCurrentLicenseCSEHandoff(input,outcome,captured,current,review,comparison?)`
is the server consumption gate: revalidate the body, check the actual current
source token, rebuild from current trusted result/review/comparison, and compare
the whole handoff. Source edits/reset/reorder return outdated; replayed result,
changed selections or changed comparison cannot pass as current. An old object
cannot observe browser changes by itself; future owners must supply fresh shared
session/review/context snapshots at consumption. This is not result authentication
if the caller itself violates the trusted-outcome composition boundary.

The public inventory/CSE introduction, original AI-disabled notices, ALA503/no-store
and all provider/budget hard stops remain unchanged. No handoff is wired into a
page, endpoint, persistent store, download or actual financial aggregate.

## Exact dictionary and separation

All objects are strict; outputs are detached, recursively immutable, and bounded
to the existing derived CSE cap of **1,500,000 UTF-8 bytes**. No truncation, source
repair, default money, horizon or hidden charge. Source/model bounds are unchanged.

| Field | Meaning |
| --- | --- |
| contract_version / target_contract | licenses/cse-handoff/v1 / cse/calculation/v1; this object is neither CSERequest nor CSEResult |
| source_module / status | licenses / provisional_unapproved; never approved, executed or contractual |
| source_token / currency | Original session UUID, fixture ID/dataset version, app+license revisions, ordered source digest; CAD |
| result_identity | Exact licenses/v1 request UUID/input digest/prompt/source token from the validated original result |
| review_snapshot | Entire validated licenses/review/v1 overlay, including not-selected entries, separate from original AI; no approval timestamp |
| provenance | Original full envelope metadata: module/provider/model/paid-or-fallback/routing reason, generation time, prompt/request/input hash, nullable usage and warnings |
| coverage / not_evaluated | Original complete/incomplete status, reasons/counts/missing/skipped/all-result overlap IDs, plus exact skipped reasons; not inferred from selected subset |
| selection_state | selected_opportunities or no_selected_opportunities; empty selection is not a verified zero-benefit portfolio |
| financial_aggregation | Literal withheld; no savings, assumed impact, net-benefit or aggregate amount field |
| candidates | At most100 original selected findings, preserving model order |
| comparison | Null means CSE ownership comparison was not supplied, not that the whole portfolio is conflict-free; otherwise separate current CSE source/review binding and included ALA claims |
| ownership_conflicts | Exact unchanged inspectCostClaims output with internal claim IDs, reason and attribution/application root |
| selected_license_overlap | Exact shared license IDs and selected original finding IDs, separate from original all-result overlap coverage |

Each candidate contains:

| Field | Meaning |
| --- | --- |
| original | Complete unchanged licenses/v1 finding: ID/category/license+app IDs/suggested_action/rationale/evidence/unknowns/assumptions/uncertainty/review_required |
| selection | Exact separate {finding_id,status:selected,origin:visitor_selection} record |
| claim | Existing CSE CostClaim shape: internal line_id, explicit attribution_key, source_kind:license and spend_app_ids equal to original app IDs |
| ownership | Exact license_id -> app_id mapping in original license-ID order, retaining repeated IDs across distinct findings |
| licenses | Actual captured selected LicensePosition records, preserving nullable values, quantities/vendor/product/notes and absent/null renewal; plus annual_spend evidence conversion |
| applications | Only linked app ID, captured Buyer/Target side/name and annual_cost evidence; no unrelated raw session/context |
| source_evidence | Original pointers resolved to exact license attribute values and their linked app IDs; absent attributes are not fabricated |
| financial_eligibility / withholding_reasons | Deterministic withholding disclosures below, never a recommendation or financial authorization |

Result and review identities must match exactly. Duplicate candidates/selections,
unknown finding references, duplicate pointers/source IDs within a finding, wrong
joins, altered raw cost/evidence, or mismatched original/reference arrays fail
validation. Repeated licenses across distinct findings remain valid and visible.
Selected original reference totals retain licenses/v1's max400 license memberships,
max400 app memberships, max400 evidence pointers, max200 unique licenses/max100
unique applications. Coverage stays original; the structural reader cannot prove
the unrepresented unselected source inventory without the server snapshots.

## Source money is evidence, never savings

Both license annual_spend and app annual_cost use `{major_units,minor_units,state}`.
Original major-unit number/null is retained. The **existing** `sourceCostMinor`
converts exactly representable, bounded two-decimal CAD amounts to integer cents.
Zero -> 0/known; null -> null/unknown; excessive fractional precision, scientific
notation or unsupported magnitude -> null/unsupported_precision. This state also
covers the CSE monetary range bound. No Math.round, FX or epsilon adjustment.
An omitted required annual amount invalidates the source contract; optional renewal
absence stays absent. There is no guessed spend or zero repair.

Annual license spend is already inside the linked app annual cost. They are not
added as separate baselines, savings or estimates. Entitled/used seats, vendor,
product, renewal date and model narrative never generate money or benefit ratios.

Withholding flags are fixed and recomputed structurally:

1. `withheld_overlap` when selected licenses repeat or a claim participates in a
   shared root/attribution conflict. It has primary precedence.
2. `withheld_unknown_amount` when any represented license/app cost is unknown or
   unsupported precision/range. Next primary precedence.
3. `withheld_no_supported_assumption` is always retained: this unit provides no
   approved supported financial savings assumption.
4. `withheld_cse_license_source_unsupported` is always retained and is primary when
   no overlap/unknown flag applies. Current CSE v1 explicitly withholds licenses.

Known source costs, including zero, do not change these last two flags. No numeric
aggregate is emitted for empty selection, unknown evidence or known evidence.

## Existing CSE compatibility and ownership comparison

| Existing CSE contract | This unit's behavior |
| --- | --- |
| cse/calculation/v1 formulas, CAD units, bounds | Completely unchanged; no new financial model |
| ALA-specific CSEContext/review identity | Kept separate; never used to validate license visitor selection |
| CostClaimSchema/inspectCostClaims | Reused for whole-application spend-root assessment only |
| source_kind:license -> unsupported_license_source | Remains enforced by unchanged calculateCSE, even if money is supplied |
| Explicit financial inclusion | No license financial line auto-created or inserted into a CSERequest |
| Unknowns and conflict withholding | Retained; no automatic winner, cap, split, allocation or silent omission |

Optional comparison input is exactly `{context:CSEContext,request:CSERequest}` from
trusted current server composition. Existing schemas/calculator validate the pair,
`matchesCSESource` checks actual current session, and source identity must equal
the license token plus CAD. Only included **ALA** lines are copied as structural
claims; reserved-license lines in a supplied comparison are rejected. Invalid or
unavailable CSE review context cannot masquerade as license selection authority.
Calculation may be incomplete/not-computable: included potential ownership claims
still matter conservatively even if financial amounts are unknown. No CSE numeric
amounts, unrelated ALA analysis or whole context is copied into the handoff.

License claim attribution key is `license/<request_id>/<finding_id>`. Internal
claim IDs are l_ or c_ plus48 hex characters of SHA-256 over original request/finding
identity or CSE review digest/source line ID. They are assessment aliases, not
rewritten source IDs or authentication. Original finding/source_line_id mappings
remain explicit. Aliases are stable under finding reordering; a collision/duplicate
fails closed through the existing guard. External attribution keys are unchanged.

Combined selected-license plus included-CSE claims must fit the unchanged
**200-claim /100-app-root** guard. Exceeding it rejects the handoff; no truncation
or raised limits. Two distinct licenses on one app conflict under whole-spend
ownership, even if a future policy might allocate them differently. Shared license
membership and same-app ownership are reported separately. CSE-only conflicts
can also be present in a supplied comparison; they are not license suggestions.

## Freshness, errors and future decisions

App/license edit, publication, ordered source change and reset invalidate the
original license token, including unversioned data changes. TSA-only changes stay
current against the original captured snapshot. New AI response/review/comparison
must be resupplied; the current-consumption gate rejects old handoffs. No new state
store, session revision, derived result or persistent approval is created.

Errors use fixed safe text and one of: no_analysis, invalid_source, outdated,
invalid_selection, invalid_comparison, ownership_limit_exceeded, handoff_too_large,
invalid_handoff. No provider/model/source payload leakage, guessed identity,
partial candidate list, automatic retry or model repair request.

Example **fabricated test evidence only**: a selected license with annual_spend0
and app annual_cost100.25 carries license0 cents and app10025 cents separately,
with financial aggregation withheld. Two selected findings citing that license
retain both original findings and report a shared root; no savings sum is produced.
These examples are not public inference results.

Trusted public populated-result delivery and U03.02 UI, live model/store/budget/
