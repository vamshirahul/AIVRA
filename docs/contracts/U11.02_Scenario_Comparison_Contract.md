## Arithmetic, units and comparability

Baseline and alternative retain original CSE equations A, M, T, O=M+T, H=A×years,
N=H−O, exact cents, bounds, missing-data and whole-application ownership rules.
Only new arithmetic is **difference = alternative − baseline**, using BigInt and
checked bounds before exact Number conversion. No floating money conversion/rounding.

Six metrics: annual recurring savings (cents/year), migration and transition costs
(cents once), total one-time cost (cents once), recurring savings and net benefit
over the explicit horizon. Each original CSE total remains bounded by MAX_MINOR;
net is signed. Two legitimate signed outcomes can differ by **2×MAX_MINOR cents**,
so the difference bound is ±2,000,000,000,000 cents, safely exact. This mathematical
subtraction range does not raise any CSE input, aggregate or financial assumption cap.

If either amount is null, the difference is null/unknown_amount; never coerce it to
zero. Known matching amounts give exact zero, including explicit zero assumptions.
When horizons differ or are unknown, period savings/net differences are withheld;
supported annual and once-only costs may still be compared in their own units.
Each side's actual horizon and original known figures remain visible with an explicit
not-like-for-like warning. No annualization, forecast/discount/tax/FX or cost allocation.

If either calculator result is invalid, compareScenarios returns a fixed safe error
with no comparison. If either is not_computable, overall status is not_computable;
known figures on the other side are preserved only as its original supported values,
and differences remain unknown. Incomplete source coverage/components or incompatible
horizons produce incomplete status. Status computed means supported comparable explicit
assumptions, not verified/complete business impact of a changed disposition.

Original warnings/conflict groups/unknown line reasons remain inside each result
and are shown. No winner, split, silent material omission or duplicate benefit.
Numeric license contributions remain withheld; advisory license findings are not
inserted into either request. Scenario validation rejects forged license/source rows.

## UI and transient lifecycle

Existing protected ScenarioEditor offers Compare scenarios after Clone. The comparison
table names Baseline / Alternative — hypothetical / Alternative minus baseline, shows
all six supported values, explicit signs and CAD units, both horizons, status/coverage
and missing-data warnings. Positive costs are larger costs; no positivity color score.
Disposition hypotheses and explicit financial assumption differences are separate.
Unadjusted action hypotheses explicitly say their financial effect has not been modeled.

Every raw form edit immediately hides the comparison and marks that form unsaved.
Compare is disabled until all dirty forms are saved or restored. Even restoring the
same input text does not clear the save/restore latch. Failed Save leaves valid scenario
unchanged and comparison unavailable. Successful Save/Restore invalidates comparison;
only deliberate Compare recalculates. Per-form remount versions reset restored fields
without discarding other unsaved forms; reset-all also discards unsaved local controls.
This narrow UI lifecycle change leaves scenario/draft/v1 operations/semantics unchanged.
Baseline/source changes unmount all scenario/comparison state before new verification;
TSA-only changes retain it. Refresh/navigation discard memory; no new storage key.

Native table caption/row/column headers, labeled controls, live status and errors,
focus restoration and scoped A1 responsive rows support keyboard/mobile/desktop use.
No charts, scenario list, export button or rich lineage explorer.
