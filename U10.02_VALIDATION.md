## Implementation and shared changes

Explicit createAssistantAskOwner.ask uses only the existing createAIRouter; one
await of its full reservation/provider/settlement pipeline, with current issued
source validation before/after and before committing/releasing the answer. Each
question rebuilds current U10.01 context. Imported/cloned context/history/handles
cannot gain owner authority. Context changes permanently revoke conversations and
answers; accounted work is not refunded or automatically rerun. All history lives
in per-owner weakly held memory, frozen and session/context-bound. No source writes.

Strict context.assistant carries structured source context, question and history;
no user_text packing. Typed module/prompt/system/deal/history bindings are validated
before dispatch. The adapter verifies real namespaced citations against the typed
catalog, exact extractor parity and answer/missing-context structure. No fabricated
flat IDs or permissive empty extraction. Only insufficient-evidence answers may
have no citations. Complete original model envelope/provenance is validated again
at the owner, independently from model-authored data and source freshness.

Essential shared data-only extraction breaks the otherwise unavoidable cycle:
AI invocation -> AssistantContextSchema -> upstream outcome/orchestrator -> router/
adapter -> AI invocation. Existing public exports remain at old paths; no business
schema fields/constraints are changed. Source-body comparison against synchronized
HEAD verified five extracted source-token/outcome definition blocks exactly
unchanged: ALA source/outcome, license source/outcome, Playbook outcome. Business
schema imports switch to independent base contracts. Base constants/error/envelope/
transport types preserve old values/messages; metadata prompt-version schema has
the same regex/bounds. Existing shared and downstream regression suites verify it.

| Larger valid context | Actual100-app Unicode domain context can capture but full duplicated invocation exceeds128KB; refused before reservation with no truncation or omitted sources |

At four turns next Ask fails before dispatch; an explicit new conversation is
required. Appending an otherwise valid large Unicode answer that exceeds the byte
cap withholds the whole answer/append and preserves prior current history, while
accounting remains intact. Source/Reset changes hide/revoke current history and old
issued answers. Mutable caller question is not reread into history after dispatch.
History/response text stays untrusted JSON, never system roles or source evidence.
