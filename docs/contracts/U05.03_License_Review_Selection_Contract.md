## Trusted presentation boundary

`projectLicenseResults(outcome, capturedSession, currentSession)` is **server-only**.
It calls the existing `inspectLicenseOutcome` from U05.02, unchanged. Missing outcome
returns absent. Invalid metadata/schema/coverage/version/digest/source returns
invalid; changed relevant source returns outdated. These states have no data rows
or selection controls. Valid complete/incomplete results retain their status.

The server grants the compile-time trusted projection brand only after inspection.
This is not authentication, a signature or proof of model execution. Future callers
must obtain genuine results from a protected trusted server composition. No client
JSON import, storage value, header/query/environment toggle, route or test bypass
is supplied. No public successful-result delivery exists today.

The recursively frozen client-safe `LicenseResultsData` contains:

| Field | Meaning |
| --- | --- |
| `provenance` | Original ResultEnvelope metadata, unchanged: module, request ID, input digest, provider/model, paid/fallback and routing reason, prompt version, generated time, nullable usage and warnings |
| `source_token` | Original session UUID, fixture/version, application/license revisions and ordered source digest |
| `currency` | Captured deal currency; no conversion or arithmetic |
| `coverage` | Original revalidated structural status, reasons, source/accounted counts, missing/not-evaluated/overlapping IDs |
| `findings[].original` | Every original licenses/v1 finding field in model-authored order, including original pointers, unknowns, assumptions, uncertainty and review_required |
| `findings[].applications` | Exact app ID, captured source name and Buyer/Target side for each original app reference |
| `findings[].source_evidence` | Original license/attribute pointer plus its exact linked app ID and actual captured source value |
| `not_evaluated` | Exact original source license IDs and model-authored reasons |

No whole session, provider prompt/context, unrelated source records, budget or
credentials are projected. App side/name is joined by exact opaque app ID, not
vendor/name heuristics. License vendor and app vendor are never substituted. Null
renders Unknown; zero renders 0. Absent renewal is never fabricated or cited as a
supplied value. All strings are escaped native React text, never HTML/Markdown.

Existing 128,000-byte input, 64,000-byte model output/envelope, source limits and
2,048-token cap remain unchanged. A new **512,000 UTF-8 byte projection ceiling**
bounds repeated resolved evidence/app names; overflow returns invalid without
dropping or truncating original findings. This does not increase inference limits.

## Visitor overlay contract — licenses/review/v1

Pure client-safe helpers operate only against a current/incomplete trusted view.
All overlay objects are strict Zod shapes, bounded and immutable:

```text
draft = {
  schema_version: "licenses/review/v1",
  result_identity: {
    request_id: UUID, input_digest: SHA256, prompt_version: "licenses/v1",
    source_token: {session_id, fixture_id, fixture_dataset_version,
                   application_revision, license_revision, source_digest}
  },
  selections: [{finding_id, status: "selected" | "not_selected",
                origin: "visitor_selection"}]
}
```

At most 100 unique selections, matching licenses/v1's finding bound. Finding IDs
retain the original 1–64 character letter/digit/underscore/hyphen contract. Identity
uses exact validated request/source fields; source IDs are max 128, digests 64 hex,
revisions nonnegative integers, fixture dataset version semantic major.minor.patch.
Every selection must reference a real finding in that exact result. Missing and
not-evaluated source licenses cannot be turned into selectable findings.

Default **unreviewed** means no overlay record. Explicit **selected** means
“Selected for further review — unapproved.” **not_selected** means visitor choice,
not a rejection of evidence or model conclusion. Clear/restore removes that one
record and restores unreviewed. A visitor can reverse either choice. No review note
editor is offered in this bounded unit; note/approval/amount/timestamp/identity
claims or copied AI fields are rejected as unexpected properties.

`saveLicenseSelection` validates the whole existing draft and exact edit reference
before changing a single selection. `clearLicenseSelection` validates identity and
finding before removal. Same-status saves and already-unreviewed clears are no-ops.
Other findings and collection order are retained. Invalid/duplicate/foreign/stale/
oversize/extra data returns one fixed safe error and never mutates any input.
`validateLicenseSelectionDraft` returns null on failure; `licenseDraftForView`
explicitly resets an invalid/old draft to a new empty draft, or null for no result.

`licenseReviewEntries` exposes original projected finding plus a separate visitor
selection (or null), never an effective rewritten AI finding. This is a display
selector only, not a downstream publication/export or cost-impact contract.

## Overlap, uncertainty and incomplete analysis

Multiple distinct findings may legitimately share license IDs. The UI preserves
them, displays original overlap IDs, and `selectedLicenseOverlaps` identifies exact
shared license IDs/finding IDs among selected entries. This is source membership
inspection, never an optimization rule, priority score, financial sum or policy to
resolve duplicates. Both overlapping findings remain selectable. No savings amount
is computed, selected or added; selection never implies additive benefit.

Incomplete coverage remains prominently incomplete after every visitor choice.
Missing/not-evaluated IDs and original reasons remain visible; an empty result
does not establish zero opportunities. Unknowns/assumptions and qualitative
uncertainty remain original model content. No legal rights, verified entitlement,
approval, execution or guaranteed savings is implied.

## Component lifetime and source freshness

`LicenseReviewWorkspace` is an isolated client component with React state only.
A stable key uses complete request/source identity, not array position, vendor or
category. Finding order changes preserve selections by exact finding ID. New
analysis identity or no/invalid/outdated view unmounts the inner review synchronously,
discarding all choices. A fresh mount/refresh/navigation starts empty; old selections
are not cached for reuse if an old analysis later reappears. A synchronous latest
draft ref prevents rapid independent button actions from losing earlier choices.

The **owner must propagate fresh trusted views whenever shared source changes**.
U05.02 inspection compares captured/current sessions, including ordered record
digests, before projection. App/license edits, publication, reorder and reset
invalidate; irrelevant TSA-only edits stay current when compared against the
original captured snapshot. No new browser source store/hash, session schema,
sessionStorage key or derived-results write is added. The dormant component does
not observe a browser session by itself; future protected delivery must wire
shared-provider invalidation into its trusted view owner before public activation.
