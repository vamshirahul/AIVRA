## Protected composition and input preparation

All four `lib/server/playbook/` modules import `server-only`. Ordinary client-context
imports fail. No provider/router/adapter is invoked, no environment is read and no
network or storage operation occurs. No fabricated result is exported by application
code; the only fabricated outcomes are in the offline test script.

`preparePlaybookContract(PlaybookInputs)` is the bounded contract preflight. Its
inputs are trusted internal server composition: original ALA outcome, captured
session, latest current session, saved review, original financial draft, current
scenario and explicit `baseline`/`alternative` selection. There are no defaults
that silently select a scenario, approve advice, fill assumptions or generate tasks.

Preparation:

1. Validate the complete current DemoSessionSchema and unchanged 512,000-character
   session limit; reject any coercion/normalization/extra field, duplicate/dangling
   app/license/TSA identity or invalid date through existing source contracts.
2. Reuse `prepareCSEContext` and `projectALAResults`: source-bound original ALA
   validation, coverage/digest checks and existing visitor-review validation.
3. Validate the original financial draft, then call unchanged
   `validateCurrentScenario` and `compareScenarios` against that same protected
   source. No fabricated review identity, modified CSE source context or monetary rule.
4. Capture a detached immutable domain input, exact source values and explicit
   selection. Copy only the selected original CSE status/totals/warnings/conflicts;
   there is no second calculation engine or financial estimate.
5. Enforce 128,000 UTF-8 bytes for the domain input, and for the combined domain
   input + server-owned system instructions + generated output JSON schema.
   Oversize is `request_too_large`, without truncation or dropped records.

`buildPlaybookInput` is the underlying snapshot builder; future composition must
use `preparePlaybookContract` for complete schema/prompt accounting.
Safe failures expose only fixed text with `invalid_input`/`request_too_large`.

There is currently no successful trusted public AI result source. Validated shape,
hashes, TypeScript types and the existing ALA export format are not proof of actual
model execution. A browser export/file/HTTP body must never be promoted to a trusted
outcome by calling these functions. No new reader, import or endpoint is provided.

## playbook/input/v1

Strict `PlaybookInputSchema`; all nested records reuse existing typed contracts.

| Field | Meaning |
| --- | --- |
| contract_version / prompt_version | playbook/input/v1 / playbook/v1 |
| illustrative_unapproved | true; no execution or financial approval |
| source | session lifetime UUID, exact fixture versions, session revision and independent application/license/TSA revisions |
| source.deal_digest | SHA-256 of the complete current deal, including linked license source data required by existing CSE freshness |
| source.review_digest | Unchanged validated CSE reviewed-ALA digest |
| source.scenario_digest | SHA-256 of validated scenario and explicit scenario selection |
| applications | Exact current application contracts, stable IDs and Buyer/Target sides; 2–100, existing max50/side enforced by session validation |
| tsa_services | Exact current TSA source fields/links/statuses; 0–100 |
| reviewed_ala | Existing ala/review-export/v1: original AI findings/evidence/rationale/uncertainty/model provenance, saved visitor overrides and effective proposals separately |
| selected_scenario | Explicit baseline or alternative; neither is a verified integration decision |
| scenario | Unchanged scenario/draft/v1: immutable reviewed baseline, raw/normalized financial assumptions, alternative disposition/destination edits and justifications |
| financial_summary | Exact existing selected CSE CAD-cent totals/status/warnings/conflicts, not a price inferred from dispositions |
| incomplete_context | ala_incomplete and/or financial_incomplete from validated original coverage and selected calculation state |

Known relationships are supplied through original ALA findings/destinations and
TSA related_app_ids, not a new inferred dependency graph. No standalone license
recommendations, CSE approval or broader M09 dependency module is implied.
License source contents are validated/digested but not copied into model context.
Unknown/null, known zero, absent links and recorded empty links remain distinct.
No fabricated owner, date, task, saving, approval, source fact or analysis identity.

`matchesPlaybookInput(captured, latestProtectedInputs)` rebuilds and compares the
whole validated snapshot. Reset/lifetime, any source revision, unversioned source
content, review, raw assumption note, baseline/alternative edit or selection change
invalidates the capture. Session revision changes conservatively invalidate too.
No asynchronous operation occurs here. U04.02 must obtain latest protected state
and check before/after every future async boundary; a caller passing stale snapshots
cannot discover later browser changes through a pure function.

## playbook/output/v1

Strict `PlaybookResultSchema`, model-authored data only. No model/provider metadata
is accepted inside generated data. Every object is strict, text is bounded/nonblank,
no coercion/default/repair. Maximum 64,000 UTF-8 bytes at inspection, no truncation.

| Field | Meaning / bounds |
| --- | --- |
| contract_version / status | playbook/output/v1 / ai_generated_unapproved_draft |
| coverage_status | complete or incomplete; structural coverage only, not plan quality/readiness |
| phases | 0–12 local phase IDs, contiguous unique sequence1..N, title, assumptions, source_refs; no predetermined business phase names |
| actions | 0–100 local activity IDs, phase_id, title/description, nullable proposed ownership_role, depends_on_activity_ids, assumptions, uncertainty and source_refs |
| milestones | 0–40 local IDs, phase, title, nonempty after_activity_ids, nullable proposed_date/date_assumption pair, source_refs |
| risks | 0–40 local IDs, advisory description, assumptions, uncertainty and source_refs; no computed risk score |
| not_addressed | 0–400 unique explicit source references and reasons for omitted evidence |
| limitations | 0–20 bounded limitation strings |

Generated IDs are unique across phases/activities/milestones/risks, max64 characters.
Titles/roles max120; descriptions max800; assumption/reason strings max400.
Assumptions max10 per relevant row, dependencies max20 per activity/milestone,
source refs1–20 per row, aggregate source refs including not_addressed max400.
Null role means unknown/unassigned. Any nonnull ownership role is a proposed role,
not a verified source owner or task assignment. Proposed dates require an explicit
nonblank date assumption; null dates require null basis. They remain illustrative,
even if copied from a known TSA source date. Dates must be real calendar dates.

Activities reference existing phases and existing dependency activity IDs; no
self-links, duplicate links, cycles or references into later phases. Milestones
follow existing activities in the same/earlier phase. These are integrity checks,
not deterministic sequencing recommendations. Missing/empty plans are incomplete.

Source references are a strict discriminated union:

- application: exact app_id and side.
- tsa: exact tsa_id.
- ala_action: exact finding_id, action_id, subject app_id and side from the
  validated reviewed ALA. Original versus visitor versus alternative content
  remains distinguishable in the input; this reference never approves an action.

`inspectPlaybookResult(output, trustedCapturedInput)` validates all source-reference
paths in phases, actions, milestones, risks and not_addressed. Foreign IDs, wrong
types/sides and altered finding/action subjects fail as invalid_model_output.
Duplicate refs within one row or not_addressed and cited+skipped contradictions
fail. Shared citations across activities are allowed.

Coverage enumerates missing application IDs, TSA IDs and reviewed action IDs.
Any missing/skipped source, incomplete input context, or absent phase/activity/
milestone forces incomplete; a falsely complete declaration is rejected.
An entirely unaddressed but structurally valid incomplete output is not a generated
usable plan. Full coverage cannot verify narrative grounding, role plausibility,
risk truth, completeness of real integration work or calibrated confidence.

`PLAYBOOK_OUTPUT_CONTRACT` reuses the generic adapter's Zod/reference interface.
`extractPlaybookReferences` enumerates every structured root source path, including
not_addressed, and deduplicates legitimate repeated citations. Generated local
IDs never enter the source allowlist. Empty refs allow an honest incomplete result,
not complete coverage. Module-specific inspection is still mandatory after generic
adapter validation in a later unit.

`PlaybookEnvelopeSchema` reuses the common strict adapter provenance/usage envelope,
binds module=playbook and prompt_version=playbook/v1, and preserves paid/fallback
identity rules. Metadata must come from the guarded server adapter, never the LLM.
The schema alone is not an inference attestation; U04.02 owns actual input digest,
trusted envelope/source binding and before/after-await orchestration.

## Gateway boundary and later units

The domain input is intentionally **not InvocationInput**. Current generic context
allows only deal and at most 2,000 characters of user_text. It cannot carry full
review/scenario/TSA contract data. No cast, string truncation, browser payload trust,
raised limit or material shared-contract change is introduced here. U04.02 must
explicitly review a minimal structured-context integration through the existing
guarded router, preserving size/schema accounting, budget/rate/concurrency safeguards
and live-disabled hard stops. This is a later integration requirement, not an
unresolved U04.01 schema prerequisite. No endpoint exists for Playbook today.

System instructions are server-owned `PLAYBOOK_SYSTEM_PROMPT`; all names, notes,
rationales and visitor assumptions are untrusted data. No narrative is generated
locally, no pattern matches choose recommendations, no financial formula is changed.
Future rendering must escape text; this unit does not render or execute any output.

ALA/playbook specimens and fetch forbidden. It covers immutability/separation,
original CSE equality, strict source failures, source/review/scenario freshness,
all generated source paths, graph/date/identity integrity, incomplete coverage,
unknown/zero/omitted links, payload/envelope bounds and server-only/public boundaries.
