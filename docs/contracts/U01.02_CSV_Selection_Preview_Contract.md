# U01.02 — Bounded CSV selection and draft preview

Status: **in review**. REQ-011/013/061, ADR-007. This unit parses local synthetic
CSV sources only; it does not map, normalize, import, confirm, publish or analyze them.

## Intake and syntax

`lib/data-mapper/parse-csv.ts` is browser-safe and has no session, file-system,
network, provider or storage dependency. `readCSVFile` accepts a browser File's
name/size/arrayBuffer interface; mocked adapters are used only in tests.

- One `.csv` file per side; extension is case-insensitive. Empty/missing stems,
  paths and other extensions are rejected. MIME is not used for authorization:
  browsers vary, and extension plus actual text syntax/encoding are checked.
- Maximum **500,000 bytes**, decimal 500 KB, inclusive. Metadata is checked before
  any read. The returned buffer is checked again before decoding, including size
  agreement with metadata; an overlimit file is never read. No archives/base64 or
  remote URL intake exists. Empty files fail. Filename display is capped at 120
  code units with an ellipsis; no path or raw content enters error messages/logs.
- Fatal UTF-8 decoding, with optional initial BOM stripped by TextDecoder.
  Malformed UTF-8, UTF-16 BOMs and NUL-containing text are rejected. This is not
  heuristic detection of every possible legacy encoding; syntactically valid
  UTF-8 is the accepted contract. No encoding guessing or lossy replacement.
- Comma-separated fields support whole-field quoting, doubled quote escapes,
  embedded quoted commas/newlines and CRLF/LF/CR record endings. Newline content
  inside quotes is preserved. Quotes inside plain fields, unterminated quotes or
  any non-delimiter/newline after a closing quote are rejected, including spaces.
- Exactly one header record is excluded from the **50-data-record** cap. A 51st
  record fails the entire parse; nothing is truncated or published. Header-only
  files are valid previews with zero data rows. Each header must be nonblank after
  a whitespace-only check; the displayed header itself is not trimmed/renamed.
  Duplicate headers are preserved for later manual mapping, not auto-corrected.
- Only truly empty **unquoted physical lines** outside quoted fields are ignored,
  including leading/trailing/interior lines. A line containing spaces, delimiters
  or `""` is a record, even if the decoded cells are empty. Such rows cannot evade
  the 50-row cap. Quoted blank/newline content remains data. Every data record must
  have exactly the header field count; empty cells stay empty strings.

The finite parser returns the first issue and stops. File bytes bound scanning
and source string/field allocations; no unbounded issue list or error echo exists.
No extra undocumented column cap is imposed. A very wide but bounded CSV may
require extensive horizontal scrolling. No numeric coercion, domain schema,
application ID, header recognition or recommendation rule is introduced.

## Results, draft lifecycle and errors

`CSVResult` is `{ok:true,file_name,file_size_bytes,headers,rows,row_count}` or
`{ok:false,error:{code,row?}}`. No success rows accompany an error. The optional
row is **0 for the header**, otherwise a 1-based **data record** number, not a
physical line number (quoted newlines do not increment it). Safe fixed copy comes
from `CSV_ERRORS`; no thrown File error or cell content is displayed as an issue.

| Error code | Condition |
| --- | --- |
| `invalid_file` | Unsupported/missing filename extension or path-like name |
| `too_large` | Metadata or actual bytes exceed 500,000 |
| `empty_file` | Zero bytes |
| `read_failed` | Unreadable File or metadata/buffer-size disagreement |
| `invalid_utf8` | Fatal decoding failure or NUL text |
| `missing_header` | No header or a blank header cell |
| `malformed_quotes` | Invalid quote placement/closure |
| `wrong_width` | Data record field count differs from the header |
| `too_many_rows` | A 51st data record |

`CSVDraft` has UI-owned `side`, generation and `status` of `not_selected`,
`reading`, `ready` or `error`, with a preview/error only in the corresponding
state. `csvDraftReducer` is a pure immutable transition helper; it is not a new
global store. The two drafts live in `CSVPreview` React state. The active side
comes from existing inventory tabs, never from file names or contents.

A selection starts a new generation and replaces only that side. Completion is
accepted only for the matching currently-reading generation. Clear advances the
generation; older read completions cannot restore a cleared/replaced draft. Picker
cancellation leaves the draft intact. Native input value is cleared after change
so selecting the same file again works; the filename metadata identifies the
retained draft. Unmount suppresses async dispatch; a later mount starts fresh.
File reads cannot be canceled mid-read by arrayBuffer, but are bounded and ignored
when obsolete. Parsing itself is synchronous and bounded after the read completes.

No draft, filename or bytes go to sessionStorage/localStorage, cookies, IndexedDB,
server memory/endpoints, logs, telemetry or external services. Side switching,
reading, parsing, errors and clearing do not mutate shared source values, revisions,
metadata, dataset version or reset semantics. Global Reset still resets only the
shared session; an uncommitted draft remains separate until clear/unmount. Leaving
the module/remounting or refreshing discards drafts; they never become confirmed.

## Presentation and handoff

The original sample inventory stays visible in the existing active-side panel and
is labeled **Sample inventory (current shared session)**. Below it, the matching
native **Choose Buyer CSV** / **Choose Target CSV** control and draft preview are
separately labeled **Selected CSV preview (not yet imported)**. Both controls carry
the required synthetic/test-only, no-confidential-information and browser-only
privacy disclosure. Reading uses a polite status only during real pending work;
side-specific failure is one alert; no partial-success claim is made.

Ready previews show side, bounded filename, byte size, parsed count and all raw
headers/rows in original order. Caption/column scopes and a named focusable scroll
region keep the table accessible and contained on narrow screens. React escapes
all headers/cells/filenames; formulas are plain text, never evaluated/exported.
Existing A1 tokens/focus styles are reused. No disabled fake Map/Confirm action.

Boundary copy explicitly defers column mapping, field validation and Confirm to
U01.03 and normalized publication/source version changes to U01.04. Any future
handoff must be separately approved; this unit does not change session/domain
schemas, server routes or AI infrastructure.

`npm run check:csv-preview` is included once in `check:ci`. Unit tests cover exact
bounds, syntax/encoding/blank policy and reducer races. The existing optional CDP
inventory harness accepts `--csv-browser` to run actual file-picker/React race,
side-isolation and mobile checks without a new framework or AISFA dependency.
No screen-reader/full WCAG or future mapping acceptance is implied. Rollback is a
revert of this bounded picker/parser/view/test/doc change, with no migrations/resources.
