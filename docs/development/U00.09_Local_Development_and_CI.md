# Local development and foundation CI

U00.09, in review. One Next.js application; no AISFA checkout, database, Docker,
browser framework, API key or service account is required for development/checks.

## Fresh clone

Install Git, Node **24.22.1** and npm **11.19.1**. `.nvmrc` pins CI's Node version;
the supported Node engine is >=24.22.1 and <25. Windows PowerShell and macOS/Linux
can use the commands below. If `npm.ps1` is blocked, use `npm.cmd` instead of npm;
there is no need to change PowerShell execution policy.

```sh
git clone https://github.com/vamshirahul/AIVRA.git
cd AIVRA
node --version
npm --version
git status
npm ci --no-audit --no-fund
npm run dev
```

The repository is private: use your normal GitHub Git access for cloning.
Visit http://localhost:3000 and `/data-mapper` for a local smoke check. Expect
Public Preview, the synthetic deal, ten navigation destinations and introductory
module pages. Stop the server with Ctrl+C. Development uses Next's dev server;
`npm run build` creates production output, and `npm start` serves that output.
Stop dev before starting production on the same port. To use an alternate port:

```sh
npm run dev -- --port 3001
# Or, after building and stopping the other server:
npm start -- --port 3001
```

To suppress Next telemetry locally, set this before dev/build/checks:

```powershell
# Windows PowerShell
$env:NEXT_TELEMETRY_DISABLED='1'
npm.cmd run check:ci
```

```sh
# macOS/Linux
NEXT_TELEMETRY_DISABLED=1 npm run check:ci
```

## Shared offline checks

`npm run check:ci` runs these existing checks sequentially, once each, and stops
at the first failure using `&&` (nonzero status propagates to npm and Actions):

1. `npm run validate:fixture` — synthetic data, IDs/links and negative cases.
2. `node scripts/check-demo-session.mts` — shared state/persistence/invalidation.
3. `npm run check:ai-adapter` — mocked structured output/source validation/guards.
4. `npm run check:ai-controls` — fake store, independent budgets, rates and routing.
5. `npm run check:ai-ui` — isolated state/copy/render checks, **without browser**.
6. `npm run typecheck` — Next route types and TypeScript.
7. `npm run build` — one production build.

Run the individual command for the code you change during development; use the
shared command for final local/CI parity. No lint tool is configured. No live
provider interoperability/quality, cross-instance durable-store atomicity, browser
UAT, deployed endpoints, cloud services or U90 end-to-end acceptance is claimed.

`.github/workflows/ci.yml` runs one `foundation-checks` job on Ubuntu for PRs
targeting main and pushes to main. It uses SHA-pinned GitHub checkout/setup-node,
Node from `.nvmrc`, exact packageManager npm, `npm ci --no-audit --no-fund`, then
the shared check. Token permissions are `contents: read`, checkout credentials are
not persisted, runtime is bounded to 15 minutes, superseded runs are canceled.
Next telemetry is disabled and the AI enable flag is false. No repository secrets
are passed. Package-registry downloads are normal install traffic, not inference.
There is no deployment, auto-merge, release or branch-protection change.

See the PR **Checks** tab or repository **Actions → Foundation CI** for real run
logs and conclusions. A local pass does not prove an Ubuntu/GitHub pass. Pending,
disabled, billing-restricted or failed Actions must be reported honestly. A founder
can separately require `foundation-checks` in branch protection after review;
this unit does not configure repository settings or authorize paid runner capacity.

## Environment, privacy and activation limits

No environment file is required. `.env.example` contains **blank placeholders
only**; optional `.env.local` is Git-ignored and must never be committed. Never put
provider credentials into browser variables, Actions YAML, screenshots or logs.
Populating environment variables alone cannot enable live inference: both OpenAI
pre-dispatch and provider-fetch hard stops remain, and the router is offline-only.

The fictional Buyer Northstar and Target Meridian are synthetic examples.
Browser-tab `sessionStorage` is temporary, not confidential storage; do not upload
real client transactions. If storage is denied, edits continue in memory and may
be lost on refresh. Reset is explicit. Four AI-intended intros truthfully show
“AI not enabled”; seven Future Features icons are inert. These are expected states.

Before any live inference: ADR-012 exact paid/open-weight models, terms and prices;
approved independent budgets/limits/spend; a real durable atomic usage store with
multi-instance validation; trusted anonymous ingress/protected module entrypoint;
provider backstops, monitoring/reconciliation and bounded live tests; end-to-end
acceptance and explicit G5 release authorization. ADR-013 hosting approval and
deployment remain deferred. See the [AI control contract](../contracts/U00.07_AI_Budget_Routing_Contract.md).

## Optional independent browser smoke

Browser tests are manual and excluded from `check:ci`. Do not copy paths from old
validation reports that used another workspace's installed tools. For a standalone
browser run, you may use an existing installation of **playwright-core** and a
compatible Chromium executable from a tooling location you control. This is
optional; no framework or browser is installed by AIVRA or CI.

Start a local production server on 127.0.0.1:3000 after building, then in a second
terminal point the harness to your own existing absolute paths:

```powershell
$env:AIVRA_PLAYWRIGHT_PATH = Read-Host 'Absolute path to your playwright-core package'
$env:AIVRA_CHROMIUM_PATH = Read-Host 'Absolute path to your Chromium executable'
npm.cmd run check:ai-ui -- --browser
```

```sh
printf 'Absolute path to your playwright-core package: '
read -r AIVRA_PLAYWRIGHT_PATH
printf 'Absolute path to your Chromium executable: '
read -r AIVRA_CHROMIUM_PATH
export AIVRA_PLAYWRIGHT_PATH AIVRA_CHROMIUM_PATH
npm run check:ai-ui -- --browser
```

Use `npm start -- --hostname 127.0.0.1 --port 3000` for the server. The browser
check uses loopback only; `AIVRA_BASE_URL` can select another loopback port.
If tools are unavailable, skip the optional smoke and record that limitation;
offline checks need neither variable nor browser. Older standalone browser scripts
are also manual and are not part of this unit's automatic validation.

## Troubleshooting and next unit

| Symptom | Action |
| --- | --- |
| Wrong Node/npm | Select `.nvmrc` with your version manager or install the pinned Node; use npm 11.19.1, then check both version commands |
| Missing modules | From this repo's root, run `npm ci --no-audit --no-fund`; no other workspace is required |
| Lockfile/install mismatch | Restore a matching approved package.json/lockfile pair or review the dependency change; do not regenerate the lockfile with an unpinned install |
| PowerShell script policy | Invoke `npm.cmd`; avoid changing machine policy |
| Port occupied | Stop the old server, or pass an explicit alternate `--port` |
| Stale Next output | Stop the server first and rebuild; if necessary remove only this repo's regenerable `.next` directory after verifying its absolute path, then rebuild |
| Storage denied | Expect the memory-only notice; refresh may lose edits; do not treat it as confidential storage |
| AI disabled | Expected; do not add keys or bypass guards to make the shell work |
| CI fails | Open the failed job/step logs; reproduce the specific failing command before repeating all checks |

Do not use `git clean`, `git reset --hard` or broad recursive cleanup as setup steps.
Approved local documents may be untracked; preserve them. U01.01 begins M01 Data
Mapper by displaying/switching stable Buyer/Target sample inventories. Keep one
shared session and the common contracts; this foundation adds no AI business
recommendation rules. U90 acceptance and founder release approval remain later work.

Rollback: revert the isolated U00.09 workflow/script/docs change. No migration,
application state or external resource is created.
