## TSA-CREATE-001 — Browser-session creation

Existing session/controller modules expose createTSA. No new store, schema version,
storage key or independent mutation mechanism. The provider automatically exposes
the controller method via its existing spread; no provider rewrite is needed.

| Rule | Implementation |
| --- | --- |
| ID | One `tsa-${crypto.randomUUID()}` attempt per validated creation; visitor cannot submit tsa_id |
| Uniqueness | Existing full DemoSession/fixture validation rejects collision with any app/license/TSA record; no retries, identity rewriting or silent unlink |
| Required | Nonblank title/provider/recipient and explicitly selected original enum status; no initial status default |
| Optional | Owner/start/end/milestone/risk notes omitted → null; UI blank optional strings → null; existing schema notes max500 and ISO/calendar/range rules |
| Relationships | Existing app IDs only, max10 distinct references. Omitted/undefined relationship input stays omitted; recorded empty [] remains explicit no-links |
| Token | Captured session_id + full session_revision must exactly match current controller state; stale/reset attempts fail before append |
| Commit | Complete TSAServiceSchema, full DemoSessionSchema and original serializeSession character cap; append one record, increment tsa/session revisions once, keep other arrays/fixture/metadata intact |
| Failure | No source mutation, writes, notifications or revisions on invalid shape/date/reference, collision, limit/size, UUID exception or stale token |
| Persistence | Existing controller apply/persist pipeline and browser-tab sessionStorage only |

Pure createTSA serializes before returning to enforce existing 512,000-character
limit for direct callers too; the controller serializes again before committing as
with every original operation. This validates size, not a second write. Existing
100-service cap stays fixed. UUID is generated only on Save, never on open, typing
or Cancel. No deletion/reorder/creation defaults for factual required fields.

## Existing-record editing and validation

The preferred bounded edit surface is status, nullable owner, start/end dates, exit
milestone and risk/dependency notes. Existing TSA ID, title/provider/recipient and
application relationships are read-only and retained exactly. Creation supplies
its own required identity labels/current application references. No invented labels
or dependencies, and no automatic changes to source status.

Form drafts are ephemeral. Original TSAServiceSchema validates the complete proposed
service; original updateTSA and full session/serialization remain the final authority.
No writes per keystroke. Save rejection retains text and shows bounded field/error
summary; Cancel discards only the draft. No-op Save returns the original snapshot
with no write, notification, timestamp or revision change. Source strings render as
escaped React text; no HTML/URL activation or model processing.

The existing updateTSA operation gains an optional expected TSAEditToken for guarded
UI commits; all original two-argument controller callers remain compatible. Token
contains session lifetime, TSA revision, application revision, exact TSA ID and
captured record JSON. UI checks the latest getSnapshot immediately before Save;
the controller/pure update then check atomically inside apply. New TSA, source/app
edits or Reset reject old tokens. Unrelated metadata changes do not stale edit
tokens when TSA/app source is unchanged; creation deliberately uses full revision.
No stale draft overwrites a newer record, even when text returns to older values.

Stale form retains its draft, disables Save and offers Reload current values
(explicitly discards draft) or Cancel. Reset replaces the lifetime-keyed workspace,
discarding pending create/edit drafts, filters and messages. No old form callback
can apply an old token to the reset session. A latest-draft ref is cleared on unmount.
Successful Save/Cancel restores focus to the original Edit/Add control; if a status
change hides that row, focus returns to the filter. Invalid Save focuses the error
summary. Only one panel is active; filters/other Edit/Add controls are disabled
until Save/Cancel, avoiding silent draft loss.

## Source freshness, filtering and attention

TSA changes increment only the TSA/session revision. Existing derived metadata is
retained: playbook/assistant/health consumers depending on TSA become stale;
ALA/cost/scenario sources retain their existing independent dependency rules.
No results or dashboard counts are generated/published by this unit.

Status filter uses only planned/active/at_risk/completed plus All statuses. It reads
current valid source rows, retains source order/IDs and never edits/deletes hidden
records. No-match and empty inventories are distinct. Filter is memory-only and
returns to All on refresh, navigation remount or Reset; no stored filter key.

Attention has **no approaching-date threshold**. The workspace captures and displays
today's UTC YYYY-MM-DD on mount, with no timer. Known ISO start/end values compare
lexicographically as before/on/after that explicit reference; null remains unknown.
Milestone attention reports supplied/unknown, never achieved/not achieved. Source
at_risk remains a separate user-selected enum, not a computed risk. This is the
packet's minimal supported informational indication for REQ-082: no 7/30/90-day
policy, risk score, prediction, timezone conversion or automatic status transition.
The reference stays fixed until remount/refresh/Reset and is labeled accordingly.

All eleven U07.01 source columns remain; a twelfth action/attention column is added
only on the interactive surface. The standalone pure read-only view stays available
for existing SSR source regressions. Loading/unavailable/empty/invalid states and
exact linked names/sides/IDs retain prior semantics. Existing A1 tokens, labels,
field errors, native controls, scroll-region focus and responsive form grid are used.

## Storage failure and security boundary

Existing quota/access failure semantics are preserved: a validated atomic update
remains usable in memory, removes stale persisted state when possible, and signals
storageAvailable=false. Save says memory only / may be lost on refresh; existing
session banner remains. This is not a failed partial record or durable save promise.
Validation/stale/size failure occurs before persistence and never mutates state.
No second storage key, localStorage, database, auth, network, live AI or cloud work.

## Acceptance tests and limits

Eight focused groups cover approved creation rules, globally unique ID collision
rejection, optional/null/omitted/empty distinctions, full source/session caps,
atomic errors and UUID failure, existing update/no-op/Cancel behavior, stale/reset/
app/source tokens, filters/date/milestone semantics, dependent freshness, refresh,
quota-memory behavior, fixture preservation and zero external/provider calls.
The previous pure TSA source-view suite remains in CI. Its optional browser check
now asserts the original eleven source cells separately from the added action column.

Existing Chromium harness --tsa-edit-browser tests the actual public provider:
Add/validation/explicit status and UUID append, current links/escaped notes, no-op/
Cancel/Edit/Save, filters/no-match, refresh/SPA navigation, Reset during a pending
draft, unknown versus recorded-empty links, quota notice, keyboard and 1440/390/320
screenshots. Source-race/reload logic is covered by controller/helper tests; browser
does not add production debug globals to inject other modules' mutations. Full
screen-reader/WCAG/physical-device and later release UAT remain separate.

No deletion, U07.03 export/dashboard, financial calculations, risk prediction,
live AI, new dependencies/persistence or deployment. Rollback: revert this unit's
feature files; no persisted schema migration, secrets or external resources.
