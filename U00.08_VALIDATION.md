## Focused evidence

1. Static not-enabled and idle have no live region, provenance, result or CTA.
   Loading has one polite atomic `status`, honest pending text, no progress/ETA.
2. Simulated prevalidated paid/fallback metadata renders model/provider, AI draft,
   not-transaction-advice and no-human-approval copy. Both permitted fallback
   reasons are tested; no free/unlimited claim. Stale appears only when supplied.
   These are fabricated **test metadata**, not successful AI invocations or provider approvals.
3. Invalid identity, excessive model length, missing/forbidden reason and invalid
   mode are suppressed. Every one of the **14 current server failure codes** is
   checked against the server schema's list and mapped to fixed text with one
   alert and data-retention notice. Raw-message/payload canaries never render.
   Provider failure explicitly does not imply a generated fallback result.
4. Fallback/error rendering leaves a synthetic deal plus derived metadata snapshot
   byte-identical. Shared component/mapper source checks exclude storage, effects,
   timers, environment, network and server-runtime imports. The state type imports
   are erased, and plain Node rendering works without the server-only condition.
5. Approved text contrast ratios: foreground/surface **14.33**, accent/accent-soft
   **5.10**, success pair **6.53**, warning pair **5.52**, error pair **5.93**;
   all exceed 4.5:1. No focusable element or new keyboard interaction is introduced.

The actual production shell smoke returned HTTP 200 for all ten navigation
destinations. At **1440px and 390px**, all four AI-intended intros rendered exactly
one disabled notice and retained “Not yet implemented,” with no notice controls,

endpoint, server action, AI business rule or request transport was added or used.
