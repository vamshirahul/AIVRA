## Server trust boundary

`projectALAResults(outcome, capturedSource, currentSource)` in server-only
`lib/server/ala/presentation.ts` accepts a trusted U02.02 outcome and the exact
captured and current session snapshots. Although parameters are `unknown` to force
validation, this is **not an HTTP/visitor JSON entrypoint**. Future callers must
obtain the outcome from a separately approved protected production execution path.
No such successful public source exists today. A schema-valid fabricated envelope
or TypeScript brand cannot authenticate an execution or founder model approval.

Validation is independent of display:

1. Bound serialized outcome to the existing 64,000-byte envelope cap and parse
   exact `ALAAnalyzeOutcomeSchema`, requiring unchanged values and success/incomplete.
   Errors, extra root/envelope fields, malformed identity/provenance and contradictory
   status/coverage are invalid. No raw exception/provider strings are returned.
2. Validate both complete sessions using existing DemoSessionSchema and the
   512,000-character bound. Reject source normalization or stripping.
3. Require `matchesALASource(token,captured)` with the exact U02.01 SHA-256 rules.
   Missing/unverified captured source is invalid; never join to guessed source.
4. Re-run `inspectALAResult` against captured applications. Deep-compare computed
   coverage, including source/accounted counts and ordered missing/not-evaluated IDs,
   to outcome.coverage. Caller-supplied coverage alone is never trusted.
5. Rebuild captured `ala/v1` input and compare the envelope input digest using the
   adapter's exact `{input,references}` SHA-256 semantics and existing reference-policy
   schema. This validates captured request consistency, not provider execution.
6. Require `matchesALASource(token,current)`. Valid app edits/publication, reset,
   source lifetime/revision or digest changes produce **outdated** with no data.
   License-only changes remain current, since freshness is application-only; digest
   comparison of the full invocation uses the original captured snapshot, not later
   license values. Malformed current source is invalid.
7. Only then project envelope metadata via existing `metadataFromValidatedResult`
   and deeply freeze the bounded display data. No session mutation/metadata write.

## Client-safe display contract

`lib/ala/results-view.ts` exports readonly `ALAResultsView` and opaque
`ALAResultsData`. All server type imports are erased. The only runtime producer
of populated projections is the server validation boundary. The compile-time marker
is not serialized security; do not cast browser/storage/URL data into this type.

| State | Presentation |
| --- | --- |
| absent | No analysis/findings available; no table or provenance |
| invalid | Existing U00.08 invalid-model safe error; no rows or provider text |
| outdated | Explicit source-changed notice; all rows/evidence/provenance suppressed |
| current | Validated AI draft, structurally complete coverage, never human approval |
| incomplete | Actual draft findings plus conspicuous coverage warning and unassessed IDs |

The populated projection includes exact finding/action fields, member IDs and
captured names; inspected coverage; source revision/currency; ordered missing and
not-evaluated records; evidence pointers with only their captured attribute values;
and envelope provider/model/mode/reason/prompt/time/request ID/input digest. It omits
full requests, unrelated source records, credentials, budgets, usage/cost fields,
hidden prompts and raw provider responses. Bounds come from existing schemas:
100 findings, 200 actions, 400 evidence/member references, 100 apps (50 per side),
existing text caps. No truncation, inference or normalization of result strings.

## Read-only presentation

`components/ala/ala-results-grid.ts` is pure React text rendering with no effects,
state, network, parsing, persistence or edit/export controls. Existing AIStatusNotice
supplies real paid/fallback metadata copy and safe invalid-result messages. Explicit
draft/review-required/not-transaction-advice guidance accompanies any trusted draft.

The table groups rows by finding, retains all cross-finding repeats and uses one
row per original action. It shows finding ID/domain/relationship, exact Buyer/Target
IDs and captured names, action ID/subject/side/disposition/destination, complete
finding/action rationales in native details, source pointers/values and qualitative
uncertainty/reason. No probabilities or inferred destinations. Null destination is
`None / Not applicable`; null source value is `Unknown`; numeric zero remains zero.
Annual cost labels use the captured currency. Plain text preserves case and notes.
Evidence pointer existence is explicitly not independent verification of reasoning.

Source/accounted counts are unique applications, separate from finding/action row
counts. Explicit not-evaluated counts as structurally accounted but remains incomplete;
missing IDs say `No AI finding returned — Not assessed`. Both lists preserve captured
source order within their category, with exact supplied reasons for not-evaluated.
No fabricated rows, repair, retry, approval, matching or local disposition selection.

Semantic caption/column headers, finding row-group headers and tbody groups support
reading order. The labelled focusable scroll region contains horizontal table scroll;
native details/summary expose all rationales to keyboard navigation. Scoped CSS uses
existing A1 tokens, fixed table layout, safe text wrapping and visible summary focus.
No filters were added. Full populated-grid browser/screen-reader UAT remains pending
protected integration; deterministic SSR/semantics/CSS checks are not a WCAG audit.
