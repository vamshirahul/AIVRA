# U00.08 — Shared AI feedback presentation

Status: in review. REQ-003/005/050/053/055/059; A1 Coastal Navy.
No live integration, endpoint, provider, model selection or business action is enabled.

## Read-only boundary

`AIStatusNotice({state})` in `components/ai/ai-status-notice.ts` renders React
elements in server shells or a future client component. `lib/ai/ai-view-state.ts`
is the single client-safe presentation contract. Its server contract imports are
**type-only** and erased. Neither module reads environment, storage, session state,
or provider configuration; neither has effects, timers, polling or network calls.
They accept no transport, raw error, prompt, result data, HTML or arbitrary status text.

| State | Accepted fields | Meaning and announcement |
| --- | --- | --- |
| `not_enabled` | None | Static AI integration planned; no request claimed; no live region |
| `idle` | None | No analysis initiated; sample input is not a result; no live region |
| `loading` | None | Caller has a genuinely pending request; “Analyzing with AI...” in one polite, atomic `status` |
| `completed` | `resultMetadata`, optional `freshness: current/stale` | Server-validated paid/fallback result provenance and AI draft; one polite, atomic `status` |
| `error` | `safeErrorCode: FailureCode` | Fixed safe copy, no fabricated result; one atomic `alert`, without redundant `aria-live` |

Completed metadata is a readonly discriminated union: paid forbids a routing reason;
fallback requires exactly `budget_exhausted` or `paid_unavailable`. Both identify
the actual provider and model. Obtain the nominally branded metadata with
`metadataFromValidatedResult(envelope)` **only after server validation of a real
successful result**. It projects these fields and discards data, usage, IDs and all
other envelope fields. A malformed identity/mode/reason returns null, and malformed
completed presentation safely becomes `invalid_model_output`.

The brand is a TypeScript misuse guard, not authentication, serialization or proof
of server validation. The helper validates presentation bounds, not the output
schema, references or model eligibility. Future transport owners must validate
their received server envelope before projecting metadata, including after JSON
deserialization. Do not pass visitor-controlled or provider-generated identity.
Provider is bounded to 1–64 `[a-z0-9.-]` characters and model to 1–128
`[a-zA-Z0-9._:/-]`, matching existing server identity bounds. React escapes text;
identity is plain text, never a URL or HTML.

Paid results say “AI draft · Paid model.” Fallback says “AI draft · Open-weight AI
fallback,” shows the same actual identity fields, explains the permitted routing
reason and says results may differ. Neither implies approval, confidence, free or
unlimited service. A provider failure never implies fallback was attempted.
`freshness: stale` adds an “Outdated” sentence only when supplied by the owner.
The notice never calculates freshness or changes session revisions/results.

## Safe error mapping

`AI_ERROR_COPY` exhaustively satisfies the current server `FailureCode` union.
Errors always add “Your synthetic session data is retained.” This is a read-only
presentation guarantee, not a promise of encrypted or durable storage. Future
owners must preserve previous data/results when handling failure themselves.

| Codes | Visitor explanation |
| --- | --- |
| `invalid_input` | Inputs could not be validated |
| `request_too_large` | Reduce supplied input size |
| `invalid_model_output` | No valid AI result available |
| `provider_unavailable` | Provider could not complete; no fallback result generated |
| `unexpected_error` | Request could not complete |
| `ai_not_enabled`, `ai_disabled` | Requests currently disabled |
| `ai_controls_not_ready` | Integration not ready for live requests |
| `controls_unavailable` | Usage protections unavailable; further requests paused |
| `rate_limited` | Request limit reached; availability may change |
| `capacity_reached` | Capacity full; availability may change |
| `paid_budget_exhausted` | Paid allowance exhausted; no fallback result available |
| `fallback_unavailable` | Independent fallback unavailable or allowance exhausted |
| `duplicate_request` | Already handled/reserved; no additional request started |

Unknown runtime codes fall back to fixed unexpected-error copy and are not echoed.
Never render server/provider message strings, request IDs, payloads, source text,
balances, IPs, environment or credential names. No specific retry/reset is promised
to restore service. No retry button is provided in this unit. A later working
explicit action belongs to its real request owner; never add an inert CTA here.

## Future caller handoff (U02.03 and other AI modules)

Today the four AI-intended intros render only:

```tsx
<AIStatusNotice state={{ status: "not_enabled" }} />
```

For a later approved module, the owner initially holds `{status: "idle"}`. Only
inside its real explicit user action, after all live gates have been cleared:

```ts
// Illustrative lifecycle, not an implemented action or client router invocation.
setView({ status: "loading" });
const reply = await approvedProtectedModuleAction(); // future module-owned action
if (!reply.ok) {
  setView({ status: "error", safeErrorCode: reply.error.code });
} else {
  // reply.result has passed the module envelope/schema/reference validation.
  const metadata = metadataFromValidatedResult(reply.result);
  setView(metadata
    ? { status: "completed", resultMetadata: metadata }
    : { status: "error", safeErrorCode: "invalid_model_output" });
}
```

Import the view types/helper and notice into the owner, never the server router
runtime into client code. The owner must handle exceptions with a safe code,
avoid racing/superseded requests, capture source versions and persist results only
according to later module contracts. Render the validated business result separately;
this notice accepts only provenance. Keep earlier data/results on failure. Request
owners alone reset/update view state; component mounting or fixture loading never
starts analysis. U00.07 alone determines routing; this mapper does not select a path.

## Accessibility, current integration and exclusions

One small static notice appears on Application Rationalization, License Optimizer,
Playbook Generator and AI M&A Assistant. All nine introductions retain “Not yet
implemented.” Other introductions, navigation, seven inert future items, shared
session/reset behavior and disclosures are unchanged.

Words communicate every state. Existing A1 foreground/surface and semantic color
tokens are reused without changing their values. Text wraps at narrow widths;
there are no animations, percent progress or focusable elements. Caller updates
the same notice to announce changes; avoid rendering duplicate notices or remounting
an unchanged error repeatedly. No focus is stolen. Screen-reader announcements
and all future dynamic client lifecycles still need assistive-technology acceptance;
local static/DOM checks do not certify complete WCAG conformance.

No public status API, AI button, result switcher, mock response, session mutation,
background retry, prompt, recommendation rule, dependency install or live request
is introduced. Existing server code and both OpenAI hard stops remain untouched.
ADR-012, durable store, protected ingress and G5 activation gates remain pending.
Rollback is a revert of these presentation/doc changes; no migration or resources.
