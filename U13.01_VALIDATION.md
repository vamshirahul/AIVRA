## Implementation and integrity

Version `health/metrics/v1` defines immutable, read-only application/side counts,
TSA source-status counts, original ALA action rows/recorded visitor overrides,
existing calculated CSE totals/warnings and Playbook activities/milestones/edit count.
Every populated metric has a source path; result-backed metrics retain original
request/input identity. Full session/fixture/revisions/deal digest and a complete
input binding digest preserve traceability.

There is **no existing affirmative all-suggestions-reviewed counter**. ALA override
counts are exposed accurately; `reviewed_suggestions` stays null/not_recorded.
Unchanged AI actions are not silently counted as reviewed/approved. No new review
instrumentation, approval policy or unsupported percentage is introduced.

CSE needs an already supplied calculated result plus current draft and reviewed
context. Existing buildEstimateRequest/calculateCSE revalidate that result exactly;
they do not auto-create an estimate from spend. Exact CAD cents, signed/null totals,
horizon, original warnings and double-counting safeguards are retained. No license
savings aggregation or second financial engine. Not-computable output is unavailable.

Each metric distinguishes current/incomplete values from absent/outdated/invalid/
unavailable/not_recorded null values. Missing reviews retain unknown override/edit
counts; invalid reviews are not repaired. Valid empty TSA means zero, missing AI
or financial result means null. Independent inventory remains available with
invalid optional business results.

The server-only reader is trusted module-owner composition, not HTTP/file/JSON
execution authentication. Existing ALA/CSE shape/digest validation does not prove
arbitrary imported data came from an LLM. Playbook uses its existing owner-issued
source. No public delivery bridge is introduced.

Assembly reads twice and fails on changed inputs. Complete source binding includes
original results, review content, assumptions and current Playbook data, even when
aggregate counts remain unchanged. A private WeakMap associates exact issued
snapshots with the reader; clones/JSON cannot become current by assertion.
Observed invalidation is permanent until a new build; reverting data cannot revive
an old capture. Transient mutations hidden between all observations remain outside
the authoritative-reader guarantee.

Original session bounds and MAX_CSE_BYTES (1,500,000 UTF-8 bytes for complete binding)
remain enforced without truncation or a cap increase. Invalid primary source,
reader exception/instability and oversized composition fail with safe fixed codes.
No prompts, provider/config credentials or raw private exceptions are returned.
