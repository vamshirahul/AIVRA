## Protected owner and explicit workflow

`createAssistantAskOwner(options={})` constructs the existing createAIRouter once.
Options are trusted server composition, never client configuration. Defaults fail
ai_disabled. Actual execution still requires validated offline policy, trusted
hashed client key, fake usage store and mock transports. No environment switch can
enable live execution. The Assistant imports no adapter, SDK transport or provider.

| Operation | Contract |
| --- | --- |
| createConversation(readSource) | Builds a genuine current U10.01 context via authoritative latest-source reader; returns ready plus opaque in-memory conversation handle and empty frozen history, or fixed error |
| ask(handle,request,caller) | Only dispatch path; strict request/question and trusted client_key, owned current conversation and bounded history; one guarded router await |
| getHistory(handle) | Current frozen history or null; no storage or imported-history hydration |
| isCurrent(result) | Exact owner-issued successful result object plus current source; JSON/clones cannot acquire issued status |

Each owner is composed for the visitor's current tab/session. Handles are frozen
opaque objects backed by a private per-owner WeakMap; they cannot be serialized,
used by another owner or reconstructed from JSON/session UUIDs. There is no global
conversation-ID lookup, authentication requirement or public handle transport.
Future protected delivery must provide real source ownership/currentness and
per-tab isolation; this unit does not solve stateless production session delivery.

Before each Ask, the owner rebuilds current U10.01 context and compares the entire
capture, then calls isCurrentAssistantContext. This covers session lifetime/Reset,
fixture/full source digests/revisions, available upstream result identity,
ALA visitor review, raw financial assumptions, owner-issued Playbook/review/scenario
and missing-context state. Changes permanently revoke the conversation and all
issued answers; reverting data cannot revive it after detected invalidation.
Authoritative readers must actually read current state; hidden changes cannot be
detected by function types or hashes. Imported context is never accepted by Ask.

The owner checks immediately before dispatch, after its sole await of the complete
guarded router (including store/provider/settlement), during envelope/reference
validation and immediately before atomic history commit/answer release. Already
reserved/dispatched router work remains accounted even if sources change; there
is no budget rollback, settlement bypass or automatic replacement call. Internal
router accounting awaits retain their existing semantics. No source data is mutated.

An immediate per-conversation busy guard rejects overlapping Ask calls. The shared
router independently enforces cross-conversation/global/client/provider concurrency,
rates, budgets and trusted identity. Creation, reads, source updates and navigation
never call a provider. Only an explicit ask() invokes the router once.

## Versioned request, answer and history

| Structure | Fields / semantics |
| --- | --- |
| assistant/ask/v1 visitor request | Strict contract_version and question only; no model/system/context/history/caller request UUID fields |
| Question | 1–2,000 UTF-16 code units, nonblank; no C0 controls except tab/CR/LF and no DEL; no trimming or instruction promotion |
| Typed context.assistant payload | Same version, actual U10.01 AssistantContextSchema, captured question and owner-supplied AssistantHistorySchema; no whole-context user_text packing |
| assistant/answer/v1 | status=answered or insufficient_evidence; nonblank answer<=4,000 code units; <=20 exact typed citations; complete original missing_context array; illustrative_unapproved=true; narrative_not_verified=true |
| Answered | At least one supported typed citation required; a section citation is permitted only for an actually supplied section |
| Insufficient evidence | May have zero citations; explanation is model-authored, never a local canned business answer |
| Provenance envelope | Existing strict server-owned provider/model/mode/fallback reason/request UUID/input digest/prompt/generation time/usage/warnings; module=assistant, prompt_version=assistant/v1 |
| assistant/history/v1 | conversation UUID, session UUID, full context digest and <=4 question/envelope exchange pairs; <=32,000 UTF-8 bytes total |

Answer references reuse the exact U10.01 namespaced union: source IDs/Buyer-Target
side, license/app parent, ALA finding/action parent, license finding, assumption
line, Playbook phase/activity/milestone/risk and supplied section. No invented flat
IDs, narrative regex extraction, URLs or confidence scores. Duplicate/invented/
wrong-side/wrong-parent references and extra/coerced/oversized/inconsistent outputs
fail; nothing is repaired or dropped. Complete missing_context labels must equal
the authorized context, including incomplete/stale/unavailable evidence states.
Membership/disclosure structure cannot verify narrative truth, legal correctness,
calibrated uncertainty or whether an insufficient-evidence narrative is appropriate.

The model cannot author provenance fields inside data. The owner revalidates the
full envelope, exact server UUID, request/reference-policy digest, fixed configured
provider/model/mode/fallback reason and current issued-context citations through
validateAssistantReferences. validateAssistantEnvelope is validation only and
never grants result ownership. Only successful owner Ask returns an issued result.

History is generated by the owner after a valid answer; raw history/imported files
cannot be passed to ask(). Requests with history/role/system fields fail. The
wire schema also rejects malformed history, foreign session/context binding and
unsupported citations in prior answers. All prior question/reply text is untrusted
data in the JSON user context, never system messages or new source evidence.
The transcript records the frozen question actually sent, not a mutable caller
object reread after an await. History/answers are immutable snapshots.

At four exchanges another Ask fails history_limit before reservation. An explicit
new conversation can start from current sources; there is no automatic eviction,
clipping, summarization or UI Reset control. If appending a valid large response
would exceed32,000 bytes, the entire append/response fails history_limit and prior
history remains intact; authorized provider usage remains accounted. Provider/
control/output failures preserve prior current history. Stale conversations expose
no current history. No database, browser storage or persistent transcript is added.

## Typed gateway and dependency graph

Existing InvocationInput gains only optional `context.assistant` with the strict
payload above. Presence (or assistant/v1 prompt) requires module=assistant, the
exact server-owned ASSISTANT_SYSTEM_PROMPT, no user_text/Playbook payload, exact
deal equality/digest/fixture and history session/context digest. Other modules
cannot carry Assistant payload. Legacy generic adapter/control test invocations
without this field retain original flat-ID rules; public code has no such path.

For typed Assistant payload only, legacy allowed_source_ids is exactly empty,
because namespaced references cannot honestly be represented as fabricated source
IDs. This is **not** a bypass of output reference verification: the same adapter
requires the fixed AssistantAnswerSchema and strict reference policy, extracts the
actual structured answer.citations, compares extractor output exactly to those
citations, and independently validates all entries against the supplied typed
catalog plus answer-state/missing-context rules. A permissive empty extractor for
a cited answer fails. Empty citations pass only the insufficient-evidence state.
Original flat-ID verification remains unchanged for ALA/licenses/Playbook/legacy
tests. Reference-policy allow_empty=true is state-restricted by the answer schema.

The unchanged guarded router is the sole execution gateway. The SDK transport's
small Assistant branch serializes typed context/question/history directly as
untrusted JSON and names the typed catalog in its appended instruction. It adds
no fictitious flat IDs or redundant catalog outside context. Existing model object,
structured Output.object, store:false, maxRetries:0, abort and <=2,048 output tokens
are preserved. Actual SDK MockLanguageModelV4 tests inspect this wire path offline.

To avoid AI-contract -> Assistant-context -> upstream-orchestrator -> router ->
adapter -> AI-contract cycles, unchanged data shapes are factored into server-only
ai/base-contracts.ts and ALA/license source-schema/outcome-schema plus Playbook
outcome-schema. Existing exports are retained at their original paths. Business
output schemas import only base contracts; Playbook schema uses existing
input-schema directly. AssistantContextSchema switches to those data-only imports.
No schema fields, enum values, source semantics, error messages, provider policy
or financial formulas are changed by this extraction. Existing suites verify
all old module behavior. Import-DAG/server-only tests verify both old and new entrypoints.

## Bounds, routing and safe failure

Full serialized invocation includes both the unchanged generic deal and Assistant
context deal, question, complete history, system instructions/catalog and output
JSON schema. Duplicate deal byte cost is measured, not hidden. The owner and
Assistant preflight enforce128,000 UTF-8 bytes before authorization; the router
also applies configured policy max_input_bytes. Existing64,000-byte model output/
envelope and2,048-token authorization caps remain. Larger context/history may fail
before four exchanges; nothing is truncated, selectively omitted or re-encoded
into user_text. A U10.01 context fitting its domain limit may not fit full Ask.

Fixed safe shared errors are reused. Local source_changed/invalid_conversation/
history_limit have fixed bounded messages. No raw model/store/provider exceptions,
context/question bodies, credentials or policy secrets are logged/returned.
Model-generated answer text remains untrusted and future U10.03 rendering must
escape it. No HTML renderer or business recommendation engine is introduced.

Paid/fallback remain independently budgeted; only existing paid-budget exhaustion
or configured paid-disabled conditions select fallback. Rate/concurrency/provider/
timeout/malformed output/store/settlement failures never generate a fallback retry.
Reservation/settlement/unknown-usage retention and caller identity rules are intact.
Default policy disables; live_dispatch_enabled remains literal false. Both OpenAI
factory/fetch hard stops, ADR-012 approvals, pricing/durable-store/ingress/release
requirements and deployment configuration stay unchanged. No real API call/charge.
