# U02.02 — Deliberate readiness action and offline ALA orchestration

Status: **in review**. REQ-020/021/025/059. Bounded offline implementation only;
live-AI activation blocked. No local matching/disposition rules or persisted results.

## Public reality: an unconditional unavailable route

`POST /api/ai/ala` is the only API path. `app/api/ai/ala/route.ts` declares Node
runtime and exports a POST with **no request argument, imports, environment reads,
body/header access or activation branch**. It always returns HTTP **503**,
`Cache-Control: no-store`, JSON Content-Type, and this fixed error:

```json
{"status":"error","error":{"code":"ai_controls_not_ready","request_id":null,"message":"Live AI analysis is not enabled. Availability check only."}}
```

No router, provider, fake/real usage store, session parser, credential or request
payload is accessed. Environment flags, headers, client models and test modes cannot
activate it. Unsupported methods use Next's method handling (GET verified 405).
No status endpoint, CORS wildcard, ingestion backend or pseudo-authorization exists.
An arbitrary caller can send bytes to any HTTP server, but this handler does not
deserialize/log/forward/persist them. The actual UI sends **no body or source data**.
The unconditional route is the safety boundary today; it is not a live protected
inference endpoint, and adding one requires separately approved work.

## UI and lifecycle

Only `/application-rationalization` gets `AnalyzeApplications`. Its counts and
application source revision come from the existing shared session, with the
synthetic/test-only warning. One primary native **Analyze applications** button
checks availability only, as adjacent persistent guidance explicitly states.

Initial/hydration/navigation/reset/refresh do not fetch. Each deliberate click
issues one POST to the inert route with no body, credentials omitted and no-store.
An immediate in-flight guard and disabled button suppress repeats; no retries,
polling, chaining or background inference. A ten-second AbortController deadline
bounds the readiness request. Actual pending copy says **Checking AI readiness...**
in a polite status, rather than falsely claiming an LLM is analyzing. Shared
AIStatusNotice supplies initial not-enabled and safe error presentation.

Only a bounded, strict error response is accepted by this UI; unexpected success,
extra fields or malformed data never produce a completed AI state/model label.
Server message strings are not rendered; fixed shared copy is selected by known
safe code. Every error preserves the synthetic source and derived metadata.
The server's fixed error is <256 characters; client accepts at most 1,024 response
characters. No input/source payload or response is logged or stored.

Unmount and changes to session lifetime/application revision abort and invalidate
the generation; older completion is ignored. Unrelated license-only revisions do
not invalidate application freshness. This UI is **error/readiness-only**: it does
not accept successful outputs or claim full cryptographic digest freshness. Before
a future success UI, compare the returned token using the exact established U02.01
application digest semantics; do not import server-only hashing into a client.

Other module content, nav, seven inert future items and A1 tokens remain unchanged.
No findings grid, result persistence, reviewed overrides, metadata registration,
exports, fabricated recommendation or provider identity appears on public routes.

## Trusted server-only composition, disconnected from public HTTP

`createALAAnalyzer(options = {})` in `lib/server/ala/analyze.ts` returns
`analyze(currentSession, trustedCaller)`. Options have exactly the existing
`createAIRouter` option type; caller uses that router's server-owned hash/request-ID
interface. Injection is trusted server test/composition only, never HTTP JSON.
The public route imports/calls **none** of this module. Default analyzer options
still produce the existing disabled router error.

The composition performs, in order:

1. `buildALARequest` validates current source, freezes the actual `ala/v1` request,
   derives its full application allowlist and captures source token before await.
2. Invoke only `createAIRouter(options)` with `ALA_OUTPUT_CONTRACT` and trusted
   caller. It performs existing reservations/rate/concurrency/provider checks;
   no direct adapter/SDK/provider factory bypass is added.
3. Revalidate generic result envelope, unchanged values, ALA module/prompt identity
   and the existing 64,000-byte generated-data cap.
4. Run `inspectALAResult(envelope.data, capturedRequest.context.deal.applications)`.
   Wrong actual side/ID, membership/evidence or other integrity failure yields
   invalid_model_output with **no envelope/draft** in that error result.
5. Preserve computed complete/incomplete coverage exactly. Missing/not-evaluated
   records stay incomplete; no repair request, missing finding or action is created.
6. Return strict local outcome with original envelope values and captured token.
   No session/deal/derived-result write, provider retry or automatic metadata call.

## Strict outcome dictionary

`ALAAnalyzeOutcomeSchema` / `ALAAnalyzeOutcome` are an unpersisted tagged union:

| Status | Fields / meaning |
| --- | --- |
| `error` | `error:{code:FailureCode,request_id:UUID|null,message:string(1..160)}`; existing fixed server-owned messages, no output or token |
| `success` | `envelope:ResultEnvelope<ALAResult>`, `coverage:ALACoverage` with status complete, `source_token:ALASourceToken` |
| `incomplete` | Same validated draft envelope/token, coverage status incomplete; not complete or approved |

Objects are strict, with existing source/model/envelope bounds. Local coverage
schema describes the established U02.01 coverage fields; only the existing ALA
inspector computes them. Status/coverage and module/prompt identity must agree.
IDs missing from coverage lists are source accounting, not a local recommendation.
Unknown citations and malformed output fail the router/generic adapter; internally
consistent wrong-side outputs additionally fail ALA inspection. All failures use
fixed safe code/message and the router request ID if available; no raw error text.

The captured token is `{session_id,application_revision,fixture_id,
fixture_dataset_version,applications_digest}`. It belongs to the pre-await source.
The server cannot observe later browser-tab edits automatically. Offline tests use
`matchesALASource` against simulated current state: edit/publication/reset invalidate,
license-only change does not. Future consumers must check currentness and label stale
drafts honestly before presenting results. Structural complete is not narrative
grounding, quality, human approval or transaction advice.

## Testing, compatibility and activation gates

`check:ala-action` uses the actual guarded router, new deterministic test transports
and the existing fake usage store **only in the script**. Test policy/model/rate/
approval values are explicitly invented simulation metadata. No fake store/provider
is imported by runtime route or orchestrator. Fake success remains separate from
public reality. Ordinary production code has no live composition/service binding.

Two earlier foundation checks prohibited every API directory. As justified before
editing, their compatibility assertions now allow **only the exact inert route**,
verify its no-argument/static-503/no-import/no-env/body-access properties, and retain
all other API/bypass/client-import/fake-store prohibitions. This supports the newly
authorized unavailable endpoint; it does not suppress real live-boundary failures.

Limits stay 128,000 input bytes, 64,000 generated-output bytes, <=2,048 output tokens,
existing deadlines and no retries. Complete 50+50-app narrative feasibility remains
unproven; mocked output does not establish provider/tokenizer quality. No cap/budget
was raised, app dropped or hidden batching introduced.

Before any real body ingestion/inference: ADR-012 exact paid/open-weight models,
prices/terms/quality approval; trusted anonymous ingress and server request assembly;
real durable atomic usage authorization/recovery; approved independent budgets/rates/
concurrency/fallback caps; provider spend backstops/monitoring/reconciliation; bounded
live-test authority and G5 release approval. Both OpenAI hard stops remain untouched.

U02.03 may later render validated drafts only after a separately approved protected
live path exists and freshness validation is implemented. It must never display
offline fake results, silently approve incomplete output or overwrite the original
LLM draft with a review edit. None of that work starts here.

Rollback: revert this bounded UI/route/orchestration/test/docs change. No schema/key
migration, server-stored data, cloud resource or provider-account state exists.
