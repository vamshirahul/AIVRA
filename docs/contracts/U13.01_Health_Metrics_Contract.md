# U13.01 — Computed dashboard metrics and missing-data states

## Authority and scope

Exact G2 title: **Define computed dashboard metrics and missing-data states**.
Parent: **M13 Integration Health Dashboard** (register shorthand: M13 Integration
Health). G0 purpose: display live summary cards/simple status visualizations from
current demo analysis, TSA and Playbook state; no BI warehouse or enterprise KPIs.
Requirements: **REQ-110 / REQ-111**. Prerequisites: **U01.04 U02.04 U03.02 U07.03
U04.03**. Register acceptance: **Metrics traceable to session; no invented true deal
KPIs**. Plan and register agree. Founder authorization covers U13.01 only.

Deliverable: a typed, versioned read-only metric snapshot and currentness check,
with offline tests. No tiles, charts, navigation/deep links (U13.02), live-update UI
acceptance (U13.03), scenario integration, exports or release work.
The G0 optional scenario comparison is not required for this contract and is not
silently synthesized. No UI redesign or browser interaction is introduced.

ADR-002/003/004/006/009/010 retain server-owned AI, ephemeral session architecture,
guarded spend and honest navigation. A1 theme remains unchanged. ADR-012 model and
ADR-013 hosting/live-release conditions remain gated. Risks RISK-005/006/008 are
addressed through source validation, unchanged arithmetic and explicit freshness.

## health/metrics/v1

`lib/integration-health/metrics.ts` exports browser-safe **types** and the version.
`lib/server/integration-health/metrics.ts` exports `buildHealthMetrics(read)` and
`isCurrentHealthMetrics(snapshot)`. The projection imports no AI router/adapter,
provider, SDK, persistence, UI or transaction writer.

| Field | Definition and source |
| --- | --- |
| source_binding_digest | SHA-256 of the complete input/source binding, including saved reviews and assumptions; not execution authentication |
| source | Session UUID, fixture versions, session revision, independent input revisions and SHA-256 of the full current deal |
| applications | Exact current total, Buyer and Target array counts after complete DemoSession validation |
| tsa | Existing buildTSASummary counts: Total, Planned, Active, At Risk, Completed across all saved records; no list filter, date prediction or status inference |
| ala | Existing projectALAResults coverage and original action-row count; validated saved-review visitor override count, or null when no valid saved review exists; missing/not-evaluated counts |
| reviewed_suggestions | null / not_recorded: existing review records do not track affirmative review of every unchanged action; overrides are not approvals or proof all suggestions were reviewed |
| estimate | Unchanged supplied CSE totals/warnings, CAD minor units and horizon; only when a supplied calculated result matches current reviewed context and current draft |
| playbook | Owner-issued current/incomplete original activity and milestone counts, plus valid visitor-edit count or null if no review supplied |

Every populated metric includes a source path. ALA, estimate and Playbook also
retain their validated original request UUID/input digest for tracing; the overall
snapshot supplies the exact session/source identity. No source names become IDs.
Snapshots are synthetic and illustrative/unapproved, not real transaction health,
verified savings, approval progress, risk scores or confidence percentages.

`current` and `incomplete` contain a value plus trace. Missing states contain
**value=null** plus a fixed reason: `absent`, `outdated`, `invalid`, `unavailable`
or `not_recorded`. Zero is retained only when actually supported. Empty valid TSA
inventory means zero; absent financial output does not. Incomplete CSE amounts
retain nullable totals and original warnings; not-computable estimates withhold
the value. An invalid review is not silently replaced with an empty review.

## Protected sources and calculation integrity

The authoritative synchronous reader supplies the actual current session and
optional module-owned ALA outcome/captured session/review, calculated estimate plus
current financial draft, and the existing protected Playbook review source.
This is an internal trusted composition contract, not a JSON/HTTP import or a
boolean ownership grant. ALA/CSE consistency validation cannot authenticate
arbitrary fabricated model output. Callers must obtain genuine results from the
approved owners. The public route is not wired to this reader in U13.01.

Full session validation reuses buildTSASummary/DemoSessionSchema, including shared
ID uniqueness and relationships. ALA projection validates original context, digest,
coverage and currentness; buildReviewedExport validates original/visitor separation.
The CSE context is rebuilt with prepareCSEContext. The already supplied result must
match that exact context, its draft's buildEstimateRequest and the existing
calculateCSE output. This recalculation verifies consistency only; it cannot create
a metric without a supplied calculated result, infer savings from spend, alter
assumptions or introduce another financial engine. Existing conflicts, missing
amounts and withheld license aggregation remain untouched.

Playbook counts require the actual protected source's currentness, matching full
session identity/revisions and deal digest. Existing projectPlaybookReview validates
optional visitor edits; originals remain unchanged. No recommendations are inferred
from the number of activities or source statuses.

## Snapshot lifecycle and failure

Assembly reads the authoritative reader twice; changed sources between reads fail
`source_changed`. Invalid primary sources, malformed reader composition, size
overflow or exceptions fail `invalid_source`, with no partial snapshot or private
error. Optional invalid/missing results withhold their metric while preserving
independent inventory counts. The complete source binding reuses MAX_CSE_BYTES
as a conservative UTF-8 bound; original session/output bounds are not raised.

Successful snapshots are detached and recursively frozen. A private WeakMap binds
the exact issued object to its reader and complete source digest (including original
results, saved reviews, raw assumptions and current Playbook data), rather than
aggregate counts alone. Imported/cloned snapshots have no currentness authority.
Observed changes permanently revoke that capture; reverting data cannot revive it.
A new explicit build is required. Readers must expose actual changes; changes
that occur and revert between all observations cannot be detected.

No new persistent source store, cross-tab singleton, network transport or activation
grant exists. Genuine protected public AI/result delivery and model quality remain
separately gated; this offline contract does not establish release readiness.

## Validation and rollback

`npm run check:health-metrics` uses existing guarded fabricated fixtures only in
scripts: exact counts/traces, null/zero, original/review fidelity, CSE consistency,
invalid/stale/missing sections, source mutation/reversion, unstable/throwing readers,
immutability and server-only/no-inference boundaries. CI also retains all existing
business and AI regressions. No UI acceptance/browser run is needed in this unit.

Rollback: revert the single U13.01 commit. No data migration, transaction repair,
credential removal or storage cleanup is required. Approved baseline files remain
unmodified/untracked; register mapping and evidence live in U13.01_VALIDATION.md.
