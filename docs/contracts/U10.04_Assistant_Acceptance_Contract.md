# U10.04 — Assistant mutation and failure acceptance

## Approved definition

G2 Implementation Plan v0.1 and `docs/registers/unit-register.csv` define
**Protect assistant from unintended mutation and test failure cases**, parent
**M10 AI M&A Assistant**, prerequisite **U10.03**, **REQ-091 / REQ-093**, effort S.
Exact acceptance: **“Instruction attempts do not alter session; unsafe/unavailable
errors preserve history.”** REQ-091 requires context-grounded gateway answers
without invented facts; REQ-093 prohibits silent portfolio changes/module actions.

The founder's U10.04 packet authorizes offline interaction acceptance and bounded
fixes only. It explicitly retains disabled public Ask until approved protected
per-tab delivery and live activation. It does not authorize new runtime delivery,
providers, persistence, deployment, financial rules, tools or other units.

## Reused architecture and invariant

U10.01 source/reference authority, U10.02 WeakMap owner and guarded router, and
U10.03 presenter/controller/UI remain authoritative and **unchanged**. Tests reuse
their actual code and existing fabricated offline fixtures rather than duplicating
a model, deal schema or inference path. The production route receives no source.

For unchanged authorized context, rejected questions, model output or provider/
control failures must not append, rewrite or delete accepted current history.
The composer retains failed text. Safe error copy cannot reveal private exceptions.
Detected source changes are different: the old result/conversation is permanently
revoked and cannot be displayed as current. Hiding stale results is required, not
an obligation to display invalid history. Returning data to an earlier value cannot
revive an observed revoked context. Mutations hidden and reverted between all
observations remain outside the authoritative reader's detectability contract.

The Assistant never initiates application/license/TSA, review, assumption, scenario
or Playbook changes. Mutation tests explicitly change protected upstream fixtures
as an external visitor/source action; snapshots then prove no Assistant writes.
Reset clears chat only and demands a fresh conversation for subsequent Ask.

## Incremental acceptance coverage

`check:assistant-acceptance` adds interaction coverage to existing context, Ask,
chat, adapter, controls and UI tests. It does not rerun those suites internally.

- Hostile question/source/answer text stays data; system prompt unchanged, prior
  answers are not system roles, unsupported model tool fields fail atomically.
- Thirteen source changes at three timings (before Ask, during provider execution,
  after accepted answer): applications, licenses, TSA, session Reset, ALA original
  metadata, visitor ALA review, financial notes, Playbook availability/review,
  input revision mismatch, missing license findings, invalid upstream outcome and
  invalid primary session. Old handles and display state remain revoked on revert.
- Existing accepted transcript survives provider/timeout/store/settlement failures
  and malformed/unsupported citations, metadata and output fields. No retry or
  unauthorized fallback. Source change during settlement suppresses output while
  preserving accounted usage.
- Paid-budget exhaustion alone permits independent eligible fallback; disabled
  fallback, rate and concurrency refusals remain guarded. Double submit and pending
  repeated Reset do not dispatch extra calls or restore late answers.
- Existing 2,000-character question, 4,000-character answer, 20-citation,
  four-exchange and 32,000-byte history rules remain unchanged. Actual multibyte
  history overflow preserves the prior transcript; nothing is clipped.
- Foreign/serialized owner handles, absent caller authorization and disabled AI
  fail safely. U10.02 continues exact envelope/provenance mismatch testing.

The shared offline chat fixture exposes source replacement, model-output/provider
hooks, policy/store composition, captured requests and a monotonic fake clock.
These hooks exist only in `scripts/`. Advancing test time past lease/rate windows
does not refund retained exposure or change production guard policies. Each fake
policy/store remains isolated and no external model requests are permitted.

The existing Chromium harness is extended to verify failures **after** an accepted
answer: transcript, prepared question and deal state survive, with accessible safe
alerts. It retains populated isolated and honest public-disabled checks at
1440/390/320, keyboard/focus, ordered history, Reset, injection-safe React text,
citation/provenance labels, source invalidation and unmount behavior.

## Acceptance layers and limits

Backend mocked acceptance, isolated component interaction, actual public unavailable
behavior and live-model quality are reported separately. No public Ask/real-model
grounding, semantic injection resistance, calibrated accuracy or transaction advice
is claimed. Structural reference membership is not narrative truth.

No dependency or security-sensitive contract change is required. No baseline status
or source file is rewritten; explicit founder authorization supersedes only this
unit's historical planning-only register text. Revert the bounded U10.04 commit to
roll back tests/docs; no transaction or storage migration exists.
