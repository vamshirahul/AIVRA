# U13.03 — Dashboard update acceptance

Exact approved G2/register title: **Verify live updates across scenario/TSA/ALA
session edits**. Parent: M13 Integration Health Dashboard. Dependencies:
**U13.02 U11.02**. Requirements: **REQ-110 REQ-111**. Acceptance: **TSA and reviewed
results updates correctly propagate; no model calls on dashboard view**.

This unit adds update/interaction acceptance using existing U13.01/U13.02 and
U11.02 operations. It does not add scenario tiles, protected public delivery, AI,
new financial rules, persistence, polling, deployment or another unit.

## Source operations and evidence

- Applications use existing shared-session publishApplications for adding/removing
  an unlinked synthetic record, updateApplication for edits, current publication
  tokens and existing orphan protection. No creation/deletion rule is invented.
- TSA uses existing updateTSA and Reset; all five portfolio counts are compared to
  buildTSASummary, independent of active list filters. Rapid sequential updates
  must render one coherent current count set.
- Original ALA replacement comes through createALAAnalyzer with existing guarded
  offline transports. saveReviewOverride records explicit visitor changes without
  altering original actions; old financial context becomes outdated.
- Scenario changes use cloneBaseline, editAlternativeFinancialInput,
  editAlternativeHorizon and compareScenarios. Existing CSE results/drafts are
  checked by U13.01, without implementing scenario metrics or another calculator.
  Dirty assumptions withhold old totals; missing amounts retain null/warnings;
  signed CAD and explicit zero remain unchanged.
- Playbook changes use actual owner.generate, createPlaybookReviewSource and
  savePlaybookEdit. New source identities and visitor edits are separate. Financial
  source changes revoke the previous plan through its actual owner reader.

Every captured health snapshot is issued by buildHealthMetrics. Tests use
isCurrentHealthMetrics, including same-object invalidation, revision-only changes,
invalid/unavailable source, Reset and data reversion. Observed revoked objects must
not regain currentness. Provider counters must remain unchanged during metric
assembly/currentness checks; explicit mocked generation is test setup, not a view
side effect. No real provider/network requests are permitted.

## Browser layers

The existing Chromium/CDP harness accepts opt-in AIVRA_HEALTH_UPDATES and development
AIVRA_HEALTH_UPDATES_ONLY. Only scripts/ignored loopback fixtures use these switches;
there is no production query, injected owner, endpoint or configuration change.
Owner-issued offline snapshots are serialized only as fabricated test display
specimens. The loopback delivery emulator is not server ownership or genuine
browser transport; actual ownership is verified separately in Node. Its revocation
set prevents replay of old display fixtures after observed change.

Isolated actual components cover protected result sequences, application publication,
TSA status transitions, batched changes, unavailable/invalid states and Reset.
The final local public application separately covers keyboard navigation, actual TSA
editing/filtering, returning current counts and Reset using a disposable synthetic
browser-tab session. No production source fixture/business file is modified.
Existing 1440/390/320 layout/AX/focus/link checks remain in the harness.

Public ALA/CSE/Playbook delivery remains **BLOCKED** pending approved protected
transport. No public successful analysis or live-model quality is claimed. Source
readers must expose changes; hidden changes reverted between observations cannot
be detected. Native AX/keyboard/viewport checks are not a manual screen-reader or
physical-device certification.

## Boundaries and rollback

No runtime change is required unless a focused acceptance test proves a defect.
U13.01 contracts, formulas, model/routing/budget controls, TSA statuses, Playbook and
review semantics, session persistence and inert features remain unchanged. Approved
baseline documents remain untracked and byte-for-byte preserved.

Rollback: revert the single U13.03 test/docs/registration commit. No transaction
migration, runtime data repair, credential cleanup or cloud action is necessary.
