## Typed structured context and unchanged boundaries

The generic strict InvocationSchema gains exactly one optional typed field:
`context.playbook: PlaybookInputSchema`. It is required for module=playbook, and
forbidden for ala/licenses/assistant. Playbook also requires prompt_version=playbook/v1,
the exact server-owned PLAYBOOK_SYSTEM_PROMPT, no user_text field, and the exact
allowlist of supplied deal application IDs followed by TSA IDs. No user_text length
change, arbitrary JSON override, string packing, truncation or visitor-selected schema.
Old ala/license/assistant request shapes retain their behavior.

The unchanged U04.01 input shape/constants/type are extracted into server-only
`input-schema.ts` and re-exported at the original input.ts paths. This avoids an
otherwise circular dependency through ALA orchestration/router/adapter. No field,
version, parser semantics or existing source contract changes. The extracted schema
depends only on existing client-safe source/review/scenario/CSE schemas, not AI calls.

Invocation refinement validates the existing complete SyntheticDealFixtureSchema,
all existing record limits and cross-links, exact domain application/TSA arrays,
fixture identity, full-deal digest, scenario+selection digest, review digest binding,
and genuine allowlist membership/order. Structured source consistency is not model
execution attestation or permission to promote an imported export/file into trusted
server evidence. `buildPlaybookInvocation` always calls preparePlaybookContract from
original protected U04.01 inputs; no public body is parsed into that builder.

The full deal is retained, including linked licenses, to preserve existing generic
source validation and CSE freshness. The nested Playbook object deliberately
duplicates application/TSA source records. The duplicated byte cost is measured,
not hidden. No source rows or assumption notes are dropped.

For Playbook, validateInvocation rejects normalization and enforces the unchanged
128,000-byte full invocation plus output JSON-schema ceiling. The unchanged router
then applies the configured policy maximum, which cannot exceed that ceiling.
Earlier U04.01 domain/schema/prompt checks still run. Requests that do not fit fail
request_too_large before reservation/dispatch; no splitting, partial request, cap
increase or retry. Source session ceiling remains 512,000 characters.

The SDK transport needs no change: its existing untrusted_context JSON includes
the typed object directly, separately from server system instructions. Existing
store:false, maxRetries:0, abort and <=2,048 output-token bound remain. An actual
SDK MockLanguageModelV4 check verifies that exact structured object reaches it.

## Explicit protected owner

`createPlaybookGenerator(options={})` constructs the unchanged createAIRouter once.
The only generation path is `await invoke(request, PLAYBOOK_OUTPUT_CONTRACT, caller)`.
Adapter imports in request.ts/generate.ts use only validateInvocation for preflight;
neither can call createAIAdapter or a provider. Router accounting/lease/policy code,
SDK transport and OpenAI factory remain byte-for-byte unchanged.

Owner methods:

- `generate(readSource, caller)` deliberately prepares and requests a new draft.
- `regenerate(prior, readSource, caller)` deliberately requests another draft from
  latest sources. Prior must be an exact outcome object issued by this owner.
- `isCurrent(prior, readSource)` checks issued ownership and latest source equality.

`readSource` is a required synchronous function owned by trusted server composition,
returning the latest PlaybookInputs from the authoritative protected source owner,
or null. A raw snapshot argument is not accepted. It must supply original validated
ALA outcome/capture, saved review, current session/financial draft/scenario and explicit
scenario selection. A recycled closed-over snapshot is not an authoritative reader;
the function type cannot enforce honesty. No such successful protected production
source owner exists on the public page today. No public ingestion/attestation is added.

Each call creates its own server UUID and forwards only the validated client_key
with that UUID. Callers cannot supply/reuse a request identity or choose prompts,
models, transport, allowlist or output schema. Options are trusted server-only
composition; successful execution today requires explicit offline-test policy,
fake usage store and fake transports/SDK model. Defaults are disabled.

Flow:

1. Read authoritative source; prepare immutable U04.01 input and full invocation.
2. Read source again immediately before the sole await and compare the complete
   captured input using matchesPlaybookInput.
3. Enter the unchanged guarded router. Reservation, per-client/global rate and
   concurrency, independent paid/fallback budgets, fixed provider identity, timeouts,
   worst-case accounting/usage settlement all still apply.
4. Immediately after the await, obtain a fresh authoritative read and compare again.
   Reset, session/input revisions, application/license/TSA edits, unversioned source
   changes, review justifications, financial notes/scenario edits/selection changes
   withhold acceptance. Reader unavailability also fails safely.
5. Validate full PlaybookEnvelopeSchema, exact request UUID/digest, module/prompt,
   selected policy provider/model/mode/fallback reason and unchanged metadata. The
   captured Playbook input must equal the invocation's own structured context.
6. Call inspectPlaybookResult for every source path, side/subject, structural graph,
   identity/date and actual coverage checks. Reject rather than repair or retry.
7. Return a frozen success/incomplete outcome only after all validation. No session
   registry, original ALA, visitor review, source record or scenario is written.

Source checks bracket all awaits in this orchestrator. Changes during the router's
internal store/provider/settlement awaits cause the returned draft to be withheld.
Already authorized/dispatched work remains accounted by the router even when stale;
source invalidation does not release budget or trigger another call. No changes to
reservation/settlement semantics are introduced to cancel or refund such work.

## Outcome and regeneration semantics

Strict PlaybookOutcomeSchema:

| Field | Meaning |
| --- | --- |
| status | error, success or incomplete; never approval or execution |
| operation | generate or regenerate, for accepted outcomes |
| envelope | Unmodified guarded-adapter data/provenance/usage envelope, module playbook / prompt playbook/v1 |
| coverage | Actual missing app/TSA/action IDs, not_addressed and incomplete context; complete only as structural coverage |
| source | Captured exact U04.01 session/fixture/revisions and source/review/scenario digests |
| error | Fixed code/request_id/message only; no source IDs, raw provider/store exceptions or metadata |

Local safe error codes source_changed and invalid_previous_draft are action-local;
the shared AI error vocabulary and client display contracts are not expanded.
Provider/guard failures reuse existing fixed shared error messages. Full generated
envelope is bounded to 64,000 UTF-8 bytes; the existing generated-data cap remains.
No model-authored provider metadata is accepted inside generated data.

A private WeakMap records outcome object -> captured input only for this protected
owner's accepted outcomes. It is not persistence, an exported trust token, or a
history store. Parsing/cloning a result cannot authorize Regenerate or isCurrent.
The pure exported validatePlaybookEnvelope helper never grants owner-issued status.

Regenerate is a new fully budgeted request with a fresh UUID, not a discounted
continuation. It can deliberately refresh an old issued draft using changed current
sources. It never reuses the old captured invocation. Failure returns an error and
does not mutate/replace the prior immutable object; isCurrent can still revoke that
prior draft after source changes. Consumers must check currentness at point of use.
No automatic generation on source updates, typing, navigation, refresh, Reset,
provider failure or fallback; no repair call or provider-error retry/failover.

## Public availability UI and endpoint

G2 explicitly requires an action, so /playbook-generator now has one primary
Generate playbook button. A1 Coastal Navy classes already used for ALA readiness
are reused without token/style changes. Copy states live Playbook AI is not enabled,
no draft has been generated and no deal data is sent. Regenerate is explained as
unavailable because no actual validated public draft exists; no pretend enabled
regeneration control, result grid, editor or export is added.

On an explicit click only, one POST goes to /api/ai/playbook with no body, credentials,
dataset/source token, model selection or authorization. Repeat clicks are suppressed
by an immediate controller ref and disabled state. There is a ten-second abort,
unmount cleanup and session-lifetime/revision/ticket guard against stale completion.
Checking availability is the only pending status; never Generating or fake progress.
Only the fixed-shaped 503 failure is accepted. Malformed or successful-looking
replies produce an honest failure message; response content never renders as HTML.

The route has zero imports, request arguments/body/header reads or environment checks,
and always returns fixed 503/no-store with ai_controls_not_ready, null request_id.
GET is 405. Neither env=true nor hostile headers/body can enable it. The original
ALA readiness route is unchanged. Neither endpoint imports the generation owner,
router, provider or test fakes. No successful public inference path exists.
