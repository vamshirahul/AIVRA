# U11.03 — Scenario provenance, stale warnings and export

In review; not release approval. Exact approved G2: **Surface scenario provenance,
stale warnings and compact export**; dependency **U11.02**; **REQ-102 REQ-103**.
Exact register acceptance: **Differences/limitations identifiable; download
preserves both scenarios**. G2 section 3 specifies CSV/JSON tables; approved ADR-008
includes M11. JSON and CSV follow that baseline; the particular typed-row CSV layout
below is an implementation choice. No PDF, import, additional scenario or persistence.

## Existing source, calculations and provenance

The real public `/scenario-modeling` still mounts ScenarioWorkspace with no source
or currentness grant. It has readiness links, no populated comparison, mock result
or download controls. U11.03 does not provide a trusted ALA/CSE result owner, inference
authentication, a public API or a saved-scenario flow. Existing ALA POST remains
unconditional 503/no-store; live providers stay disabled.

The protected workspace retains its original session/source/review/CSE-baseline key,
record digest checks, immediate old-editor unmount and TSA-only dependency semantics.
Only this verified owner supplies `exportAuthorized=true`; a direct ScenarioEditor
defaults false. A caller supplying its own source/flag violates the trust boundary.
Schema/digest equality and opaque permits do not establish genuine AI execution.

The original **scenario/draft/v1**, **scenario/comparison/v1** and
**cse/calculation/v1** schemas/functions remain untouched. Both original CSE outputs
and six original comparison differences are retained, never postprocessed into
supported savings. Missing values remain null; zero and negative net remain exact
integer CAD minor units. Differences may span ±2×MAX_MINOR, as already supported by
U11.02. Annual, once-only and horizon units are explicit; differing/unknown horizons
retain null reasons. Conflicting spend, excluded lines, incomplete coverage and
numeric license withholding remain unchanged. Disposition hypotheses never price
themselves or create a new AI review identity/digest.

The comparison disclosure shows exact available original model/provider/mode,
request/input digest/prompt/generation time, source session/fixture/dataset/schema,
app/license revisions, source/review digest, original findings/rationales/evidence/
uncertainty and baseline visitor overrides. Missing optional fallback reason is
Unavailable / not supplied. It does not invent model dates, confidence, approvals,
usage metadata absent from the existing projection, or an alternative model run.
Alternative hypotheses and financial assumptions remain explicitly visitor supplied.
Long finding details are native disclosures, not a full raw JSON/session dump.

## Permission and snapshot lifecycle

`lib/scenario-modeling/scenario-export.ts` provides:

- `captureScenarioExport(source,scenario,comparison,authorized,unsaved)`: requires
  exact true/false authority and zero unsaved inputs after an explicit successful
  Compare; validates with unchanged validateCurrentScenario and
  validateCurrentComparison against original source. The latter may recalculate
  only at capture for consistency. Computed/incomplete supported results can export;
  invalid, not-computable, tampered, mismatched or oversized snapshots cannot.
- A frozen opaque in-memory permit in a private WeakMap binds the detached,
  recursively frozen artifact to exact source/view, scenario and compared bytes.
  No imported JSON can reconstruct this permit or become a trusted result.
- `revokeScenarioExport`: removes permit authority. UI holds the live permit in a
  ref so invalidation is synchronous. A synchronous dirty-key set prevents stale
  event closures comparing/exporting old saved values before a form state commit.
- `prepareScenarioDownload`: requires the live permit and identical current
  source/scenario/comparison plus current owner grant and no unsaved edits. Any
  mismatch, revoked authority or unsaved input destroys the permit; reverting data
  does not revive it. Serializes only the captured snapshot, with **no calculation
  or recapture on download**. Unsupported formats produce a safe error.
- `downloadScenarioComparison`: existing CSE/ALA DownloadPort + Blob/object URL/
  temporary-anchor cleanup pattern. No IO until preparation succeeds. Anchor removal
  is in finally; URL revoke is deferred after success and immediate on failures,
  including cleanup-scheduling failure. Errors never include raw exception text.

Every raw note, disposition, destination, amount, inclusion and horizon edit removes
the comparison/provenance/download surface and revokes its permit. Failed Save,
successful Save/Restore/reset, another Compare (including failure), source change,
failed currentness or unmount also revoke. Reverting typed text alone stays dirty;
Save/Restore plus another explicit successful Compare is required. Layout-effect
cleanup revokes on unmount. TSA-only changes retain authority when cost inputs remain
current. Navigation/refresh loses everything; no new session key or event bus.

Stale/unverified source shows a visible warning and prerequisite recovery links;
unsaved/edited comparison status explains revocation. Current unsupported results
show disabled download buttons with an explanation. Product reports only Download
initiated, not a guarantee that a browser wrote a file.

## Canonical JSON dictionary

Strict **scenario/comparison-export/v1**. UTF-8 application/json;charset=utf-8;
fixed filename **aivra-scenario-comparison-v1.json**. No export timestamp or
user-controlled filename. Identical captured snapshots give deterministic bytes.

| Field | Meaning |
| --- | --- |
| contract_version | scenario/comparison-export/v1 |
| artifact_kind / illustrative_unapproved | scenario_comparison / literal true |
| disclosures | Three fixed synthetic/hypothetical/unapproved, original-versus-visitor and financial-limitation statements (SCENARIO_DISCLOSURES) |
| units | Existing CSE export units for annual, migration, transition, once-total, horizon savings, net benefit and whole years |
| scenario | Exact original scenario/draft/v1: source binding, immutable original/effective baseline, raw/canonical assumptions for both sides, alternative action hypotheses/reasons |
| comparison | Exact original scenario/comparison/v1: both full unmodified CSE results, differences, horizons, warnings, changes and unquantified actions |

The two original CSE contexts retain reviewed original ALA evidence/rationale/
uncertainty/coverage/model provenance and effective visitor overrides independently.
Only necessary existing calculation/review/source context is serialized. No redundant
DemoSession, TSA, raw license inventory, cookies, credentials or environment. Existing
context duplication inside U11.02 is retained for parity, not duplicated again as
a new provenance tree. There is no artifact reader/import-to-trust operation.

## Human-readable CSV with complete structured detail

UTF-8 text/csv;charset=utf-8; **aivra-scenario-comparison-v1.csv**. Every cell quoted,
internal quotes doubled, CRLF rows and final CRLF. Exact columns:

```text
record_type,layer,key,status,unit,amount_minor,reason,id,detail_json,description
```

| Typed row | Detail / reconstruction |
| --- | --- |
| metadata | Root fields other than scenario/comparison; units and fixed disclosures |
| scenario | Full scenario, preserving both sides' raw/canonical assumptions and original/effective/hypothetical distinction |
| baseline_result | Original comparison.baseline_result including evidence/context/warnings/conflicts/exclusions |
| alternative_result | Original comparison.alternative_result with unchanged original reviewed context |
| comparison | All comparison fields except the two result rows above (avoid duplicating large evidence again) |
| metric | Eighteen readable rows: six metrics × baseline, alternative, alternative_minus_baseline; exact integer amount/null, status, units, original difference reason |
| hypothesis | Each changed action: readable proposed disposition/subject ID plus exact finding/action/side/destination/reason/baseline interpretation in detail_json |

Preserve every typed row. Reassemble root metadata + scenario + comparison with its
two result fields for lossless JSON parity. Metric rows summarize existing values,
never calculate money. Side null reason is unknown_in_original_result; original
component reasons/warnings remain in its full result row. Known monetary cells are
signed integers including 0; unknown is literal null, never empty or default zero.
Non-monetary empty cells mean that column is not applicable to that typed row.

Text starting with whitespace/Unicode format characters then =,+,-,@, or leading
tab/CR/LF, gains an apostrophe before quoting. Only validated signed integer/null
amount_minor cells bypass formula sanitization; legitimate negative net/deltas remain
numeric. Dangerous raw subject IDs gain a prefix, while exact IDs remain unchanged
inside JSON-bearing cells and canonical JSON. Quotes, commas, newlines, Unicode and
controls within JSON strings round-trip via JSON escapes. Unsupported raw C0 controls
reject safely. Import spreadsheet data as text where needed; behavior varies across
spreadsheet applications. No spreadsheet/CSV importer is introduced.

## Bounds, evidence and limitations

Capture and each complete UTF-8 download use unchanged **MAX_CSE_BYTES=1,500,000**.
Wrapper/scenario overhead can prevent capture although comparison is valid. CSV
quote expansion may exceed the limit while JSON fits; refuse the complete CSV before
Blob allocation. No partial output, truncation, splitting or raised caps. Size failure
does not grant another artifact; a JSON download from the same valid permit remains
possible if it fits. Fixed safe unavailable/too-large/browser errors retain inputs.

Nine focused offline groups cover parity, immutability, versions, original visitor
overrides, structured CSV reconstruction, ±2×MAX differences, unknowns/horizons/
coverage/exclusions/conflicts, malicious formula/control text, permits/tampering/
freshness, cleanup and real oversized evidence. Original server composers validate
fabricated specimens; no AI/provider/network calls. Existing suites run once in final
CI. Optional AIVRA_SCENARIO_EXPORT_BROWSER=1 extends the existing loopback harness:
actual keyboard downloads inspected on disk against Blob MIME/bytes/filename,
staleness/overflow failure and 1440/390/320 layouts. Ignored .temp/u11-03 only;
actual public production readiness page remains unpopulated.

No genuine populated public AI UAT, full screen-reader/WCAG/physical-device audit,
production authentication, live AI, quantitative license savings or G5 release claim.
No dependency/cloud/persistence/extra scenario. Rollback: revert the nine U11.03 files;
no migrations, credentials, resources or changes to approved baseline documents.
