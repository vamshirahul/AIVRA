## Source validation and pure handoff

buildTSASummary reads the complete current DemoSession, not filtered inventory rows.
It validates original DemoSessionSchema, existing 512,000-character session limit,
identity/version/record limits and full reference integrity. Deep equality rejects
silent normalization/unknown-property stripping. Malformed source, duplicate IDs,
missing applications or invalid TSA fields make the entire summary unavailable;
no partial/dropped-row summary or invented zero counts. Original schemas, fixture,
session/controller/provider and revisions remain unchanged.

Strict **tsa/summary/v1** is the source-revision-bound dashboard handoff:

| Field | Meaning |
| --- | --- |
| contract_version | tsa/summary/v1 |
| source.session_id / fixture | Exact current lifetime and fixture ID/schema/dataset versions |
| source.session_revision | Full source session revision, also conservatively guards unrelated concurrent changes |
| source.tsa_revision / application_revision | Current independent source revisions |
| scope / synthetic / unapproved | all_current_tsa_services / true / true |
| counts | total, planned, active, at_risk, completed; each integer 0..100 |
| services | Complete current original TSA records, unchanged order/fields/IDs/dates/status/nulls/optional relationships |
| linked_applications | Only referenced current app IDs, company_side and app_name, each once in application source order |

Counts increment from explicit source enums only. **total = planned + active +
at_risk + completed = services.length**. Empty valid inventory yields five factual
zeros; missing/invalid source yields Unavailable. Schema refinements check counts,
uniqueness and the exact relationship-ID set. No date/risk/financial calculations,
AI output or derived health result is created. No redundant source bus or persistence.

The summary graph is detached and recursively frozen. It contains no unreferenced
app inventory, application financial/owner/notes, license amounts/records, TSA draft,
AI results, environment/cookies/secrets or full DemoSession. Validation may inspect
the full input, but only necessary TSA/link/source metadata is serialized.

## Export contract, exact fields and formats

Strict **tsa/summary-export/v1** wraps `{contract_version,disclosure,summary}`. The
fixed disclosure marks synthetic fictional/unapproved source and explicitly rejects
verified contractual/risk/exit-success claims. No invented generation/export timestamp.
Same source snapshot produces deterministic bytes.

JSON: application/json;charset=utf-8; **aivra-tsa-summary-v1.json**. Lossless source
TSA services and exact referenced app evidence; omitted related_app_ids stays omitted,
[] stays recorded-empty, nulls remain null and raw source statuses/dates unchanged.

CSV: text/csv;charset=utf-8; **aivra-tsa-summary-v1.csv**. All cells quoted, embedded
quotes doubled, CRLF records and final CRLF. Exact nineteen columns:

```text
record_type,export_version,source_json,disclosure,counts_json,tsa_id,title,provider,
recipient,owner,start_date,end_date,source_status,exit_milestone,risk_notes,
relationship_state,related_app_ids_json,linked_applications_json,source_record_json
```

The first summary row carries export version, exact source versions/identity,
disclosure and counts. Following service rows preserve source order and readable
fields. Null owner/dates display Unknown; null milestone/notes Unknown / not supplied.
These labels are human summary text; **source_record_json** retains exact null versus
literal-string distinctions and every original source field/ID/value. Preserve it.

relationship_state is not_supplied, recorded_empty or recorded_links. Omitted
relationship information uses not_supplied in the structured link cells; recorded
empty arrays use []. Recorded IDs remain exact JSON arrays; linked_applications_json
lists exact current names/sides/IDs in each service's reference order. Empty full
inventory exports a summary row only, not a fabricated service.

Text cells starting with whitespace/Unicode format characters then =,+,-,@, or
leading tab/CR/LF, gain an apostrophe before CSV escaping. Dangerous raw IDs/text
remain exact within structured JSON fields and canonical JSON. Quotes, multiline
Unicode and JSON escaped controls round-trip. Unsupported raw C0 controls reject
the CSV atomically; JSON escapes them. Invalid source text requiring normalization
fails before export. Spreadsheet import-as-text may be appropriate; no importer added.

## Byte bounds, currentness and download lifecycle

Both complete downloads use **MAX_TSA_EXPORT_BYTES=512,000 UTF-8 bytes**, reusing
the existing numeric session ceiling conservatively for output bytes. The existing
source cap is 512,000 characters; it is not raised or confused with output bytes.
Unicode/quote expansion can make valid source too large to download. Refuse the
whole artifact before Blob allocation, without truncation/splitting/partial content.
JSON exactly at 512,000 bytes passes; 512,001 fails, covered by focused regression.

Download is a deliberate button action. The tracker reads the latest controller
getSnapshot on every attempt; it does not use a cached React session or old artifact.
Opening Add/Edit immediately disables export using both UI state and latest-draft
ref; invalid/stale drafts remain blocked until Save/Cancel. The entire saved source
exports regardless of status filter, with explicit coverage text.

downloadTSASummary accepts a current mounted-owner reader. It captures/validates,
prepares fixed content, rereads complete summary identity/content before allocating
resources and again immediately before anchor.click. Session/app/TSA revisions,
Reset/lifetime, link/name/content changes (even unversioned), draft opening or unmount
reject a pending attempt. No asynchronous preparation, cached permit or replay/import
path. UI mount ref is cleared on unmount and reset in effect setup for Strict Mode.
Later changes do not rewrite a file correctly dispatched from its captured source.

Existing DownloadPort/Blob/object URL/temporary-anchor pattern is reused. Anchor
removal is in finally; successful URL cleanup is deferred, failure cleanup immediate.
Safe unavailable/too-large/browser messages never expose raw exceptions or claim
disk persistence; product says Download initiated. Existing storageAvailable=false
adds a memory-only/refresh-loss notice. No new key, network or storage write.

list are reused. All other module routes and seven inert Future Features are preserved.
