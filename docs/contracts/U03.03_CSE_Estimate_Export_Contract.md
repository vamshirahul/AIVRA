## Trust, eligibility and calculation lifecycle

The public `/cost-synergy` page still receives no protected context/currentness grant.
It shows no validated ALA analysis, financial controls, fabricated results or download
buttons. The existing ALA endpoint remains unconditional 503/no-store. This unit
adds no result delivery, successful public inference or export-import pathway.

The existing protected `CostSynergyEstimateWorkspace` retains its exact source/
review/record keys and asynchronous digest verification. Only its current mounted
editor gets `exportAuthorized=true`; direct editor composition defaults false.
All financial input edits synchronously revoke the current export permit, including
note, inclusion and horizon edits. Restoring the previous text does not restore
export authority: another explicit Calculate is required. Reset and calculation
failure clear authority. Source/review/result/currentness changes unmount the owner
and revoke its permit; TSA-only changes retain the existing dependency lifetime.
Previous comparison snapshots are never offered independent download buttons.

`lib/cost-synergy/estimate-export.ts` provides:

- `captureEstimateExport`: after explicit Calculate, requires owner authority,
  computed/incomplete status and exact context/current draft/request binding. It
  checks full equality against the unchanged calculator **at capture time**; this
  consistency check is pure and preserves the original result, with no AI call or
  changed equation. Invalid/not_computable/forged output receives no permit.
- An opaque, frozen, in-memory permit backed by a private WeakMap binds a detached
  immutable artifact to exact raw draft and context identities. It cannot be
  serialized/reconstructed from JSON. `revokeEstimateExport` removes its authority.
- `prepareCSEDownload`: requires the same current owner authority, live permit,
  exact raw draft and context. Serializes only the previously captured result;
  **never recalculates on download** or silently fixes inconsistent amounts.
- `downloadCSEEstimate`: deliberate browser Blob/object-URL/temporary-anchor action,
  with the existing ALA DownloadPort pattern and cleanup on success/failure.

These checks are structural/lifecycle integrity, not authentication of inference.
The protected owner must still obtain genuine validated outcomes from the server
composition boundary and refresh/revoke currentness. A caller inventing its own
context/authority violates that boundary; no public way to do that is added.
No file reader can turn an exported artifact into trusted model provenance.

## JSON contract

UTF-8 `application/json;charset=utf-8`; filename **aivra-cse-estimate-v1.json**.
Deterministic bytes for the same calculated result; no export timestamp or unsafe
user-supplied filename portion. Wrapper version **cse/estimate-export/v1**, strict
`CSEEstimateExportSchema`; calculation version stays **cse/calculation/v1**.

| Field | Meaning |
| --- | --- |
| contract_version | cse/estimate-export/v1 |
| artifact_kind | cse_estimate |
| illustrative_unapproved | literal true, never approval/execution |
| disclosures | Exact three strings below |
| units | Exact annual/migration/transition/once-total/horizon/net/year descriptions |
| estimate | Original strict CSEResult, status computed or incomplete only |

Exact disclosures:

1. Illustrative, unapproved estimate; not a forecast or verified savings.
2. Synthetic/test data only. Amounts are visitor assumptions, not AI-generated financial facts.
3. Incomplete coverage and unknown or conflicting amounts must not be treated as complete portfolio savings.

The original result retains its request, exact integer CAD minor-unit assumptions,
units, inclusion/exclusion flags, attribution and spend roots, action/finding/subject
IDs and sides, basis notes, horizon, totals, line states/reasons, warnings/conflicts,
source identity/digest/revisions, review identity/digest and context. Context retains
original ALA analysis, original recommendations/rationale/evidence/uncertainty,
effective visitor overrides/destinations/reasons, coverage/missing/not-evaluated
records and genuine supplied model/request/prompt/generation provenance separately.

Only this bounded necessary calculation/review/source evidence is serialized: no
redundant DemoSession, TSA records, license inventory, cookies, environment or keys.
Source application costs remain evidence; nothing automatically becomes savings.
CSEResultSchema reuse validates shape, not standalone financial authenticity;
the capture check separately verifies actual calculator equality. No reader/import.

## CSV table view

UTF-8 `text/csv;charset=utf-8`; filename **aivra-cse-estimate-v1.csv**. Every cell is
quoted, internal quotes doubled, CRLF records and final CRLF. One **summary** row
precedes source-ordered **line** rows. Preserve the summary row: it carries source,
review, original/effective ALA context/provenance, coverage and estimate limitations.

Exact columns:

```text
record_type,export_version,calculation_version,status,illustrative_unapproved,
currency,money_unit,units_json,disclosures_json,source_json,review_identity_json,
review_digest,context_json,warnings_json,conflicts_json,horizon_years,
annual_recurring_savings_minor,migration_one_time_cost_minor,
transition_overlap_cost_minor,one_time_total_minor,horizon_recurring_savings_minor,
illustrative_net_benefit_minor,line_id,included,request_line_json,calculated_line_json
```

Summary carries exact totals as integer cents, literal **null** for unknown monetary
values/horizon and numeric 0 for explicit zero. Negative net remains a signed integer.
No numeric formatting, conversion, recalculation or rounding. Known one-time totals
survive incomplete annual data only when the calculator actually supplies them.
Line rows carry exact request/result JSON: all input units/basis/notes and references,
excluded flags, source costs, line states, calculated components and reason codes.
Aggregate-only columns are blank on line rows, never implied line-level zeros.

Text beginning with whitespace/invisible separators then =,+,-,@, or leading tab/
CR/LF, receives an apostrophe before CSV quoting. The seven known numeric summary
columns allow only validated signed integers or null without that prefix, preserving
legitimate negative net values without allowing expressions. Dangerous raw IDs may
gain a protective apostrophe; exact IDs remain in structured JSON cells and canonical
JSON. Structured strings/embedded commas/quotes/newlines/Unicode are lossless through
JSON plus CSV escaping; no evaluation. Unsupported raw C0 controls reject safely.
Spreadsheet behavior varies: import as text where necessary. No CSV importer exists.

## Limits, errors and resource cleanup

The artifact and each output use the existing **1,500,000 UTF-8 byte** CSE cap.
Wrapper overhead/repeated evidence/CSV quote expansion can exceed it. No partial
file, silent omission, truncation, splitting or cap increase. An invalid/oversized
capture yields no permit; oversized CSV preparation yields export_too_large before
Blob/URL creation. Fixed export_unavailable/download_unavailable errors never expose
exception/model text. Both buttons are secondary and keyboard accessible, appear
only beside the current result, and follow existing A1 responsive/focus styles.

Download allocates a Blob/URL only after all checks. Temporary anchor is removed in
finally. Successful click schedules URL revocation on the next task; failures revoke
immediately, including failed append/click/remove/cleanup scheduling. Report only
**Download initiated**; browser/disk saving is not asserted by the product. Cleanup
is the only scheduled work. No provider request, telemetry or persistent state.
