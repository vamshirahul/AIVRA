## Server-only composition and source authority

All three lib/server/assistant modules import server-only. `buildAssistantContext`
requires a synchronous authoritative `AssistantSourceReader`, returning latest
current session and optional protected upstream inputs. No HTTP/file/import reader
or public source promotion exists. Session source data is validated with the actual
DemoSessionSchema and existing512,000-character/session/record/reference limits,
without normalization, fallback fixture, name-based matching or silent repair.

Optional ALA/license outcomes must originate in the existing protected execution
path. Existing projection/inspection functions verify structure, digests, source
IDs, evidence, coverage and metadata; they do **not authenticate** arbitrary JSON
as genuine execution. A caller inventing outcomes or dishonest stale reader breaks
trusted composition. No successful protected public result source exists today.
Playbook retains its stronger original issued-object owner through U04.03's actual
PlaybookReviewSource, not a client flag or imported schema-valid result.

Assembly reads the owner twice and compares the entire assembled context. It
returns a detached recursively frozen snapshot and privately registers object
ownership in a WeakMap. `isCurrentAssistantContext` rebuilds from latest protected
inputs and compares the entire context, including source lifetime/fixture/session/
input revisions/full deal digest, saved reviews, assumptions, Playbook source and
provenance. Any mismatch/error/revoked section permanently invalidates the old
capture. A new explicit capture is required; data reverting cannot revive it.
Checks cannot detect mutations never exposed by a dishonest reader or occurring
and reverting between observations. Later Ask must check before/after every await.
Parsing/cloning context, hashing data or supplying authorized=true never registers
ownership. No serialized token, database, session write or new storage key exists.

Optional sections are either `{state:current|incomplete,data:...}` or strictly
`{state:absent|outdated|invalid|unavailable}` with **no data payload**. A missing
result is not a computed zero or successful empty analysis. Invalid/stale/error
optional results are excluded with explicit labels; an invalid primary session
fails the whole capture. Missing/malformed ALA review retains current original
ALA but sets reviewed=null and labels its review; no default saved review is
invented. Invalid Playbook review withholds its section entirely. Missing review
remains null rather than synthesizing visitor confirmation. Incomplete results
remain available only with original coverage and explicit incomplete label.

Assumptions require current valid reviewed ALA, supplied expected_review_digest
matching the existing CSE context, and exact captured/current full-session equality.
Existing form validation preserves known0 versus missing null, inclusion flags,
units/horizon/basis and invalid-money handling. The conservative full-session gate
also withholds assumptions after unrelated metadata/TSA changes. No financial
calculation/second model, license savings or scenario comparison is introduced.
Playbook original dependencies/source links/roles/date uncertainty and provenance
remain untouched; its owner checks original review/scenario sources too.

## Bounded reference contract

At most400 entries in catalog or submitted citations, strict objects, no coercion,
unknown keys, name-derived IDs, free-form URLs or arbitrary JSON section paths.
Source IDs reuse SourceIdSchema (1–128 non-whitespace characters); generated IDs
use the existing1–64 alphanumeric/underscore/hyphen convention.

| kind | Exact identity |
| --- | --- |
| section | deal, ala, ala_review, license_findings, assumptions, playbook, playbook_review, only when actually supplied |
| application | app_id and exact buyer/target side |
| license | license_id and actual linked app_id |
| tsa | tsa_id |
| ala_finding | finding_id |
| ala_action | finding_id plus actual child action_id |
| license_finding | finding_id in the license namespace |
| assumption | current normalized line_id |
| playbook_phase/activity/milestone/risk | actual local id in that record namespace |

`validateAssistantReferences` requires the exact current issued context and checks
strict structured membership, parent/side/kind, duplicates and bounds twice around
validation. Empty citations are structurally permitted for a later unsupported/
unavailable answer; this does not authorize an uncited factual answer. No narrative
ID regex extraction, invented citation, confidence score or semantic truth claim.
Malformed citation output fails fixed invalid_source_references, without repair.
Future U10.02 answer schema and grounding/refusal semantics remain unimplemented.

## Instructions, size and gateway handoff

ASSISTANT_CONTEXT_INSTRUCTIONS is server-owned bounded text, separate from all
source text and future visitor questions. Commands in notes/model narratives/
visitor overrides are literal untrusted data; no stripping or keyword filter
turns them into system instructions. Rules require missing-evidence acknowledgment,
exact supplied citations, no action/mutation/secret disclosure or invented savings/
facts/people/dates/confidence. Prompt separation is defense in depth, not proof a
future model resists every injection. There is no model invocation in this unit.

Complete context/catalog plus server instructions must fit unchanged128,000 UTF-8
bytes. A catalog exceeding400 or oversized complete payload fails atomically with
request_too_large; no truncation, row dropping, slicing, history packing or cap raise.
Fixed invalid_input/source_changed failures do not reveal raw exceptions/data.

This domain object is **not InvocationInput**. Current generic gateway context
accepts deal/user_text and Playbook-only structured context. U10.02 must review a
minimal typed Assistant integration through the guarded router and account for
full invocation, future question/history, output JSON schema and policy ceilings.
Do not pack context into the existing2,000-character user_text, cast around the
schema, bypass the adapter/router or infer live approval from these contracts.
No router/provider/budget/rate/concurrency/fallback/pricing/policy or endpoint
change is made. Both OpenAI hard stops remain. Current Assistant page stays an
introduction with not-enabled notice and no fake answer or query/debug source.
