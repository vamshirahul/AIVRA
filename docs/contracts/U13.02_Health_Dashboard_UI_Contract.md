# U13.02 — Integration Health dashboard tiles

## Approved mapping

G2 and the unit register agree: **Render concise status tiles with deep links to
modules**, parent M13 Integration Health Dashboard, **REQ-110 / REQ-112**,
dependencies **U13.01 U00.03**. Acceptance: **“Tiles show counts, available estimates,
links; absent data explicitly unavailable.”** REQ-111 missing-data semantics are
reused from U13.01. No material scope conflict or missing prerequisite exists.

U13.02 renders the existing metric definitions. U13.03's broader cross-module
live-update acceptance, optional scenario metrics, live inference, protected result
delivery, persistence, deployment and release are excluded.

## Public workspace and values

`/integration-health` uses the existing A1 Coastal Navy shell and a responsive
two-column/stacked layout, with semantic section headings and description lists:

- Application Landscape: exact validated current-session total, Buyer and Target.
- Application Rationalization: original action rows, recorded visitor overrides,
  missing/not-evaluated application coverage and all-suggestions-reviewed count.
- Cost Synergy: existing six calculated monetary totals, horizon and warnings.
- TSA: the existing TSAHealthSummary component, once, with its unchanged portfolio
  source-status counts, labels, revisions and overview link.
- Playbook: original activity/milestone and recorded visitor-edit counts.

Public application counts require the same full bounded DemoSession validation
already performed by buildTSASummary; only array counts are derived. TSA has no
second calculator or contradictory count display. Public protected results have
no authorized delivery source, so their values remain unavailable. The reviewed
suggestions count is explicitly not_recorded; visitor overrides are not approvals
or proof all unchanged suggestions were reviewed. No fake numbers or sample AI
successes are installed in the public route.

Every metric has a title, units, state text and supported value or nonnumeric
unavailable text. State vocabulary is U13.01's exact current, incomplete, absent,
outdated, invalid, unavailable and not_recorded. Loading is a separate workspace
notice, never zero. Valid zero remains zero. Missing reviews and null financial
amounts remain unknown. Fixed state explanations avoid exposing raw exceptions
or internal reason strings.

Monetary display uses existing formatCAD, preserving CAD cents and negative signs;
no conversion rounding or new formula. Existing CSE warnings are rendered with
fixed readable labels, including missing amounts, incomplete analysis, overlapping
spend and withheld license aggregation. Counts/estimates are fictional and
illustrative, not verified savings, health/readiness scores, predictions, approvals
or real integration completion. Playbook counts are draft sizes only.

## Protected presentation seam

HealthPresentationSource is a function-bearing in-memory interface: getSnapshot,
subscribe, isCurrent and matchesSession. A genuine future owner must use U13.01
buildHealthMetrics/isCurrentHealthMetrics and actual authoritative session data.
It is not JSON authorization, a browser boolean, an RPC protocol or a bridge for
serializing private server handles. No source is supplied by the public route.

The browser supplemental display guard strictly checks bounded field shape,
states, counts, CAD units/minor bounds, original warning enums and source metadata.
It neither authenticates AI execution nor recalculates financial values. Populated
values require the source's exact issued-object currentness and full session match,
plus matching fixture/session/revisions and application/TSA counts. A parsed clone
does not gain authority. No server-only runtime is imported into client code.

Owner notifications increment a mounted presentation revision, forcing revalidation
even when the same snapshot object becomes revoked. Shared-session changes rerender
through the existing provider and suppress mismatched protected values immediately.
No polling, storage, background requests or Refresh action. Broad mutation/UAT
remains U13.03; the bounded stale/Reset display checks here protect this component.

Untrusted content uses React text escaping. No generated HTML/Markdown/links,
analytics, prompt logging, credentials, transaction tools or data mutations.

## Navigation and accessibility

Only existing overview routes are linked: /data-mapper,
/application-rationalization, /license-optimizer, /cost-synergy,
/scenario-modeling, /playbook-generator and /tsa-tracker. Labels say Open module
or View/edit TSA services. No fabricated query, fragment or record routes.
Main navigation and seven Future Features remain unchanged/inert.

Responsive cards wrap at 1440/390/320px. Native links, semantic headings/dl,
textual states, workspace polite status announcements and existing visible focus
styles preserve keyboard/read order. No chart library, animation or color-only
meaning. Source labels are concise, without dense digests/diagnostic output.

## Validation and limits

check:health-dashboard reuses the U13.01 guarded fixture through an exported helper;
it does not run that suite on import. Fixtures stay in ignored .temp/u13-02 and a
separate loopback Chromium harness, never in the application. Populated/incomplete/
absent/outdated snapshots originate from actual offline U13.01 projection; isolated
invalid/foreign/revoked injection exercises rejection. Fake delivery is labelled
offline only and cannot establish genuine public delivery or LLM quality.

The existing Chromium/CDP pattern checks actual components, labels, signed money,
warning/null/zero handling, exact links, one TSA summary, keyboard/accessibility
tree, invalid/stale/Reset display and 1440/390/320 overflow. Production checks
separately verify real inventory counts and honest protected-result unavailability.
Keyboard/AX checks are not a full manual screen-reader or physical-device audit.

Rollback: revert the single U13.02 commit. Previous TSA-only dashboard presentation
returns; no transaction/schema migration, provider or storage cleanup is required.
All 15 baseline documents stay unchanged/untracked; execution is recorded in the
unit validation report rather than modifying approved registers.
